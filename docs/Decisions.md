## 二、方法与判据

判据的完整表述见 [Principles.md](Principles.md)。

| # | 决策 | 说明 |
|---|---|---|
| D12 | 必做与 optional 的判别式 | 长程一致性解决**上下文窗口的物理限制**，收益不随模型能力消失；其余解决**模型推理能力不足**，收益随模型变强而递减 |
| D17 | 审查类工作的增益 = **上下文差 × 验证器** | 两项相乘，缺一归零。上游按"约束类型"做的隔离不消除上下文差（切分轴不同），但无验证器时上下文差再大也无增益 |
| D24 | **模型的开放判断一律降级为受约束的选择** | 降低对模型能力与提示词的敏感度。已多次应用：D15 / D20-21 / D22-39 / D41 |
| D30 | 结构化字段上的代码检查**不是独立验证** | 字段值本就是模型写的：语义判断发生在写入时，代码检查发生在读取时。读取只是查表 |
| D31 | **检索价值与交叉比对价值必须分开评估** | 结构化对所有维度都有检索收益；代码校验只对有结构性约束的维度成立。混为一谈会误判 |
| D32 | 拆分与否的判据是 **context 是否可分**——先枚举全部 context 再看切法 | 不问"该不该有某个 agent"。**同一组工作在不同切法下结论可以相反** |
| D43 | **代码检查降级为观测，不做运行时强制** | 写作任务中它可靠性有限：字数达标≠密度达标、时间戳是模型写的、偏差可能无害。主要价值在开发期调试与 eval 采样——**正则是采样器不是判断器** |
| D44 | **修复成本决定能否自动强制** | 补交状态增量成本≈0 → 可自动强制；重生成正文成本高 → 只能提示。这界定了 D19 能自动执行的真正理由 |
| D62 | **规则可以做无损降维，不能做有损筛选** | 分界线是**模型是否知道自己缺了什么**。智能检索与规则检索共存，但规则范围受限于"所有情况下都不出错" |
| D78 | **第四类配置：能力开关。关闭即工具不注册** | 比「注册了但拒绝」强——后者仍占 prompt 体量、仍会被尝试、失败还要消耗一轮往返 |
| ~~D29~~ | ~~代码能做两类：契约完整性 + 结构性交叉比对~~ | **修正为只剩契约完整性一类。** 落地确认结构性比对全都做不了：时间是自然语言、说话者需语义抽取、地点无拓扑图；连"知情者 ⊆ 在场"也不成立（信息可经转述获得）。假警报比不检查更糟 |

## 三、生成侧拓扑

见 [design/Architecture.md](design/Architecture.md)、[design/Generation.md](design/Generation.md)。

| # | 决策 | 说明 |
|---|---|---|
| D33 | **拆分为 director / writer**，因 context 在特定切法下可分 | 关键切法：**director 只读细纲不读正文，writer 读正文保证衔接**。此刀切开了最大的共享项；两侧都读正文则不可分，应合并 |
| D34 | 中间量是**无文风约束的文章**，不是抽象规格 | 散文形态**不需要预设字段格式**（不依赖未经证实的写作理论），也**没有元层翻译任务**——这是抽象规格方案的两个致命伤 |
| ~~D35~~ | ~~**否定项必须给 writer**~~ | ~~细纲说"会发生什么"，否定项说"不能写什么"，按定义不在细纲里。体量极小，不破坏隔离。叙事节奏则可不给——细纲的事件密度已编码节奏~~ **已改设计（D139）：否定项两侧都不注入。** |
| D37 | 多候选做在**细纲层**，不在正文层 | 三份细纲比三段成品便宜，用户读走向比读全文快，且用户要控制的是走向而非文笔 |
| D52 | **director 是主 agent，writer 是被拆出去的渲染器** | writer 只承担文风，不是流水线下游的规划环节 |
| D53 | **交接是静态 workflow，固定且单向** | 编排层按固定顺序调用，无回流、无协商、无重试循环 |
| D54 | **writer 绝不能做成 director 的 tool** | 工具返回值会回流到调用者上下文，正文回流即摧毁隔离。**此条一破，Generation 全部论证作废** |
| D57 | writer 输出**偏离报告**，不改写细纲 | 通常为空；编排层记录在节点上，下一 run 的 director 可见。writer 保持纯粹 |
| D59 | **归因六类** | director 检索不足 / director 推演错 / writer 偏离细纲 / writer 文风失败 / 写入遗漏 / **写入冗余**。归因可行性是拆分的副产品 |
| D101 | **AI grader 的信号是复现率，不是单次判定** | 同一批素材连判三次（**当时以为温度已是 0，其实没有，见 D125**），跨次稳定复现的三条全是真问题，只出现一次的四条全是误报。**当时归因为「温度设 0 也消不掉这种波动」，那是错的**——温度压根没生效（D125）。结论本身仍然成立，但理由要换：随机性来自思考模式，而**这个随机性恰恰是过滤器赖以工作的东西**，不该被消除。 因此 `--repeat N` 每类判多次、过半才计入；`--regrade` 保证换 grader 时素材不变，否则 grader 的差异会和模型的随机性混在一起。这比继续给 grader 打补丁划算——**误报不需要被消灭，只需要被过滤** |
| D100 | **补第六类「写入冗余」** | 原本的五类里，写入侧只有"遗漏"没有"多余"——于是"记了不该记的"无人负责。首批实测：`照片.状态: "柜台，正面朝上"` 被全部归因一致判为没问题，而它正是 D95 点名不该记的。**冗余的代价是慢性的**（state 越长越容易看漏要紧的几条），因此不会以单点错误的形式暴露，只能靠专门一类去查。它的参照物是**写下来的判据本身**（D95/D99），仍属"有参照物"那一侧 |
| D93 | **篇幅只讲给 writer，director 那侧换成事件密度** | 实测的根因：director 的 prompt 同时说"产出是完整文章"并给了篇幅要求，而篇幅只能靠描写凑——于是它写出成品散文，writer 只能照抄（细纲/正文长度 524/526、739/753、559/544）。改为**事实 vs 呈现**的对照后降到 214/710、217/463、240/558。对照必须两侧都说（同 D35） |
| D97 | **对白：细纲写意思，正文写原话** | 语言描写也是描写。此前细纲直接写定台词，writer 只能照抄——`character_voices` 因此完全是死的，**语言习惯没有落点**。放开措辞的同时要钉死信息：数字、价钱、名字、期限细纲必须写死。用户已写出的原话是唯一例外，靠**引号**标记（细纲里除此之外不出现引号，两侧同一约定）。实测：数据化世界 1.1 → 2.4 倍，价钱全对，台词开始有口音 |
| D98 | **「某人在等」不是事实，两侧都不写** | 抢话规则原先把停止条件列作"做出了等待回应的动作"，模型据此把「等」写进细纲，writer 忠实渲染——4/4 样本以同一画面收尾。**根在 director**，只在 writer 侧说"别这么收尾"治不了：那是细纲给的事实，照写才对。修法有两半：director 停在最后一件真发生的事上；writer 被明确告知**跳过这句不算偏离**。后半更管用——实测 director 仍会写，writer 已能跳过 |
| D94 | **抢话规则也要给 writer** | 原本只在 director 一侧——因为照抄的 writer 够不着这条线。一旦它真的在展开，就会顺手把用户角色再往前推一步（实测：细纲停在"等林昭决定"，正文写出"她低头，指尖压了一下照片"）。**越界发生在哪一侧，规则就得在哪一侧** |
| D67 | **director 拿不到角色原话，接受限制** | 不开窄查询口子（会逐渐等价于读正文），不让 writer 回写台词（与纯渲染定位冲突）。缓解靠 prompt 双向用力，出错靠用户纠正 |
| ~~D36~~ | ~~细纲必须更新为「实际发生的」~~ | 落地方式改为 D57 的偏离报告 |
| ~~D9~~ | ~~规格产出方提交确定的规格，生成方不具备回推权~~ | 中间量成了细纲=文章（D34），writer 做的是改写而非从抽象规格重建，"不可行"的情形大幅减少 |

## 四、state

见 [design/State.md](design/State.md)、[design/Retrieval.md](design/Retrieval.md)。

| # | 决策 | 说明 |
|---|---|---|
| D6 | **写入保持单线程** | 一条约束，不是 topology 决策 |
| D10 | **长程一致性是必做项** | "检索和维护一批状态数据的工作客观存在，只是给到谁还不确定"——归属见 D55 |
| D18 | **有限建模：结构化存储，判断交给模型** | 建模是为了检索准、维护省，不做规则引擎。真正买到的是**前移**（生成时状态准 → 矛盾不产生） |
| D19 | 代码只强制**契约完整性**，不判断内容 | 校验"有没有提交"而非"提交得对不对"。每 run 必交增量，哪怕为空 |
| D20 | **不让模型自由定义 schema** | 已有实测：效果与提示词和模型能力强相关。"设计数据结构"是元层任务，在弱模型上加负担 |
| D55 | **state 由 director 单点写入** | 它有完整 state 上下文；writer 只做渲染，没有新事实可提交。写入单线程因此更干净 |
| D56 | `state_write` 是独立工具，**run 内暂存、run 末原子提交** | `submit_outline` 只做终止与交付，职责单一。契约：提交前至少调用一次 `state_write`，**空增量合法**——强制这一次是为区分"确实没变"与"忘了记" |
| D61 | **术语三分：state / worldinfo / history**，判别式是"谁改变它" | 废弃 `ledger` / `账本` / `后台数据` |
| D63 | worldinfo 与 history 用**同一模式：全量索引 + 按需展开** | 索引必须带体量以告知拉取代价。**时间局部性预取与 lorebook 关键词触发均按 D62 出局** |
| D64 | **写入侧乐观处理，靠用户参与维护** | 检索遗漏可自愈。提取遗漏分两种（D99 之后细化）：细纲里写了但没进 state 的，**可从 history 回捞**——state 只是捷径，信息本体在 history；只存在于正文里的，director 永远看不到，**不可自愈**。风险仍不对称，但不可自愈的那一半比原先估计的小 |
| D65 | **state 必须用户可随时查看 / 编辑** | 人类可读；**state / 细纲 / 正文都可直接改写节点数据，不做依赖检查**——乐观假设用户只改最新输出 |
| D69 | **`summarize` 做成工具，摘要懒惰生成** | 按引用寻址（`run:<id>` / `wi:<ref>`）才能真正缓存。无摘要的条目回退到"前 N 字 + 字数" |
| D74 | **取消固定核心 schema：存储层不预设任何维度** | 错误不在字段选得不好，而在这类 schema **原理上定不下来**——粒度与形态都取决于故事。"哪些维度存在"往上挪一层 |
| D75 | 键自由命名，`.` 仅用于**渲染分组** | 写入语义：`set`（覆盖，`null` 删除）、`append`（追加去重）、`remove`（见 D96）。"离场再出场"天然成立 |
| D76 | **schema 塌成两层**：自由 KV（即全部）+ 模板库（尚未做） | 不违反 D20——模型做的是"记一个键值对"，不是"设计数据结构" |
| D77 | state 的注入统一到 D63 模式 | 全量键名 + 体量小的值内联，大的只给体量 |
| D80 | **state 关闭时 E0 契约随之失效** | 没有 `state_write` 可调，就不能要求先提交增量 |
| D81 | **worldinfo 分 always / on_demand**，全为 always 时工具不注册 | 没有可展开的东西时，留着工具只是白占体量 |
| D114 | **director 的对话跨轮持续；压缩越界一次、全部替换** | 之前每轮都是全新对话，历史靠 `render_history` 重新渲染成文本。改为持续之后：上一轮的用户消息、推理、**工具调用与结果**原样接在后面——director 看得见自己查过什么、为什么那么写。连带必须改一处：**state 与控制维度从 system prompt 挪到每轮的用户消息**，因为 system 是缓存前缀，放会变的东西进去前缀每轮失效，而且旧值会以"写在最前面"的权威姿态误导模型。压缩**不是段落一收就做**，而是攒到 `CONTEXT_BUDGET_CHARS` 再做，**并且一次把所有能被摘要顶替的段落全换掉**——每收一段换一段等于每隔几轮动一次前缀，缓存反复失效，那还不如不持续。节点只存**本轮新增的消息**，重放时沿路径拼接，分支天然安全（D48） |
| D117 | **检索层早期只要求「调得动」，不做查准/查全** | 检索是 state 与摘要的**兜底**，不是常规路径：state 记约束与欠账（D109）、摘要按"可不可再生"取舍（D110），剩下真正漏掉的才轮到它。**前两条越准，兜底被用到的次数越少**——实测里检索多次"正确地闲置"，那是系统健康的表现，不是覆盖不足。在这种前提下追它的查准查全，是在优化一条很少走的路。验收标准因此只有：工具面正确、语义不误导、关掉时行为明确（D115）。**继续投入的重点是 summarize**，它决定兜底要被用到多少次 |
| D116 | **归段追问要问「断在第几条」，不是「这轮是不是结尾」** | 五版实测（`chapters`，预期分界 {3,6,9}）：批量冷调用的位置问法 0.67/1.00；逐轮二值问法无论怎么加对照——给对照框、给默认值、换成持续对话——**查全都卡在 0.33**。**决定性的差别是问题的形式，不是它看得见什么**：分界是相对判断，二值答案只能对当前轮独立表态，**说不出"不是这里，是两轮前"**。改成生成后问位置、且允许**回溯**标记到前面几条，查全 0.33 → **1.00**。仍会多切（查准 0.60），但**方向是良性的**：漏切把两段无关的戏并进同一条摘要，是不可逆的信息损失；多切只是多一条索引，每段本身仍然完整 |
| D115 | **关闭按需展开时，三者各自退回全量或永久隐去** | 共用一条原则：截断 + 按需展开是**无损降维**，一旦没了展开的路，截断就变成**有损筛选**（D62）。`state_query` 关 → state **每轮全量注入**，长值不截断；`worldinfo_read` 关 → 按需条目也**全文进静态前缀**（设定跨轮不变，代价只付一次）；`history_search` 关 → 被压缩的原文**永久隐去**，但**摘要仍留在上下文里**——整段抹掉才是不合格的，模型必须知道那几轮存在过。三处都不再广告没注册的工具 |
| D113 | **判定在生成时，压缩在需要时** | 归段被拆成两步，因为它们的**最佳时机不同**。第一版把两件事合在一起——等一批轮次滑出全文窗口再问"这几轮算不算一段"，实测查全只有 0.67（查准 1.0，从没切错过）。漏判是结构性的：**待归段缓冲区里只有已滑出窗口的轮次**，所以"第 9 轮是个分界"要等三轮之后才被问到，**而那时问的人已经看不见揭示这个分界的第 10 轮转场了**——分界恰恰是靠后一轮才认得出来的。现在每轮生成后当场问"这一轮是不是一段的结尾"，答案记在 `Node.closes_segment` 上；压缩晚些按标记分组即可 |
| D112 | **工具分两类：生成中调用 / 生成后调用** | 判据是**影不影响本轮产出**。生成中：`state_query`、`worldinfo_read`、`history_read`、`ask_question`。生成后：归段。生成后的动作**绝不能进 tool loop**——它对本轮产出毫无帮助，却要占往返、分散注意力，还和 `submit_outline` 的终止语义打架（D53）。但它**必须问 director 本人**：判据是"这场戏完了没有"，需要 state、前情和故事走向；追问接在它自己的对话后面，几乎不花额外输入 token，而另起一个只看得见几段细纲的冷调用，判据全靠猜。归段因此有三条支路：**追问**（主路）/ **到上限强制**（止损）/ **用户手动**（`POST /sessions/{id}/close-segment`）。`SummarizeMode.MANUAL` 由此才有实际含义 |
| D110 | **摘要与细纲是 n : 1，分界点由模型判断** | 按轮一一对应有两个毛病：**它不是语义单位**（一场对峙横跨四轮，一次转场只占半轮），而且**条数不收敛**（50 轮就是 50 条索引，Q23 原样还在）。因此改为按**段**压缩：编排层攒够 `MIN_SEGMENT_RUNS` 就问模型"该在第几轮之后断开"，回 0 表示这一段还没完、再等一轮，到 `MAX_SEGMENT_RUNS` 强制断开止损。段落按**「末节点 + 跨度」寻址**而非记起止 id——父指针唯一，从末节点上溯 span−1 步的链是确定的，**任何经过末节点的路径都得到同一段**，分支因此天然安全（D48）。触发仍归系统（D108），只有"算不算一段"这个语义判断归模型 |
| D111 | **分界准确率是 program grader 可以直接算的语义指标** | 极少见的一个例外：**分界点是位置，位置对不对是二值的，不需要品味**——正好卡在"违反 = 流程坏了而非写得不好"这条准入标准上。`chapters` 场景由四段界限分明的剧情组成（段间是转场），`segments` 记预期切分但**不喂给模型**。查全与查准要分开看：**切得太碎和切不出来是两种不同的失败** |
| D109 | **state 要记两类：约束类 + 悬置类** | D95 的判据（"不记会不会写出不可能发生的事"）只覆盖**逻辑**，漏掉了**叙事欠账**：契诃夫之枪挂在墙上，忘了它不产生任何矛盾，只会烂尾。**正因为它什么也不禁止，才最容易漏。** 悬置类 = 枪、承诺、没答的问题、没拆的信、撂下的狠话。判据要窄：**有人特意让它出现、而它还没有下文**——没人在意的东西不是伏笔是布景。**兑现即删**，于是 state 里的悬置项恒等于"当前还欠着的账"。这一条同时缩小了检索的必要性：**有意埋的伏笔归 state，只有"当时无人在意、后来才变关键"的细节才是检索的领地**（D106 的 B 类因此变窄） |
| D108 | **摘要由编排层在一轮滑出全文窗口时自动生成，不交给模型** | `summarize` 的收益全在**未来的轮次**——这一轮花 token，好处归下一轮。让优化当前轮的模型去做一件只利后续的事，是把激励放反了。它是系统维护，不是创作决策。仍然懒惰、仍然缓存在节点上（D69 两条性质不变），换的只是触发点。**`summarize` 默认改为 `AUTO`**，与其他能力"默认关"（D78）相反，因为它的回退项不中性：没有摘要时索引退化为"细纲前 120 字"，那不是精度低一点，而是**位置偏置**——开头原样保留、结尾完全消失，而它还顶着「总结」的名字。**会误导模型的回退不能当作安全默认值。**索引里也据实标注「总结」/「开头」 |
| D106 | **检索工具的描述要给触发条件，不是机制说明** | state 与摘要的盲区是同一个：**「当时不要紧、现在才要紧」的细节**。state 只记会约束后续的（D95），摘要只保留写它那一刻的重点——而伏笔的价值天生延迟显现，埋下时两边都进不去，这不是摘要写得不好，是原理上做不到。六条触发：引用原话 / 兑现伏笔 / 说清先后因果 / 摘要与 state 打架 / 用户直指某轮 / 疑有矛盾但说不清。反面同样要写（想知道现状看 state、接语气近几轮已在、要梗概摘要够用），否则每轮翻史 |
| D107 | **历史索引必须带 ref；`history_search` 的 query 只标注不筛选** | 两个实现缺陷解释了这层为何从未被调用：①索引写「第 N 轮」而 `history_read` 要 run id，**模型看得见却拿不动**，得先花一轮换 id；worldinfo 索引一直带 ref，它的 read 就一直被正常调用。②`query` 是子串过滤器，查不中返回空列表，模型会读成"没这回事"——**这正是判 lorebook 关键词触发不合格的那条理由，我们自己犯了同一个错**。同一个错误换个位置就没认出来 |
| D82 | `history_search` 关闭 = **禁止检索** | 更早的轮次仍以总结在场（仍满足 D62），只是没有工具能展开全文 |
| ~~D21~~ | ~~schema 三层：固定核心 / 模板库 / 自由 KV~~ | 固定核心整层作废（D74），塌成两层（D76） |
| ~~D68~~ | ~~校验输出是否完整消费了输入~~ | **取消**：它是语义判断，代码做不了；唯一实现路径随抽象规格作废。eval 时分析 trace 本就包含它 |
| D90 | **worldbook 条目带 `seeds`，session 开始时迁移进 state** | 设定条目本身是混的：性格背景是静态的（worldinfo），在哪/知道什么/什么关系是会变的（state）。没有种子时模型只能**抄**设定，而副本会与之分叉。**关键是移除诱因而非禁止**（P10）：种子已在默认包里，模型只会去改它。实测附带收获——种子键成了命名锚点，压住了键名漂移 |
| ~~D92~~ | **一份 worldbook 开启一个 session，它有两路投影**（前半句已被 D170 推翻） | worldbook 是用户编写与维护的**唯一来源**；条目正文 → worldinfo（静态，用户改），条目种子 → 初始 state（动态，剧情改）。初始 state 是 **session 级**的，不属于任何路径，改种子影响所有分支——与改角色卡效果一致。**「一份开一个」已被 D170 推翻**：worldbook 是一级资产，一份可以开出好几局故事；「两路投影」那半仍然成立 |
| D95 | **判据是「不记会不会写出不可能发生的事」，不是「这是不是状态」** | 时态判据（状态 vs 事件）拦不住记得过细：`照片.朝向` 确实是状态。实测记出了物件朝向、离收摊几分钟、以及塞成小传的 `许平: "已故男子；名字由陈屿说出；……"`。**存续时长不是判据**——冷却只剩两回合活不过几轮却必须记，照片朝向可以永远成立却什么也约束不了。配套三条：一个键只装一件事、不记「未明」（没记的本来就未知）、不再约束后续就 `set null` 删掉 |
| D99 | **state 是 history 的捷径，不是第二份记录** | 信息本体在 history；state 把"每轮都要用、又不该每次回头翻"的那几条拎到眼前。三个推论：①**判据是双条件**——既要约束后面能写什么，又要值得随时看见。两条分别排掉「照片朝向」（什么也不约束）与「本轮剧情摘要」（前情里就是它）；②**删键不等于丢信息**，因此 state 该保持短，也让 `set null` 成为一个模型敢用的动作；③**结构化靠提示词鼓励，不靠 schema 强制**（D20/D74 不变）——能用数字别用句子、能用是否别用描述、同类的事用同一套键名。既然是速查表，形状比文采重要 |
| D96 | **补 `remove`：`append` 的逆运算** | 原先只有增没有减，去掉一项只能 `set` 整个列表。实测模型改用字符串整体重写，把 `["青锋剑", "止血符 ×2"]` 拍成 `"青锋剑、止血符 ×4"`，**结构一次性塌掉且不可逆**。同时修渲染：清单原先渲染成裸的顿号串，**与字符串长得一模一样**——模型看不出形状，这才是塌陷的根因，光靠提示词修不掉。**这个缺口纯文学场景永远看不见**：那里的清单（知情、经历）天然只增不减 |
| ~~D71~~ | ~~知情归属 / 角色档案分离 / 时间分绝对相对~~ | 三条都在修补固定核心 schema，而问题出在这层 schema 本身（D74） |

| D103 | **重生成的父节点随输入入队，不经 `session.active_leaf_id`** | 活跃叶是共享状态：提交重生成时若有 run 在飞，那个 run 结束会把活跃叶覆盖成自己，重生成就挂到错误的父节点上。**产出的文本是对的，位置是错的**——树里看不出来，要等切分支时才发现状态对不上。`None` 本身是合法父节点（根），所以要单独一个 `explicit_parent` 旗标，不能用 `None` 表示"未指定" |
| D79 | **trace 是开发者模式，默认关闭**；以 node 为单位 | 关闭时事件仍推给 UI，**只是不落盘**——这正是 D25 分两层的好处 |

## 九、优化与评估

见 [Optimization.md](Optimization.md)。

| # | 决策 | 说明 |
|---|---|---|
| D83 | **三种 grader 按「有没有参照物」分工**，且恰好对应归因五类 | 四类有参照物（细纲 vs state / 细纲 vs 指令 / 正文 vs 细纲 / 增量 vs 正文）→ AI 可判；**"writer 文风失败"无参照物 → 只能 human**。这一类恰好最主观、也最影响体验 |
| D84 | **program grader 的准入：只有当「违反 = 流程坏了」而非「违反 = 写得不好」时才能用** | 可做的只有契约形状、可数的量、字符串存在性。用途只有回归护栏与采样器 |
| D85 | **不加内容层面的硬约束** | 除假警报外还有更隐蔽的伤害：**模型会为了满足检查器而牺牲质量**（灌水凑字数、硬塞模板）。那不是误报，是主动的质量损失，且检查器永远不会告警 |
| D86 | **AI grader 只用在有参照物的判断上，且需要 human 定期校准** | 无参照物时它只是第二种品味（P11）。不校准会悄悄漂移，而它的错误直接误导后续所有决策 |
| D87 | **行为代理从第一版就采集** | 重 roll 率、打断率、戏外引导频率、会话时长。零标注成本，且是"文风失败"那一类唯一可规模化的信号 |
| D88 | **回归集只保流程，不保质量** | 创作输出不确定。不要试图用回归集锁定输出内容——那等于把某一次生成当成标准答案 |

## 已被推翻的结论

不曾编号，但记录下来以免走回头路。

- ~~"topology 为 director / writer / ledger 三方"~~ → **越界**。那是另一个项目的形状。本项目的同名结论是独立重新论证的（D32/D33）。
- ~~"director 必要性与用户介入**频率**成反比"~~ → 变量是**规格度**而非频率；且这是关于**工作量**的结论，不是关于 agent 存废的。
- ~~"需要 Director + Actors 调度器做发言权仲裁"~~ → 已识别的非轮次 UX 都是长循环 + 循环内介入，不需要多自主体调度。
- ~~"滞后一拍的 reviewer 以保住流式"~~ → 因 D7 不再需要。
- ~~"extractor 应独立于 critic"~~ → 分配结论，越界。保留的是其中的约束：回写必然存在。
- ~~"goal 目标可绑结构化维度做代码判定"~~ → **错误**。那些字段的值本就是模型写的（D30）。
- ~~"关系不值得建模（校验价值低）"~~ → 混淆了检索价值与交叉比对价值（D31）。
- ~~"识别输入类型是一项必然工作（四类分类）"~~ → **不应对输入做显式分类**。四类只是举例。真正的问题是避免特定失败。
- ~~"世界响应推演独立于规格化"~~ → 合并。从方向推演剧情、从目标分解路径、从角色行为推演后果，是同一过程的不同起点。
- ~~"故事跨度是独立控制维度"~~ → 被输入处理三档与展开密度吸收（D41）。
- ~~"故事跨度 / 展开密度 / 抢话的遵守可代码检查并据此拦截"~~ → 降级为观测与 eval 采样（D43/D44）。
- ~~"goal 模式"这一措辞~~ → goal **不是模式**。模式指改变触发源的东西，目前只有时间驱动一项。
- ~~"固定核心 schema 及其维度评估表"~~ → **整层作废**（D74）。曾试图用"角色实体化""时间分绝对相对"修补，那些修补同样作废——问题不在字段。
- ~~"结构性交叉比对是代码能做的第二类"~~ → 落地确认全都做不了（D29）。
- ~~"`summarize(content)` 传裸文本"~~ → 改为按引用寻址，否则系统不知道该把摘要挂到哪里，"缓存复用"落不了地（D69）。
