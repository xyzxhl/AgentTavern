# 开局与设定

> 开一局故事需要什么、设定怎么编、编好的设定怎么复用。

## R1 · 开一局故事时明确选择一份设定

用户新建会话时先从已有 worldbook 中明确选择一份。设定库里的「在这上面开新故事」
直接带入当前 worldbook；会话列表里的「新建」则先给选择器，不静默创建一份空设定。

**不包括**：按一下「新建」就留下一个没命名、没内容、用户也没选过的空 worldbook。

**为什么**：worldbook 是一级资产。暗中创建会让设定库堆满无法辨认的空资产，也让用户
在进入故事后才发现开错了世界。

## R2 · 一份设定可以开出好几局故事

设定是独立的东西，不属于任何一局故事。同一份设定能开任意多局，**改一次所有故事
都跟着变**。

界面上要看得见「几局故事在用这份设定」；删一份还有人用的设定要被拒绝，而不是
悄悄删掉让那几局故事失去世界。

## R3 · 设定里只有条目，没有属性表单

一份设定就是一列条目，分四类：

| | 是什么 |
|---|---|
| **世界** | 一段不受限制的字：地方、组织、规矩、历史、题材与基调、内容尺度 |
| **角色** | 正文 + 他怎么说话；其中至多一个标着「用户扮演的就是他」 |
| **初始状态** | 一棵键值树：这局故事第一帧的世界状态 |
| **开场白** | 新故事在第一条用户输入之前显示的一段可选正文 |

**不包括**：题材、基调、尺度这些做成独立字段。它们和"旧货店在老城区一条窄巷尽头"
是同一种东西——**一段关于这个世界的字**，凭什么要特殊处理。

**为什么**：四类都是条目，只是编辑器与去向不同。设定页不该是“上面一个 worldbook
属性表单 + 下面一个条目列表”；题材、基调、尺度仍然不获得顶层特权。

## R4 · 「用户扮演谁」至多一个，标了新的旧的自动取消

用户在角色条目上标「用户扮演的就是他」。**标上第二个时，第一个自动取消**，不需要
用户先去把旧的那个取消掉。

这个标记属于 worldbook，不属于 session。复用同一份 worldbook 开出的所有故事
共用同一个玩家角色，**不提供 session 级覆盖**。

**为什么**：标了两个的话，「用户是谁」会变成取决于名字的字典序，另一个静默失效。
这个收敛必须在保存时发生，不能靠界面自觉——导入一份别人做的设定同样能塞进两个。

## R5 · 条目可以按需展开，长的不必每轮都在眼前

世界与角色条目可以各自设成「一直在」或「需要时才展开」。初始状态条目会先合成一棵
状态树，再由服务级 context choice 统一决定展开层级，不在单条条目上设深度。

**为什么**：一个角色的背景可能几百字，而他「在不在场」必须每轮都看得见。
静态条目的按需开关与状态树的折叠层级是两种不同机制，不能共用一个开关。

## R6 · 设定可以整份导出、导入

导出一份设定给别人，或导入别人做的。导入有两种，回答的问题不同：

| | |
|---|---|
| **导入成一份新的** | 拿到别人分享的文件时的动作 |
| **导进已有的那份** | 往手上这份里追加或替换 |

导进来的条目**一律重新分配 id**——文件里的 id 是别人存储里的地址，不是条目的身份。

**不包括**：静默丢弃读不懂的条目。校验不过就整份拒绝**并说明是哪里不对**——
一条设定悄悄消失，模型据此写出矛盾剧情且无人报错，比当场拒绝坏得多。

## R49 · 不再需要的会话可以删除

用户可以在当前故事页删除这局会话。删除前明确确认；删除后 worldbook 与 corpus 这些
一级资产仍然保留，只移除该会话自己的节点、草稿与 trace。

**不包括**：删除会话时连带删除它引用的设定或资料。

## R50 · 新会话沿用 worldbook 名称并自动避让重名

新会话默认使用所选 worldbook 的名称。已有同名会话时依次加编号，例如
`旧城区`、`旧城区 2`、`旧城区 3`；用户之后仍可在故事页自行改名。

**为什么**：新建后立刻让用户再起一次名字没有增加信息；worldbook 名已经是当前最可靠
的识别锚点。但会话列表里仍要能区分同一份设定开出的多局故事。

## R53 · 新故事可以选择一条开场白，也可以不用

开场白是 worldbook 的一种条目；一份 worldbook 可以没有，也可以准备多条候选。
创建故事时明确选择其中一条或「不用开场白」，不随机替用户决定。

选中的正文在创建时就固定下来，显示在第一条用户输入之前，作为 director 与 writer
承接故事起点的上下文；它**不是 user input、不是 turn，也不是伪造的第 0 个节点**。

**为什么**：节点承诺的是一轮完整 run 的原子结果（正文、状态增量），静态开场
不具备这些东西。另一方面，它创建时已经展示给用户，之后若跟着 worldbook 现读，修改
候选会让既有故事的开头凭空变化。

## 故事一旦开始，设定的哪一半就冻结了

这是 R2「改一次所有故事都跟着变」的**唯一例外**，也是用户必须知道的一条：

- **世界与角色的正文**：每轮现读，改了下一轮就生效。
- **初始状态**（第一帧世界是什么样）：**故事第一轮开始时就冻结**，之后改它不影响
  已经开始的故事。
- **选中的开场白**：**创建故事时就复制进 session**；之后改候选只影响新故事。

**为什么**：正文是"这个世界是什么"，改它等于改角色卡。而初始状态是**已经发生过的
剧情所依赖的事实**——第五轮写着「她掏出钥匙」而钥匙来自初始状态，把它删掉，那一轮
就凭空多了一把不存在的钥匙，且没有任何地方会报错。
