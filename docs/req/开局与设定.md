# 开局与设定

> 开一局故事需要什么、设定怎么编、编好的设定怎么复用。

## R1 · 开一局故事，不必先想好世界

用户可以直接开一局新故事就开始写，系统给它配一份空设定，边写边补。

**不包括**：要求先建好设定库才能开故事。那等于在最没有想法的那一刻逼人做决定。

**为什么**：两条路都要留——从设定库「在这上面开新故事」（先有世界），和直接新建
会话（先有故事）。

## R2 · 一份设定可以开出好几局故事

设定是独立的东西，不属于任何一局故事。同一份设定能开任意多局，**改一次所有故事
都跟着变**。

界面上要看得见「几局故事在用这份设定」；删一份还有人用的设定要被拒绝，而不是
悄悄删掉让那几局故事失去世界。

## R3 · 设定里只有条目，没有属性表单

一份设定就是一列条目，分两类：

| | 是什么 |
|---|---|
| **世界** | 一段不受限制的字：地方、组织、规矩、历史、题材与基调、内容尺度 |
| **角色** | 正文 + 他怎么说话；其中至多一个标着「用户扮演的就是他」 |

**不包括**：题材、基调、尺度这些做成独立字段。它们和"旧货店在老城区一条窄巷尽头"
是同一种东西——**一段关于这个世界的字**，凭什么要特殊处理。

**为什么**：一种东西、一个编辑器。设定页不该是"上面一个属性表单 + 下面一个条目列表"。

## R4 · 「用户扮演谁」至多一个，标了新的旧的自动取消

用户在角色条目上标「用户扮演的就是他」。**标上第二个时，第一个自动取消**，不需要
用户先去把旧的那个取消掉。

**为什么**：标了两个的话，「用户是谁」会变成取决于名字的字典序，另一个静默失效。
这个收敛必须在保存时发生，不能靠界面自觉——导入一份别人做的设定同样能塞进两个。

## R5 · 条目可以按需展开，长的不必每轮都在眼前

每条设定可以设成「一直在」或「需要时才展开」。状态类的条目还能设展开层级——
同一份设定里深浅差别很大。

**为什么**：一个角色的背景可能几百字，而他「在不在场」必须每轮都看得见。共用一个
开关时只能迁就其中一个。

## R6 · 设定可以整份导出、导入

导出一份设定给别人，或导入别人做的。导入有两种，回答的问题不同：

| | |
|---|---|
| **导入成一份新的** | 拿到别人分享的文件时的动作 |
| **导进已有的那份** | 往手上这份里追加或替换 |

导进来的条目**一律重新分配 id**——文件里的 id 是别人存储里的地址，不是条目的身份。

**不包括**：静默丢弃读不懂的条目。校验不过就整份拒绝**并说明是哪里不对**——
一条设定悄悄消失，模型据此写出矛盾剧情且无人报错，比当场拒绝坏得多。

---

## 故事一旦开始，设定的哪一半就冻结了

这是 R2「改一次所有故事都跟着变」的**唯一例外**，也是用户必须知道的一条：

- **世界与角色的正文**：每轮现读，改了下一轮就生效。
- **初始状态**（第一帧世界是什么样）：**故事第一轮跑完就冻结**，之后改它不影响
  已经开始的故事。

**为什么**：正文是"这个世界是什么"，改它等于改角色卡。而初始状态是**已经发生过的
剧情所依赖的事实**——第五轮写着「她掏出钥匙」而钥匙来自初始状态，把它删掉，那一轮
就凭空多了一把不存在的钥匙，且没有任何地方会报错。
