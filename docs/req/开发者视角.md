# 开发者视角

> 查问题时要看见什么。这些东西默认不开——**一次往返动辄几万字，一轮四个 agent
> 上十万**，平时用不着。

## R36 · 开发者模式下，每次模型往返的完整输入输出都看得见

**四个 agent 一个都不能少。** 不只是写细纲的那个——写正文的、记状态的、管目标的
同样要看得见。

**不包括**：运行时切换这个模式。开着服务切来切去，会让「这一轮到底记了没有」
变成要翻日志才知道的问题。它在启动服务时就定了。

## R37 · 刷新页面之后，之前那些轮次还查得到

开发者模式下的记录**落盘**，不是只活在当前这次连接里。

**为什么**：记了不给读回来的路等于没记，而查问题总是事后。

没留过痕的轮次要明确回「当时没开」，不是报错——那不是错误。

## R38 · 「它在想什么」和「它写了什么」分开看

模型的思考段动辄上万字（实测一轮两万多字）。它必须能**单独折叠**，不能和内容
挤在同一个开关后面。

**为什么**：查「它写了什么」和查「它为什么这么写」是两次不同的排查，一次只想看一个。

## R39 · 一轮里谁说了什么，要分得出来

一轮里最多四个 agent 说过话。**按 agent 分段**，别拼成一坨。

显示顺序要和实际运行顺序一致：推演 → 成文 → 记状态 → 判目标。**跑在正文之后的
东西，显示在正文下方**——否则读到「状态已更新」时正文还没出现，而它读的正是那份正文。

## R51 · 即使没开开发者模式，也要能定位服务为什么断了

连接、provider 流式响应或 runner 在生命周期边界异常时，留下持久化的服务日志：时间、
session / run、模型、是否流式、结束原因、token 数与异常栈。日志必须有界轮转。

**不包括**：默认记录 prompt、正文、thinking、工具参数或密钥。那些完整内容仍只属于开发者
trace；服务日志只为回答「是 provider 截断、网络断流、发送失败，还是本地异常」。
