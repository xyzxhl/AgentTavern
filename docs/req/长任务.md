# 长任务

> 设一个目标，让它自己往下跑几十轮。这一篇讲怎么设、怎么看、怎么叫停。

## R24 · 设一个目标，它自己往下写

用户写一句「让林昭查清照片的来历」，系统自己一轮接一轮往下推，不需要用户每轮
打字。

**设目标就是「去做」**——包括在一轮都还没写过的空会话上设。按下去的那一刻它就该
开始，而不是等用户再随便打句话把它推起来。

## R25 · 它先想清楚怎么走，再动手

设完目标之后，它先拆出几个**中间状态**（"照片的来源被说出来了"这种），再开始写。

**不包括**：这些中间状态是有先后的步骤。它们可以被跳过、以不同顺序达成、同时达成，
也可能因为剧情变化而不再必要。唯一的硬要求是**达成没达成看得出来**。

## R26 · 跑的时候进度一直看得见

目标跑着的时候，输入框上方一直有一条，回答三件事：**在推什么、推到哪儿、怎么叫停**。

**为什么**：用户切到别的页面时也得知道那边还在动，而「下一轮什么时候开、还剩多少
预算」恰恰是他决定「要不要现在插一句」时唯一需要的信息。

## R27 · 中间状态一条条被划掉，用户看得见

不能是跑了二十轮界面上什么都不变，然后突然告诉用户结束了。

## R28 · 预算留空就是不设上限

两条止损（最多跑几轮、最多花多少 token）**留空 = 不设上限**，不替用户填一个默认值。

**为什么**：想止损的人本来就会填一个数；不填的人却会在第 50 轮被一个自己从没见过的
数字拦下来，而那时的症状（目标突然暂停）和故障长得一模一样。

不设上限时靠**暂停**和**放弃**止损，这两个按钮一直在界面上。

## R29 · 预算跑满是暂停，不是结束

撞到上限时目标**暂停**，用户可以把上限调大接着跑。

目标只有两种真正的结局：**达成**和**不可能达成了**。这两种要分开告诉用户——
都交回控制权，但用户的下一步动作完全不同。

## R30 · 暂停期间用户可以自己写

暂停之后用户可以自己接着写几轮、切分支。**恢复时它要接上用户写的那些**，
而不是从暂停那一刻的旧进度继续。

如果按暂停时已经有一轮开始执行，暂停只阻止它结束后再开下一轮，**不打断、也不跳过
当前轮的收尾**。这一轮照常落节点、记进度与预算；暂停发生前尚未开始的轮次才不再启动。

---

## 目标花的钱要算全

「还剩多少预算」算的是**这个目标花掉的全部**，包括它开出来的每一轮生成，
不只是它自己判断进度的那几次调用。

**为什么**：钱主要花在它开出来的 run 上。只算判定的话，一个名义上「一百万 token」
的上限实际拦不住任何东西。
