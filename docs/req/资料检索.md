# 外部资料

> 给故事挂一份别人写的资料（一本小说、一段史料、一份专业手册），让它写的时候查。
>
> 解决的是**模型自己知识不够**的那一类：同人的设定与黑话、某个朝代的官职与器物、
> 一个专业领域的术语与流程。

## R40 · 给故事挂资料，它写的时候会去查

用户导入一份资料，这局故事写的时候就能查它。

**不包括**：把整份资料塞进上下文。资料动辄几十万字，塞不进，也不该塞——
每轮都带着一整本书，等于让模型在正确的一句和其余九万九千句之间自己挑。

## R41 · 一份资料能给很多局故事用

同一套同人设定、同一段史料，开多少局故事都用同一份。**改一次所有故事都跟着**。

**为什么**：同人写作最典型的场景就是同一套设定反复开新故事。
资料做成一局故事私有的，等于每开一局复制一遍。

## R42 · 它查了什么、查到什么，用户看得见

每一次检索都要看得见：**用了什么 query、命中了哪几段、来自资料的哪个位置**。

**为什么**：这条链路查不查得准，用户是唯一判得出来的人——他知道自己那份资料里有
什么。看不见的话，写错了他只会觉得"这模型不懂"，而不知道是没查到还是查错了。

## R43 · 查不全是常态，它必须说出来

**这条链路不承诺查全。** 能不能找到要的东西，取决于模型这一次的 query 问得对不对、
以及检索本身准不准——**两样都保证不了**。

所以每一次返回都要让人知道：**这是从多少字里按相关性挑出来的几段，没挑中不代表
资料里没有。**

**不包括**：让它看起来像查全了。返回几段就完事、不说来源规模、不说这是筛选结果，
会让模型（和用户）以为"资料里就这些"——**而那正是这个系统当初判定关键词触发不合格
的同一条罪**。

区别只在一点：那时可以不那么做，**这里做不到**。做不到的时候，**说出来是唯一的补法**。

## R44 · 整条链路可以关掉，关掉不留痕迹

关掉时工具根本不注册，提示词里也不提它。

**为什么**：绝大多数故事用不上这个。一个注册了但没资料可查的工具，
白占提示词体量、还会被试着调一次。

## R45 · 导入一份大资料要看得见进度

一本三十万字的小说建索引要花时间。导入之后要能看到**它进行到哪儿、什么时候能用**。

**不包括**：导入完成之前假装它已经能用。查一份还没建好索引的资料，
要明确说"还在建"，不是返回空。

---

## 这一层和别的检索不一样，用户要知道

系统里其它几样东西——世界设定、状态、剧情历史——都保证**模型知道有什么存在**，
只是精度有高有低。**外部资料做不到这一点**：它太大，装不下一份完整的目录，
而且用户给的资料未必有结构可言。

所以它的定位是**增强，不是依据**：

| | 保证 |
|---|---|
| 设定 / 状态 / 历史 | 模型知道有什么，查不查得到不影响它知不知道存在 |
| **外部资料** | **只保证查过了，不保证查全** |

这条差别写在这里，是因为它会改变用户怎么用它：
**指望它兜底会失望，拿它增强会有收获。**
