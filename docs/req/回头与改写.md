# 回头与改写

> 故事不是一条线，是一棵树。这一篇讲怎么回到树上任何一个位置，以及怎么直接改写
> 它写出来的东西。

## R17 · 不满意就换一个，旧的那版还在

对任何一轮点重新生成，得到**另一版**。两版并列，用 `⟨2/3⟩` 在它们之间切换。
重生成使用该版本当前保存的 user input；若用户先在编辑窗口改了输入，新版本必须基于
修改后的输入生成，不能把旧输入从别处找回来。

**不包括**：重新生成把旧的那版覆盖掉。用户点重来时并不知道新的会不会更好。

## R18 · 能回到之前任何一轮

用户可以切回故事树上任何一个历史节点，从那儿接着往下写。

**这是回到旧分叉点的唯一路径**——不能切回去的话，重新生成出来的那些兄弟节点
就永远回不去了。

## R19 · 在旧的一轮上重来，要先说清后面几轮会移开

在**不是当前**的那一轮上点重新生成时，后面已经写出来的几轮会移出当前这条线。

它们没有消失，切回来就在。**但这句话必须说出来**：用户按的是「重写这一轮」，
看到的却是后面几轮不见了。

## R20 · 只能直接改上一 turn 的输入、细纲、正文与状态

用户可以直接改写当前活跃路径上**最后一个已完成 turn** 的：**它打算写什么**（细纲）、
**用户当时说了什么**（user input）、**它写出来的**（正文）、**这一轮世界变成了什么样**
（状态）。更早的节点不提供直接编辑。

编辑窗口从这个 turn 完成时开始，到下一条顶层 user input 成功提交时结束。
只要有 run 正在执行或以草稿形式挂起，就不能编辑上一 turn；系统不会为了编辑自动取消
run 或丢弃草稿。run 结束或由用户明确放弃后重新按上述窗口判定——已经提交过下一条
user input 的旧窗口不会重新打开。纠正与引导属于当前 turn，不会另开编辑窗口。

修改只替换被编辑的字段，**不重跑 writer、state_manager，不重算任何后代、摘要或缓存**。
可能返回旧值的派生缓存只做失效标记，等下次读取从权威节点重建，不在保存时预先生成。
细纲、正文、状态之间因此可能不再一致；这是直接编辑的明确代价，冲突由用户负责。

**为什么只允许上一 turn**：更早的正文和状态本来就不会直接进入后续 context，
改它们的收益很小；更早的细纲会进入历史，原地修改会让已经生成的摘要与缓存失真。

## R21 · 改状态有两种改法

改状态时用户想的可能是两件不同的事，两种都要能表达：

| | 改的是 | 什么时候用 |
|---|---|---|
| **改指令** | 这一轮做了哪几笔改动 | 想加一笔、想把某一笔从「设成」改成「删掉一项」 |
| **改结果** | 这一轮跑完之后世界是什么样 | 直接把状态改成想要的样子，不管它是怎么变过来的 |

两者都作用在上一 turn 上，界面上是同一个编辑器的两个标签页，不是两个概念。

## R22 · 状态随时看得见

当前世界是什么样，用户任何时候都能打开看，人类可读。不必进开发者模式，
也不必等哪一轮结束。

## R23 · 清单类的东西要能减，不只是能加

角色身上的东西会用完，随从会离队。用户改状态时必须能**去掉列表里的一项**，
而不是只能把整个列表重设一遍。

**为什么**：只能重设的话，一个「青锋剑、止血符 ×2」的清单迟早被拍成一句话，
结构一次性塌掉且不可逆。
