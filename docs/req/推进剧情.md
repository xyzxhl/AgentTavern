# 推进剧情

> 说话、看它写、中途插话、喊停、回答它的提问。这是用得最多的一条路。

## R7 · 一条顶层输入开启一个 turn

用户提交一条顶层 user input，系统开启一个 turn，写出接下来发生的事。
正常完成时它有一个 run / node；重生成只为这个 turn 增加另一个兄弟版本，
不会吃掉下一条输入或开启下一个 turn。

连着打好几句时**逐条消费，不打包**——角色扮演里每个动作都该得到世界各自的回应，
两句并成一轮等于吞掉了其中一个动作。

## R8 · 用户写出的是动作，世界决定结果

用户写「我再来一记御剑斩」，而它还在冷却——**动作是锚点，结果归世界**。

法术冷却中、钱不够、东西用完、对方先动手，都可以让这个动作落空。但落空必须
**写得可见、有据**：写清他确实试了、以及为什么没成。

**不包括**：偷偷把它换成一个能成的动作，或者当作他根本没做过。

## R9 · 边写边看，不用等整轮跑完

正文一边生成一边出现。用户不必盯着一个转圈的图标等几分钟。

**不包括**：把这当成权威。断线时这些字可能丢，最终以整轮落地的那一份为准。

## R10 · turn 内能插话，不必等它结束

看着它往错方向走的时候，用户可以在**当前 turn 内**插一句；这条消息不是新的
turn input，不产生第二个节点。

插话分两种，区别只在正在执行的那次操作怎么处理：

| | 意思 | 当前操作 | turn |
|---|---|---|---|
| **纠正** | 正在往错处走，现在就改 | 立即打断，随后追加 | 仍是当前 turn |
| **引导** | 给接下来的推演补一句 | 让它完成，在下一个合法边界追加 | 仍是当前 turn |

**排队不是插话。** 排队内容等当前 turn 完成后才出队，作为下一个 turn 的顶层
user input。

## R11 · 喊停不等于作废

按下停止的意思是「**别再往下跑了**」，不是「刚才那些都不算」。

已经完成的工具往返与上游阶段在当前 turn 的草稿里留着；正在执行而被取消的那次操作
不算完成。恢复或带纠正继续时仍属于同一个 turn，不从一个新节点开始。turn 一旦完成、
放弃或失败，执行流量不进入节点或后续 context。

**但半截正文不留**——用户按停止恰恰是因为不想要那半句，留着它下一轮会接着往下写。

## R12 · 它可以停下来问，用户可以不选

走到岔路时它会给一个问题和**恰好三个**不同的发展方向。

用户可以选一个，**也可以都不选、自己写一条**。自己写的那条不受任何校验——
"模型没想到的第四条路"恰恰是最该传下去的一种回答。

**不包括**：一个「其他」选项。那是没有自由作答入口时的将就，白占三分之一的选项位。

## R13 · 它问得多不多，用户说了算

有一个「模型剧情控制权」的档位：**给它的权越大，它问得越少**。

## R14 · 生成的调子可以调，不用改提示词

用户可以调整六个彼此独立的服务级 choice，改完后从下一个新启动的 run 生效：怎么处理输入、
给模型多大剧情控制权、允不允许它替用户的角色说话做事、director 的事件密度、
writer 的铺陈程度，以及 goal_manager 的推进节奏。

这些不是 session 配置；同一台服务上的所有故事共用当前选择。已经在跑的 run 继续使用
启动时那组选择，不在中途混入新值；同一 turn 的重生成是新 run，会采用新值。

## R15 · 它不会替用户的角色做决定（除非允许）

默认情况下它不写用户角色的新行为、新决定、新心理。用户可以放开这条限制。

## R16 · 一段剧情写完了，可以收起来

一段戏演完之后，那几轮会被压成一条摘要，故事再长也不会把上下文撑爆。

分段可以让它自己判，也可以**用户手动断在这里**。

**不包括**：让用户操心什么时候该压缩、压成多少字。

## R52 · 整轮失败后，原输入不能随失败一起消失

整轮失败不产生节点，但时间线仍显示这次输入、失败原因和「重新生成」入口。重新生成就是
从仍然活跃的上一节点重新提交同一输入；若用户切换了分支，这份临时失败记录作废。

## R55 · （已废弃）它记得上一轮为什么查过这些资料

曾计划在每轮后另生成推演摘要。该方案取消：它增加一次调用和线性增长的非权威历史，
仍不能可靠阻止重复试探；thinking 与工具对话继续只活在当前 turn。

## R56 · 按需设定的名字要让我看得出它何时有用

用户给 worldbook 的按需条目命名时，名字本身应能说明条目的主题、适用场景和关键区分。
系统把这个名字同时当作索引提要与展开地址，不代替用户从正文里猜一个更好的名字。

## R57 · 正文写到本轮细纲的终点就停

writer 可以自由展开细节，但完成细纲列出的场景、动作、信息和结果后就结束本轮正文，
不能顺手写后续反应、赶路、时间跳转、下一项任务或下一幕准备。

## R58 · 折叠由内容结构决定，不由字数决定

state 从每条路径的叶端折叠最后两层；worldbook 只按用户选择的「需要时展开」折叠；
history 只按已经完成的剧情段折叠。字符串再长也不能单凭字数被隐藏，短内容也不能仅因
没达到阈值而绕过已经明确的折叠边界。

## R59 · 正文里的时间前后对得上

当用户、上文或细纲已经给出日期、经过天数或「当天／次日／明日」等相对关系时，正文
不能在同一条时间线上互相打架。state 只能记录正文能够唯一确定的当前时间，不能替正文
猜一个日期来掩盖矛盾。
