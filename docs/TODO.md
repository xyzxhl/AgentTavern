# 没落实的

> **开发中允许三层对不齐**，但不允许它藏在正文里——藏起来就等于假装它已经成立。
> 每条写清缺的是哪一层。
>
> 三种缺口的定义见 [Workflow.md](Workflow.md)。

| 缺什么 | 意味着 |
|---|---|
| req 有，spec 没有 | **功能还没做** |
| spec 有，test 没有 | 没人知道它现在还成不成立 |
| spec 有，代码没有 | **写在纸上的规格**——最危险的一种，它读起来和落地了的一模一样 |

## 实现与实测缺口

### 外部资料检索（S136–S154）：**代码全在了，缺的是前端断言**

前后端都落地，并且**在 Chrome 里真的点了一遍**（明暗两套主题）：丢文件 →
四种待办各出现一次 → 收进来 → 改文件 → 改名 → 删源文件 → 删除前把
「1 局故事挂着它」摆出来。GBK 那份显示 `gb18030`。

那一遍点出三处**只有看得见才发现的东西**，已修：通知过期不消失
（几秒后「正在建索引」成了假话，而卡片上写着「可用」）、不可操作的待办
压在要处理的东西上面、没有会话时挂载按钮无声消失。

**但仍然一条前端断言都没有**——这一页和 `spec/UI.md` 那八条落在同一个空缺里
（见下面「前端行为，一条测试都没有」）。人点过一遍**不等于下次改动不会退化**。

### 已明确的降级边界：相似度阈值分不开「同领域但答不上」

2026-08-30，真端点（DashScope `qwen3.7-text-embedding`，1024 维），
一份 897 字的唐代官制资料，20 个问法分三类：

| 类别 | 最低 | 中位 | 最高 |
|---|---|---|---|
| **答得上**（资料里确实写了） | +0.5557 | +0.6026 | +0.7433 |
| **同领域但答不上**（宋代枢密院、明代内阁……） | +0.4311 | +0.5322 | **+0.5812** |
| **跨领域**（晚饭吃什么、nginx 配置） | +0.2490 | +0.3175 | +0.3426 |

**跨领域那一档拦得住**：最高 0.3426，现在的 `0.35` 一条都不放过。
[S148](spec/Corpus.md) 在这一档上成立。

**中间那一档拦不住，而且没有任何阈值拦得住**：它和「答得上」重叠——
`汉代的三公九卿`（0.5812）比真答得上的 `铨选看哪几样`（0.5557）分还高。
这不是 0.35 定低了，是**相似度量的是「话题相不相关」，不是「答不答得上」**。

**设计结论**：这个缺口不能由基础阈值补上。R43 / S139 已把降级模式的承诺收窄为
“话题相关”；配置专业 reranker 时才增加“是否足以回答”的否决层。下面记录的是
已接入路径的实测，不代表所有 provider / model 都自动获得同一保证。

**这次的绝对值不能直接用。** 资料只有 897 字 3 块；一本三十万字的小说有几千块，
「最相似的那一块」的分数天然更高，三条分布会整体上移。**要重量。**

### 增强路径：专业 reranker（qwen 已实测）

**在真实链路上量的**（2026-08-31，qwen / `qwen3-rerank`，13749 字 / 49 块，
候选来自真的混合检索，20 个 query）：

| 类别 | 最低 | 中位 | 最高 |
|---|---|---|---|
| **答得上** | 0.7561 | 0.9111 | 0.9433 |
| **同领域答不上** | 0.2561 | 0.3676 | **0.4307** |
| **跨领域** | —— 混合检索那一步就没候选，S148 的阈值已经拦住 | | |

空档 **0.4307 – 0.7561**，`min_relevance` 取中点 **0.6**（0.45–0.70 在这组数据上
都是 0 漏 0 放）。**偏高是有意的**：漏掉一条真的是可恢复的（回执说「这次没找到」，
模型能换个说法），放过一条假的是不可恢复且看不见的。

> 更早还有一次 6 段手搓清单上的测量（`gte-rerank-v2`，空档 0.1594–0.2833）。
> **那组数不能用**——不同模型、候选也不是真链路给的。留在这里只为说明
> **阈值绑死在「哪一家 + 哪个模型」上**这件事有多具体。

### 量到的：问句会让 BM25 那一路整个失效

`min_coverage: 0.5` 要求 query 切出来的词有一半落在块里，而**问句里大半是疑问词**
（谁、哪、什么），资料里根本不会出现：

| query | 切出来的词 | 覆盖率 |
|---|---|---|
| `谁能驳回诏书？` | 谁/能/驳回/诏书 | 0.25 ✗ |
| `封驳 涂归` | 封驳/涂归 | 1.00 ✓ |

真实规模跑一遍（20824 字 / 68 块）确认：三个问句形式的 query，**BM25 一条候选
都没出**，全靠向量那一路。

**所以 `director.yaml` 里 `corpus_search` 描述的那句「用资料里会出现的说法，
不要问句」不是文风建议，是 BM25 能不能用上的开关。** 改软了那句话，BM25 会
静默地不再贡献候选，链路退化成纯向量——而没有任何地方会报错。这个耦合已经写进
`config.yaml` 的注释，但**没有测试钉住**：要钉得先能断言"模型实际发出的 query
长什么样"，而那要等真跑起来采样。

### reranker：qwen 接上了，另外三家还没验过

lookup.py 走的是专业 reranker 那条路，**没配时不 rerank**——按融合次序取前几条，
一次模型调用都不发。用 chat 模型排序那条退路已经删掉（S141）：它只能排序不能
否决，而这条链路最危险的一类正是「同领域但答不上」，排第几都还是会被当成答案用。
否决阈值 `corpus.min_relevance = 0.6`，在真实链路上量出来的（见 `config.yaml`
那一段的注释）。

实跑 7 个 query 判对 7 个：三个「答得上」各留下 5 段，三个「同领域答不上」
**20 条候选全部否决**、回执是「这次检索没有找到足够相关的段落」，
一个「跨领域」在混合检索那一步就没有候选。

**还欠三笔账：**

1. **cohere / jina / voyage 的形状是照文档写的，没对着真端点验过**——
   和 `Embedder.embed` 那次「按 index 归位」是同一种账。
2. **阈值只对 qwen/qwen3-rerank 有效。** 换任何一家或任何一个模型都要重量，
   照抄那个 0.6 会让整条链路的松紧悄悄变掉，而没有任何地方会报错。
3. **样本小**：一份 7 千字的资料、20 个 query。换一本三十万字的小说要重量。

### 归因第六类「写入冗余」

规格说归因分**六**类，代码里的 `AttributionClass` 只有**五**个成员，
`WRITE_REDUNDANCY` 不存在，也没有任何测试。

它当初是专门补的：原本五类里写入侧只有"遗漏"没有"多余"，于是"记了不该记的"
无人负责。而**冗余的代价是慢性的**（状态越长越容易看漏要紧的那几条），
不会以单点错误的形式暴露，只能靠专门一类去查。

连带六处仍写着「五类」：`Principles.md` P18、`README.md`、`Optimization.md` ×2、
`models/trace.py`、`bench/grader.py`。`spec/Prose.md` 写的是「六类」——
**同一个库里两种说法并存**。

新的 [`spec/Architecture.md` S12](spec/Architecture.md) 已按六类写，并在条目下
标了「这条规格没有落地」。

> 补它要动代码与测试，不在文档迁移范围内。

## spec 有，test 没有

迁移中逐条核对「验收」字段时留下的。

| 规格 | 缺什么 |
|---|---|
| [S56](spec/Retrieval.md) 检索工具的描述给触发条件不给机制说明 | 六条触发条件与三条反面都没有测试守着。**它是提示词内容，容易在下次精简时被整段删掉** |
| [S71](spec/Worldbook.md) 不认识的版本直接拒绝 | 没有测试喂一个 `version: 2` 进去看它拒不拒。这条的失败模式恰恰是「尽力而为地读进来」——**不测就发现不了** |
| [S85](spec/Prompting.md) 消融换一份 YAML 而不是开后门 | `PromptSetup` 被整套测试**用着**，但没有一条测试钉它自己的语义（改的是副本、跑完删掉） |
| [S106](spec/InputHandling.md) 动作是锚点，结果归世界 | 模型实测里选对了，**但那是蒙对的**——设计里从没规定过。现在规定了，仍然没测 |
| [S115](spec/Trace.md) 落盘的 trace 要能读回来 | 没测「没留过痕的轮次回空列表而不是 404」 |

### S34 / S35 的判据：**没有测试，而且是故意的**

「记什么」「不记什么」两条判据整个写在 `state_manager.yaml` 的正文里。原先
`test_state_write_says_what_to_record` 逐句钉着它（"约束类""兑现了""冷却"……
十几条 `in desc`）。**那些断言已经删了。**

理由不是懒：**提示词正文归用户。** 用户重写一遍措辞，那十几条就全红——
而红的不是缺陷，是他行使了那份所有权。把它钉住，等于用测试反对用户改提示词。

留下的 `test_the_criteria_are_not_in_the_tool_description` 只钉一件事：
**判据不能在工具描述里留第二份副本**（S27）。那一份用户改不到，两份并存时
他会改完 YAML 以为生效了。

代价照写：**这两条规格现在只能靠人读，靠实测发现回归。**

### 折叠层级：这一条刚从「写在纸上的规格」里爬出来

`WorldbookEntry.depth`（S67 的旧版）**从来没生效过**：`render_state` 的 `depth`
两个调用点都没传，恒为 0，`_fold` 整个是死代码——而界面上那个「展开层级」输入框，
用户填了、存了盘、对模型毫无影响。

它现在接上了（一个值，写在两份 YAML 的 `- type: context, source: state` 上），
并且有测试守着（`test_the_fold_depth_comes_from_the_yaml_and_really_folds`）。

**留在这里是当标本**：这是「spec 有、代码没有」最完整的一种形态——它读起来和
落地了的一模一样，还配了一个能动的控件。**验收字段是空的那一刻就该发现**，
而当时那条规格的验收指的是两条别的测试（注入与工具注册），
它们各自都通过，只是都不碰折叠。

### 前端行为，一条测试都没有

`spec/UI.md` 的 16 条里有 **8 条没有任何测试**：S122 一件事一个入口 · S123 左栏不做
tab · S124 设定库是页面 · S125 两块过程夹着正文 · S128 目标条进输入框上方 ·
S133 外观归本地 · S134 选取值只有一种交互形态 · S155 改名就地改。

原因很直接：**前端没有测试**。整个 `frontend/` 只有 `tsc --noEmit` 和构建，
没有一个断言。而这些恰恰是**最容易在下次改动里悄悄退化**的东西——
类型检查看不出"两个入口"或"时间线倒着走"。

**同一条判据在 [S135](spec/UI.md) 下面已经立着**：一条决策落地与否，
看的是它从用户那一侧够不够得着。而现在没有任何自动化能回答这个问题。

> **一条自我提醒。** 这一节最初列了七条，其中四条是错的——
> `test_the_tool_list_is_not_a_message`、`test_siblings_endpoint`、
> `test_a_bare_key_shadowing_a_namespaced_one_is_flagged`、
> `test_stop_cancels_only_the_run_not_the_loop` 都存在，我按关键词搜没搜到就下了结论。
>
> **搜不到不等于没有。** 报「缺测试」之前要按规格描述的**行为**去找，
> 不是按规格的**措辞**去找——测试名是用它自己的话写的。

## 悬着的问题

### 一条坏条目该不该让整份导入失败

现在是**整份失败**：`/worldbooks/import` 先 `bundle.check()`，不过就 400。

而设定库**列表**那条路走的是另一套：好的照数、坏的点出来，因为一条坏数据曾经让

**但导入还有第三种情形没被回答**：手上是别人给的一份、其中一条坏了，用户既拿不到
另外九十九条，也没法只修那一条。目前只能让他去改文件。

## test → spec 的反向链接没做

spec 那侧的「验收」字段点了 **211 个测试名**，所以 **spec → test 是通的**。
反过来（每条测试的 docstring 首行写它钉的 `S<n>`）**只做到 141 条**，
其余靠人从 spec 那侧查。

试过一次自动加，脚本在多行签名上匹配跑偏、写坏了一个文件（84 条改动而可推导的只有
79 条），已整个回滚。**这件事要么逐文件手工做，要么不做**——
自动化在这里的风险大于收益，而正向链路已经够用。
