# worldbook 交换格式

> 导入 / 导出的文件长什么样。对应 [Decisions.md](../Decisions.md) D90 / D157 / D158 /
> D170 / D175。
>
> worldbook 是**用户写的唯一输入**，所以它是这个项目里唯一值得单独定格式的东西——
> 别的（节点树、trace、state）都是跑出来的产物。
>
> **一份 worldbook 可以开出好几个 session**（D170 推翻了 D92 的一对一）。它是一级
> 资产，存在 `data/worldbooks/<id>/` 下，不在任何 session 目录里；接口是
> `GET|POST /worldbooks`、`/worldbooks/{id}/entries`、`/worldbooks/{id}/export|import`。
>
> **它只有条目，没有字段**（D175）。题材与基调、剧情尺度都是 `world` 条目——
> 它们和「旧货店在哪」是同一种东西，一段关于这个世界的字。所以包里除了名字
> 只有 `entries`。

## 1. 形状

```json
{
  "format": "agenttavern.worldbook",
  "version": 1,
  "name": "雨夜",
  "note": "给读到这份文件的人看的一句话，不是设定的一部分",
  "entries": [
    {
      "name": "题材与基调",
      "kind": "world",
      "mode": "always",
      "content": "现代，悬疑，克制。"
    },
    {
      "name": "陈屿",
      "kind": "character",
      "mode": "always",
      "content": "四十岁，旧货店老板。说话习惯绕开正题，用反问代替回答。",
      "voice": "说话绕，答非所问，很少给准话"
    },
    {
      "name": "陈屿·初始状态",
      "kind": "state",
      "mode": "on_demand",
      "depth": 2,
      "values": { "陈屿": { "在场": true, "知情": ["林昭手里有那张照片"] } }
    },
    {
      "name": "林昭",
      "kind": "character",
      "is_player": true,
      "mode": "always",
      "content": "三十岁出头，本地报社记者。做事谨慎，习惯先观察再开口。",
      "voice": "话少，先观察再开口"
    }
  ]
}
```

`entries` 里的每一条就是一个 `WorldbookEntry`（见 `models/worldbook.py`）。

**三类条目**（D159）：

| `kind` | 装什么 | 额外字段 |
|---|---|---|
| `world` | 一段不受限制的文本：地方、组织、规矩、历史 | —— |
| `character` | 正文 + **语言习惯**（`voice`，只进 writer） | `voice` / `is_player` |
| `state` | 一棵嵌套的键值树，这局故事第一帧的状态 | `values` / `depth` |

**用户扮演的角色不是第四类**，它是 `character` 加一个 `is_player`——凡是对角色
成立的（正文、语言习惯、可展开）对它一样成立，做成独立的一类就得在每一处角色
分支旁边记得再写一遍，而那种「记得」迟早会漏。

## 2. 三条约定

### 不带 `id`

导出时**去掉 `id`**，导入时重新分配。

id 是这一份存储里的地址，不是条目的身份。带着它导入会有两种坏结果：撞上已有条目
就静默覆盖，或者两份文件里的同名 id 指向完全不同的东西。**换个说法：这份文件描述
的是「有哪些设定」，不是「它们在谁的硬盘上排第几」。**

代价是导出再导入拿不回原来的 id，因此**不能拿它做备份还原**。备份是另一件事
（整个 session 目录复制走就是），格式不该同时服务两个目的。

### 不带 `summary`

它是 `summarize` 懒惰生成的缓存（D69），跟着 `content` 走。`content` 一旦被人改过，
旧摘要就是错的，而导入方无从判断改没改。**缓存不该跨机器传播。**

### 不带任何 session 配置

元指令、控制维度、能力开关、goal 都不进这份文件。它们是「这一局怎么玩」，
而 worldbook 是「这个世界是什么」——换个人来读，世界还是那个世界，玩法未必。

混在一起会让导入变成一件危险的事：用户想要的是几个角色设定，却顺带被改掉了文风、
视角和能力开关。

## 3. 导入的两种方式

| | 行为 | 什么时候用 |
|---|---|---|
| **追加** | 现有条目全留着，新条目挂上去 | 从别处拿几个角色过来 |
| **替换** | 先清空现有 worldbook，再导入 | 换一个世界重开 |

**都不改已经冻结的初始状态**（D158）：故事一旦开始，起点就定死了，导入只影响
「以后新建的会话」。故事还没开始时，导入会立刻改变当前状态——那时没有任何一轮
依赖它，改了是对的。

重名不做合并，也不报错：**同名条目可以并存**。名字是给人看的标签，不是主键；
真要去重该由人看着办，代码替他猜只会猜错。

## 4. 版本

`version` 目前恒为 `1`。它存在只是为了让将来的破坏性改动有地方落脚——
导入时校验，不认识的版本直接拒绝，而不是尽力而为地猜。

**尽力而为地读一份不认识的格式是这类功能最常见的错**：它会把一份半懂的数据导进来，
用户以为成了，几轮之后才发现有东西不对，而那时已经分不清是导入丢的还是模型写坏的。
