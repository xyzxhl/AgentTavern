# 配置分类

> 对应 [Decisions.md](../Decisions.md) Q13 / Q15 / D38 / D174。四类东西性质不同，
> **不可混为一张表**——混在一起是概念膨胀的来源。
>
> **这四类是判据，不是分区**（D174）。它们回答「这东西改变什么」，据此可以判断
> 一个新旋钮该不该存在、该长什么样。但它们**不再各自对应一个存储位置或界面区块**：
> 除了目标之外，全部住进 agent 管理（见 [UI.md](UI.md) §7）。

## 分类判据

| 类 | 改变什么 | 住在哪（D174 之后） |
|---|---|---|
| **元指令** | **目标**——这局故事要达成什么 | session（只剩 `goal`） |
| **控制维度** | **处理方式**——每轮怎么处理 | agent 管理：某个 `choice` 的 `selected` |
| **模式** | **触发源**——谁触发生成 | session（`time_driven`，与 goal 并列） |
| **能力开关** | **系统能做什么**——哪些工具存在 | agent 管理：某个工具 / 某条提示词 / 某段 context 上的开关 |

**为什么模式留在 session 而其余上调**：触发源问的是「**这局故事**没人说话时要不要
自己往前跑」——它和 goal 的自动续跑是同一类东西，回答的都是"这局故事怎么自己
往前走"。而控制维度和能力开关问的是「模型收到什么」，那是提示词的事。

## 能力开关：关闭即不注册

> **关闭的能力，其工具根本不注册**——模型看不到它。

这比「注册了但拒绝调用」强：后者仍然占 prompt 体量、仍会被尝试、失败还要消耗一轮往返。工具面越小，模型的决策空间越小（P10）。

理由与 D74 同源：**不同故事需要的能力差别很大，不该预设所有故事都一样。**

| 开关 | 默认 | 关闭时 |
|---|---|---|
| `state` | 开 | **state_manager 整个不跑**，`state_query` / `state_write` 不注册（D143）。~~E0 契约随之失效（D80）~~——E0 本身已被 D143 删除，这条连带没有对象了 |
| `history_search` | 关 | **禁止检索**：只有近期全文 + 更早的长期总结，`history.*` 不注册 |
| `summarize` | `manual` | 摘要由用户维护，`summarize` 不注册；`auto` 时模型自行压缩并缓存 |
| `ask_question` | 开 | 模型只能自己拿主意。**注意这与控制权等级不同**：等级调节积极性，这里是有没有这个动作 |
| `trace` | **关** | 见下 |

**worldinfo 的开关是数据驱动的**：每个条目有 `always`（全量注入上下文）或 `on_demand`（只进索引、按需展开）两种模式。**全部条目都是 `always` 时，worldinfo 工具不注册**——没有东西可展开，留着只是白占体量。

### trace 是开发者模式

trace 服务于 eval，**不是产品功能，默认关闭**。它以 **node 为单位**——一个 run 一个文件，记录从用户输入到最终输出之间发生的一切。

关闭时事件仍会推给 UI（「呈现 agent 工作过程」依赖它），**只是不落盘**。这正是 D25 要求 trace 与 UI 呈现分两层的好处：两者可以独立开关。

## 一、元指令

**这一类只剩 `goal` 了。** 曾经在这儿的每一样都搬走了，各有各的去处：

| 曾经在这儿 | 现在 | 判据 |
|---|---|---|
| 题材 / 基调 | **worldbook 的一条 `world` 条目**（D175） | 它就是一段关于这个世界的字，和「旧货店在哪」性质完全一样 |
| 剧情尺度 | 同上 | 同上 |
| 角色语言习惯 | **角色条目的 `voice`**（D159/D171） | 它是那个角色的属性 |
| 视角 / 文风 | **agent 管理里 writer 的两个 `choice`**（D174） | 读者偏好，而取值只该有一处 |
| **goal** | **留在 session** | 它是「这局故事要达成什么」，不是配置 |

### 三次搬家，一条判据

「换个人来读还成不成立」→ D170 用它答出「换局故事还成不成立」，把题材与尺度从
session 挪到 worldbook。**D175 再往前一步**：既然它们是这个世界写的字，就不必是
worldbook 上的**字段**，做成**条目**即可——`world` 条目本来就是"一段不受限制的
文本"，凭什么题材要特殊处理。

于是 **worldbook 只有条目，没有字段**（除了它自己的名字）。一种东西，一个编辑器。

**代价**：题材与尺度不再是独立可挪的一节，它们和别的设定一起进 worldinfo 那一块，
位置由 `render_worldinfo` 决定。这是"不特殊处理"的定义本身带来的。

### goal 的机制

**正常一轮生成结束后检查是否达标，未达标则开启下一轮**；目标刚设上（或刚恢复）时**先跑一次规划**，写出那一轮的输入（D168）。

它**不是模式**：有 goal 和没 goal，系统跑法完全一样（用户输入 → 生成），只是轮末多了一个判定。它不改变运行形态，因此归元指令。

判定方式见 [NonTurnBased.md](NonTurnBased.md) §5.5：一律交给模型，不降级为代码。**预算上限可以留空**，留空就是不设（D164）——止损交给暂停和放弃。

### 文风与角色语言习惯为何分家

两者都不随轮次变，都是 writer 的常驻输入（[Generation.md](Generation.md) §4）。
**但归属不同**：文风是读者这一侧的偏好，所以是 writer 的一个 `choice`；
角色语言习惯是**那个角色的属性**，所以在他自己那条条目上（D159）。
判据仍然是「换个人来读还成不成立」——换个人读，"陈屿说话绕"还成立，
"我喜欢短句"不成立。

## 二、控制维度

**它们全部住在 agent 管理里，各是某个 `choice` 的 `selected`**（D174）。
下面这张表是**判据的清单**，不是界面的清单。

| 维度 | 取值 | 落在哪个 agent 的哪个 choice |
|---|---|---|
| **输入处理** | 转述+推进 / 只转述 / 不转述+推进 | director · `narration_and_advancement` |
| **模型剧情控制权** | 三档 | director · `ask_question` 的**工具描述**（D140②） |
| **是否允许抢话** | 二值 | director · `speaking_rule` |
| **文风 / 视角** | 档位 | writer · `prose_style` / `pov` |
| ~~展开密度~~ | ~~档位~~ | **作为一个维度已取消**，见下 |

### ~~展开密度~~ 取消了（D174）

它曾是**一个**取值喂三处：director 的事件密度、writer 的铺陈程度、goal_manager 的
推进节奏。上调之后它们是**三个各自独立的 `choice`**，代码不再保证一致——于是
"有一个叫展开密度的维度"这句话不再为真。

**D93 的核心保住了**：那条讲的是「director 不该知道篇幅，所以同一件事在两侧读
**两组不同的措辞**」——那是语义约束，不是同步机制，而两组措辞照旧各在各的文件里。

**降级的是保证，不是能力**：现在做不到"director 紧凑、writer 铺陈"，之后可以。

### 单轮覆盖已取消

取值只剩一处之后，"覆盖"没有被覆盖的对象了（D174 推翻 D45）。输入框旁边不加任何
控制件。

### 输入处理（三档）

| 档 | 含义 | 典型输入 |
|---|---|---|
| 转述 + 推进 | 转述用户行为，然后继续演 | "我推开门" |
| 只转述 | 只写用户这一步，停下等下一步 | 贴身推进，用户完全掌控节奏 |
| 不转述 + 推进 | 用户输入作为前提，直接写后续 | "往悬疑走"这类元指令 |

三档取代了原先"转述二值 × 故事跨度"的设计。**故事跨度作为独立维度已取消**——想快进就直接写在指令里（那本来就是指令内容），想零推进就是"只转述"。

残留的"推进多少"被现有两维夹住：展开密度决定写多细，控制权等级决定跑多久停一次。控制权低时一个 run 自然短，高时模型连跑。

### 模型剧情控制权

> **直接反映为调用 `ask_question` 工具的积极性。模型控制权越高，调用积极性越低。**

这是 [NonTurnBased.md](NonTurnBased.md) §2「停下来给选项让用户选」那个统一机制的操作化形式。三种非轮次形态（长循环 / 整体多候选 / 交互式创作）都是这一个旋钮的不同档位。

两点：

- 它是**倾向**而非硬计数，因此实际效果依赖模型。
- 但 **`ask_question` 的调用频率在 trace 里直接可观测**，所以每个档位的实际表现可以被测量和校准，不必靠猜。

### 是否允许抢话

模型能否替用户的角色说话、行动、描写心理。

**为何必须显式**：这是 RP 里最尖锐的边界争议，且两种偏好都很常见——有人只要模型写 NPC，有人希望模型帮忙演自己的角色推进剧情。没有默认答案，推断必错一半。现有工具靠 prompt 写"不要替用户说话"，众所周知经常失效。

它是少数**违规几乎总是真违规**的维度（不像字数超标可能无害），因此是唯一值得做运行时提示的候选。但仍不自动修复——见 §五。

### 铺陈程度（原「展开密度」）

每单位故事时间写多少字。与"故事跨度"正交：同一场戏可以写 200 字也可以写 2000 字。

笼统的"长度"把两个量混在一起，用户说"写长一点"时模型不知道是要多写细节还是多推进剧情——这是常见的失望来源。**这个区分仍然成立**，它是三处措辞各自要表达的东西；
变的只是"三处由同一个取值驱动"这件事（见上）。

## 三、模式

**时间驱动模式**——没有用户输入时也触发生成。**尚未实现。**

这是目前唯一的模式成员，本身说明分类线划对了：它是唯一改变**触发源**的东西。

与控制权等级的区别：控制权管"模型跑多久停下来问用户一次"，时间驱动管"没有用户输入时会不会跑"。两者可叠加。

**它留在 session，不上调**（D174）：触发源问的是「**这局故事**没人说话时要不要自己
往前跑」，和 goal 的自动续跑是同一类东西——两者回答的都是"这局故事怎么自己往前走"。
控制维度和能力开关问的是"模型收到什么"，那才是提示词的事。

**长循环自主创作不是模式**，它是控制权等级调到最高 + goal 未达标持续触发，都是既有参数的取值。

## 四、goal 与控制权不冲突

**作用点不同**：控制权作用在**轮内**（是否停下来问用户），goal 作用在**轮末**（是否再开一轮）。可任意组合。

| | 无 goal | 有 goal |
|---|---|---|
| **模型控制权高**（少问） | 自主写完一轮就停 | **长循环自主创作** |
| **模型控制权低**（多问） | 一轮内多次征询，交互式创作 | 持续推进但频繁征询，边跑边确认方向 |

## 五、~~粒度分层~~ 只剩一层

**关键判断仍然成立：绝大多数设定是设一次长期有效的，不需要每轮问。** 变的是
它推出来的形态——既然设一次就长期有效，那把取值放在**它被使用的地方旁边**
（提示词里）比放在一个单独的"设置面板"里更直接。

于是三层（创建时 / 常驻面板 / 单轮覆盖）塌成一层：**全部在 agent 管理里，改完
下一轮生效**。D45 那条「单轮覆盖做成快捷方式而非选择题」随之作废——没有覆盖了。

### 换一套配置怎么办

「玩 A 用配置 1、玩 B 用配置 2」仍然做得到：**去 agent 管理改**。这是配置层面的
动作，不是每轮的动作，所以它不违反上面那条判断。

> **未定**：要不要把整套配置做成**可命名、可切换的预设**。不做的话"换一套"等于
> 手动改一批 `choice`；做的话它就成了第三类一级资产（故事 / 设定 / 配置），而
> 那会把"配置绑不绑 session"这个问题重新提出来。**先不做**，等换配置真的变成
> 日常动作再说。

## 六、维度遵守情况的检查：只做观测，不做强制

**写作任务中代码检查的可靠性有限**：

- 字数达标不等于密度约束被满足——200 字也可能堆砌词藻。
- 故事时间戳是**模型写进去的**，代码读它不是独立验证（D30）。
- 即使检出偏差也不该自动重生成：要求 1000 字给了 2000 字而用户满意时，拦截是帮倒忙；就算用户确实想重来，**决定权也该在用户，因为重生成成本高**。

**判据：修复成本决定能不能自动强制。**

| 修复动作 | 成本 | 能否自动强制 |
|---|---|---|
| 补交状态增量（补字段，不动正文） | ≈0 | ✓ 可以（D19 保留） |
| 重生成正文 | 高 | ✗ 只能提示，用户决定 |

**代码检查的主要价值在开发期与 eval**：正则不是判断器，是**采样器**——它不回答"这段写得对不对"，而是把可疑样本（字数异常、疑似抢话、时间跳跃过大）挑出来定向送 human / AI eval。这让 eval 的有效覆盖率大幅提高，不必盲抽。与 D8 配套，成本近零。

## 七、明确排除与存疑

| 候选 | 处置 |
|---|---|
| 文风 | → writer 的一个 `choice`（D174）；角色语言习惯 → 角色条目的 `voice`（D159） |
| 叙事节奏 | 归细纲的事件密度（D35），不单设 |
| 故事跨度 | **取消**，被输入处理三档与展开密度吸收 |
| 笼统的"长度" | 拆成故事跨度 × 展开密度，前者取消后者保留 |
| 元信息可见性 | 显示设置，不影响生成 |
| **随机性 / 意外程度** | **存疑**。与控制权等级相关但不完全重合（高控制权+低意外=按套路，高控制权+高意外=允许转折）。不确定用户是否感知得到这是独立旋钮，倾向先不做 |
