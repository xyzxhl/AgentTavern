# Session 元指令、控制维度与模式

> 对应 [Decisions.md](../Decisions.md) Q13 / Q15。三类东西性质不同，**不可混为一张表**——混在一起是概念膨胀的来源。

## 分类判据

| 类 | 改变什么 | 何时设定 |
|---|---|---|
| **Session 元指令** | **目标**——这个 session 要什么体验 | 创建时，很少改 |
| **控制维度** | **处理方式**——每轮怎么处理 | 会话内可调 |
| **模式** | **触发源**——谁触发生成 | 开关 |
| **能力开关** | **系统能做什么**——哪些工具存在 | session 级 |

## 能力开关：关闭即不注册

> **关闭的能力，其工具根本不注册**——模型看不到它。

这比「注册了但拒绝调用」强：后者仍然占 prompt 体量、仍会被尝试、失败还要消耗一轮往返。工具面越小，模型的决策空间越小（P10）。

理由与 D74 同源：**不同故事需要的能力差别很大，不该预设所有故事都一样。**

| 开关 | 默认 | 关闭时 |
|---|---|---|
| `state` | 开 | `state_query` / `state_write` 不注册，且 **E0 契约随之失效**——没有 `state_write` 可调，就不能要求先提交增量 |
| `history_search` | 关 | **禁止检索**：只有近期全文 + 更早的长期总结，`history.*` 不注册 |
| `summarize` | `manual` | 摘要由用户维护，`summarize` 不注册；`auto` 时模型自行压缩并缓存 |
| `ask_question` | 开 | 模型只能自己拿主意。**注意这与控制权等级不同**：等级调节积极性，这里是有没有这个动作 |
| `trace` | **关** | 见下 |

**worldinfo 的开关是数据驱动的**：每个条目有 `always`（全量注入上下文）或 `on_demand`（只进索引、按需展开）两种模式。**全部条目都是 `always` 时，worldinfo 工具不注册**——没有东西可展开，留着只是白占体量。

### trace 是开发者模式

trace 服务于 eval，**不是产品功能，默认关闭**。它以 **node 为单位**——一个 run 一个文件，记录从用户输入到最终输出之间发生的一切。

关闭时事件仍会推给 UI（「呈现 agent 工作过程」依赖它），**只是不落盘**。这正是 D25 要求 trace 与 UI 呈现分两层的好处：两者可以独立开关。

## 一、Session 元指令

用户开启这个 session 是想获得什么样的体验。定义目标，不定义过程。

- 剧情尺度
- 题材 / 基调
- **goal 终止条件**
- 视角
- 文风
- 角色语言习惯

### goal 的机制

**正常一轮生成结束后检查是否达标，未达标则开启下一轮。**

它**不是模式**：有 goal 和没 goal，系统跑法完全一样（用户输入 → 生成），只是轮末多了一个判定。它不改变运行形态，因此归元指令。

判定方式见 [NonTurnBased.md](NonTurnBased.md) §5.5：一律交给模型，不降级为代码；用独立干净上下文的窄调用；必须有 token / run 硬上限保底。

### 文风与角色语言习惯为何是元指令而非维度

它们不随轮次变。它们是 writer 的常驻输入（[Generation.md](Generation.md) §4），不是每轮要调的参数。

## 二、控制维度

| 维度 | 取值 | 层 |
|---|---|---|
| **输入处理** | 转述+推进 / 只转述 / 不转述+推进 | 常驻 + 单轮覆盖 |
| **模型剧情控制权** | 档位 | 常驻面板 |
| **展开密度** | 档位 | 常驻面板 |
| **是否允许抢话** | 二值 | 常驻面板 |

### 输入处理（三档）

| 档 | 含义 | 典型输入 |
|---|---|---|
| 转述 + 推进 | 转述用户行为，然后继续演 | "我推开门" |
| 只转述 | 只写用户这一步，停下等下一步 | 贴身推进，用户完全掌控节奏 |
| 不转述 + 推进 | 用户输入作为前提，直接写后续 | "往悬疑走"这类元指令 |

三档取代了原先"转述二值 × 故事跨度"的设计。**故事跨度作为独立维度已取消**——想快进就直接写在指令里（那本来就是指令内容），想零推进就是"只转述"。

残留的"推进多少"被现有两维夹住：展开密度决定写多细，控制权等级决定跑多久停一次。控制权低时一个 run 自然短，高时模型连跑。

### 模型剧情控制权

> **直接反映为调用 `ask_question` 工具的积极性。模型控制权越高，调用积极性越低。**

这是 [NonTurnBased.md](NonTurnBased.md) §2「停下来给选项让用户选」那个统一机制的操作化形式。三种非轮次形态（长循环 / 整体多候选 / 交互式创作）都是这一个旋钮的不同档位。

两点：

- 它是**倾向**而非硬计数，因此实际效果依赖模型。
- 但 **`ask_question` 的调用频率在 trace 里直接可观测**，所以每个档位的实际表现可以被测量和校准，不必靠猜。

### 是否允许抢话

模型能否替用户的角色说话、行动、描写心理。

**为何必须显式**：这是 RP 里最尖锐的边界争议，且两种偏好都很常见——有人只要模型写 NPC，有人希望模型帮忙演自己的角色推进剧情。没有默认答案，推断必错一半。现有工具靠 prompt 写"不要替用户说话"，众所周知经常失效。

它是少数**违规几乎总是真违规**的维度（不像字数超标可能无害），因此是唯一值得做运行时提示的候选。但仍不自动修复——见 §五。

### 展开密度

每单位故事时间写多少字。与"故事跨度"正交：同一场戏可以写 200 字也可以写 2000 字。

笼统的"长度"把两个量混在一起，用户说"写长一点"时模型不知道是要多写细节还是多推进剧情——这是常见的失望来源。

它同时影响两侧：细纲的事件密度（director）与正文的铺陈程度（writer）。

## 三、模式

**时间驱动模式**——没有用户输入时也触发生成。

这是目前唯一的模式成员，本身说明分类线划对了：它是唯一改变**触发源**的东西。

与控制权等级的区别：控制权管"模型跑多久停下来问用户一次"，时间驱动管"没有用户输入时会不会跑"。两者可叠加。

**长循环自主创作不是模式**，它是控制权等级调到最高 + goal 未达标持续触发，都是既有参数的取值。

---

## 四、goal 与控制权不冲突

**作用点不同**：控制权作用在**轮内**（是否停下来问用户），goal 作用在**轮末**（是否再开一轮）。可任意组合。

| | 无 goal | 有 goal |
|---|---|---|
| **模型控制权高**（少问） | 自主写完一轮就停 | **长循环自主创作** |
| **模型控制权低**（多问） | 一轮内多次征询，交互式创作 | 持续推进但频繁征询，边跑边确认方向 |

---

## 五、粒度分层与显式化的代价

**关键判断：绝大多数设定是设一次长期有效的，不需要每轮问。**

| 层 | 内容 |
|---|---|
| Session 创建时 | 全部元指令 |
| 常驻面板 | 控制权等级、展开密度、抢话、输入处理默认值 |
| 单轮覆盖 | 仅暴露最高频的一两项 |

**单轮覆盖不要做成选择题，做成快捷方式。** 用户不愿每轮点三个下拉框，但愿意打一个 `/只转述` 或点一个"更详细"按钮。同样是显式化，交互成本差一个数量级。

因此显式化的代价边界不在**维度数量**上，而在**单轮覆盖的交互形态**上。维度可以有八个，只要七个设一次就不用管、剩下一个用快捷方式触发，用户完全感觉不到负担。

## 六、维度遵守情况的检查：只做观测，不做强制

**写作任务中代码检查的可靠性有限**：

- 字数达标不等于密度约束被满足——200 字也可能堆砌词藻。
- 故事时间戳是**模型写进去的**，代码读它不是独立验证（D30）。
- 即使检出偏差也不该自动重生成：要求 1000 字给了 2000 字而用户满意时，拦截是帮倒忙；就算用户确实想重来，**决定权也该在用户，因为重生成成本高**。

**判据：修复成本决定能不能自动强制。**

| 修复动作 | 成本 | 能否自动强制 |
|---|---|---|
| 补交状态增量（补字段，不动正文） | ≈0 | ✓ 可以（D19 保留） |
| 重生成正文 | 高 | ✗ 只能提示，用户决定 |

**代码检查的主要价值在开发期与 eval**：正则不是判断器，是**采样器**——它不回答"这段写得对不对"，而是把可疑样本（字数异常、疑似抢话、时间跳跃过大）挑出来定向送 human / AI eval。这让 eval 的有效覆盖率大幅提高，不必盲抽。与 D8 配套，成本近零。

## 七、明确排除与存疑

| 候选 | 处置 |
|---|---|
| 文风、角色语言习惯 | → Session 元指令，不随轮次变 |
| 叙事节奏 | 归细纲的事件密度（D35），不单设 |
| 故事跨度 | **取消**，被输入处理三档与展开密度吸收 |
| 笼统的"长度" | 拆成故事跨度 × 展开密度，前者取消后者保留 |
| 元信息可见性 | 显示设置，不影响生成 |
| **随机性 / 意外程度** | **存疑**。与控制权等级相关但不完全重合（高控制权+低意外=按套路，高控制权+高意外=允许转折）。不确定用户是否感知得到这是独立旋钮，倾向先不做 |
