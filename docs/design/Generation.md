# 生成侧拓扑：director / writer

> **拆分的论证过程**。结论与组件细节见 [Architecture.md](Architecture.md)；判据见 [../Principles.md](../Principles.md) P1–P3。

## 1. 判据：不问"该不该有 director"，问"context 可不可分"

按 [../Principles.md](../Principles.md) P1–P2，多 agent 的唯一不可替代收益是**上下文隔离**。因此拆分与否的正确问法是：

**为了产出最终给用户看的正文，需要哪些 context？这些 context 是否可分？**

方法：先枚举全部 context，再看在某种切法下，两侧各自需要的部分是否有实质差异、跨界传递的信息量是否够小。

## 2. 切法一：两侧都读正文 —— 不可分

若 director 与 writer 都读正文上文，则：

| context | 决定"写什么" | 决定"怎么写" |
|---|---|---|
| 上文（正文） | ✓ 接剧情 | ✓ 接语气 |
| 世界信息 / 静态设定 | ✓ 什么合理 | ✓ 描写要准 |
| 用户指令 | ✓ | ✓ 转述需原文措辞 |
| 节奏 / 基调 | ✓ 涵盖多少事件 | ✓ 句式与段落长度 |
| 剧情约束 | ✓ | ✓ 措辞可能不慎泄露 |
| 文风指导 | ✗ | ✓ |
| 角色语言习惯 | ✗ | ✓ |

**共享项（上文、世界信息）占体量的绝大部分**，独占项都小。拆分不能让任何一方的 context 变小，只是两边都带着同一大坨、各自多一小块。

套判据表：director 入参是"共享的一大坨 + 少量剧情约束"，出参是 brief——**多入少出 → 不要拆**，且这里的压缩是品味类，无验证器。

**此切法下结论是合并。**

## 3. 切法二：director 只读细纲，不读正文 —— 可分

关键设计：**director 始终在细纲层面操作，从不读正文；writer 读正文以保证衔接。**

| context | director | writer | 体量 |
|---|---|---|---|
| 细纲历史 | ✓ | ✗ | 中 |
| 正文上文 | ✗ | ✓ 衔接 | 大 |
| 世界信息 / 静态设定 | ✓ | ✗ 细节已在细纲里 | 大 |
| state | ✓ | ✗ | 小 |
| 用户指令 | ✓ | ✗ 已在细纲里 | 小 |
| 剧情约束 / 叙事节奏 | ✓ | ✗ 细纲的事件密度已编码节奏 | 小 |
| 否定项 | ✓ | ✓ 见 §6 | 极小 |
| 文风指导 | ✗ | ✓ | **大** |
| 角色语言习惯 | ✗ | ✓ | **大** |

几乎无共享项。**这是真正的可分。**

前提是**细纲到正文的映射无歧义**，即细纲要足够细。极限形态是：

> **director 在不约束文风的情况下生成文章，writer 再根据文风要求改写。**

这个 reframe 同时解掉了抽象规格方案的两个致命问题：

- 细纲是散文而非结构化对象，**不需要预设字段格式**——也就不依赖任何未经证实的写作理论。
- 模型不必把"想写什么"翻译成一个符合预设 schema 的对象，**没有元层任务**，不增加思考负担。这是抽象规格方案与 D24 冲突的根源。

## 4. 结论拓扑

```
director（主 agent，tool loop）:
    细纲历史 + 世界信息 + state默认包 + 用户指令 + 剧情约束 + 否定项
      ↓  产出：无文风约束的文章（= 足够细的细纲）
      ↓  ── 固定、单向的静态 workflow 交接（D53）──
writer（纯渲染，单次调用）:
    该细纲 + 正文上文 + 文风指导 + 角色语言习惯 + 否定项 + schema 键名
      ↓  产出：成品正文 + 偏离报告
```

**director 是主 agent，writer 是从它身上拆下来的一个负担**（D52）——writer 只承担文风，不是流水线下游的规划环节。组件级细节见 [Architecture.md](Architecture.md)。

**writer 绝不能做成 director 的 tool**（D54）：工具返回值会回流到调用者上下文，正文一旦回流到 director，§5 的收益与本文全部论证即刻作废。

## 5. 此拓扑独有的收益：更长的历史跨度

**细纲比正文压缩，因此同样 token 预算下 director 能看长得多的历史。**

若细纲约为正文的 1/5，director 即可覆盖五倍跨度的前情。这对长程一致性是直接的、不需要额外机制的收益，甚至部分替代了state的作用——很多"她之前做过什么"的问题，读细纲历史就够，不必查 state。

**合并方案拿不到这个收益**，因为合并后只有一份上下文，压缩与否是全局的。

## 6. 必要修正：否定项必须给 writer

细纲说的是"会发生什么"，而**否定项**说的是"不能写什么"——不能提前揭示的、不允许发明的。按定义它不会出现在细纲里。

writer 改写时为求文采而添加细节，可能无意泄露伏笔或发明设定。因此否定项必须跟着走。其体量极小，不破坏隔离。

叙事节奏则确实可以不给——**细纲的事件密度本身就编码了节奏**。

## 7. 必须定死：实际偏离必须被记录

细纲有两种状态，不可混淆：**计划发生的** vs **实际发生的**。

writer 改写时可能增删细节。若偏离不被记录，director 下一轮读到的就是并未发生的版本——而由于 **director 永远不读正文，它永远发现不了这个偏差**。漂移从这里开始且不可自愈。

落地方式（D57）：**writer 输出「偏离报告」**（通常为空），编排层将其附在节点上，下一 run 的 director 读细纲历史时可见。writer **不改写细纲**，保持纯粹。

注意按 §3 与 [Architecture.md](Architecture.md) §4，writer 本就不该增删实质内容——细节的责任在 director。偏离报告是**兜底与归因信号**，不是常规通路。

## 8. 成本

director 写一遍近全长的文章，writer 再改写一遍，**输出 token 约 2x**，明显贵于"短规格 + 正文"。

但该交易是自洽的：短规格便宜，代价是品味类的有损压缩；细纲=文章几乎无损，代价是 token。[../Principles.md](../Principles.md) P7 主张预算应几乎全压在这条无验证器的边上——此处正是在按该原则花钱。

## 9. 待验证：文风的结构层面能否完全留在 writer 侧

本方案本质是两阶段生成（draft → style pass），该模式有已知失败模式：第二遍改写把第一遍的好东西磨平。

**此处方向有利**：第一遍不带文风约束（模型默认腔调），第二遍是在**去 AI 腔**而非加，比反过来安全。

**残留担忧**：默认腔调写出的东西，**结构上可能已是 AI 味的**——三段式、总结性收尾、对称句式。第二遍换词容易，换骨难。若此担忧成立，文风约束中的结构性部分（如"不要总结性收尾"）就必须前移到 director，而那会重新污染 director 的上下文。

**不现在拍板，列入消融实验项。** 它决定文风约束能否 100% 留在 writer 侧。

## 10. 与用户介入的关系

[NonTurnBased.md](NonTurnBased.md) §2 的频率旋钮触发"停下来给用户选"时，中间量的形态由**用户要看什么**决定，而非由 writer 需要什么决定。

多候选做在**细纲层**：三份细纲比三段成品便宜，用户读走向也比读全文快，且用户比较的是"走向"而非"文笔"——走向才是他想控制的。选定后只跑一次 writer。
