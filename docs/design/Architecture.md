# 架构

> 组件、时序、职责覆盖。拆分的**论证**见 [Generation.md](Generation.md)，判据见 [../Principles.md](../Principles.md)。

## 1. 拓扑

```
编排层（代码，静态 workflow）
  ├─ director（主 agent，tool loop）
  │     产出：细纲（无文风约束的文章）
  │
  │     ── 固定、单向的交接 ──▶
  │
  ├─ writer（纯渲染，单次调用）
  │     产出：正文 + 偏离报告
  │
  └─ goal 判定（窄调用，仅长任务，run 末）
```

**director 是主 agent**，拿走全部推演与状态职责。**writer 是从主 agent 身上拆下来的一个负担**——它只承担文风，不是流水线的下游规划环节（D52）。

## 2. 交接是静态 workflow，不是工具调用

编排层按固定顺序调用二者，中间没有回流、没有协商、没有重试循环（D53）。

### writer 绝不能做成 director 的 tool

把 writer 写成 `render(细纲) → 正文` 看起来很自然，但**工具返回值会回流到调用者的上下文**——正文一旦回流到 director，整个隔离设计就没了。

director 之所以能覆盖五倍跨度的历史，正是因为它**从不读正文**。**这条一破，[Generation.md](Generation.md) 的全部论证作废**（D54）。

## 3. 职责划分

| | director | writer |
|---|---|---|
| 形态 | tool loop | 单次调用 |
| state | **默认包（值）** + 点查工具 | **完全没有** |
| 历史 | 细纲历史 | 正文上文（衔接用） |
| 世界设定 | ✓ | ✗ |
| 文风 / 角色语言习惯 | ✗ | ✓ |
| 否定项 | ✓ | ✓ |
| 写 state | ✓ **唯一写者** | ✗ |
| `ask_question` | ✓ | ✗ |
| 产出 | 细纲 | 正文 + 偏离报告 |

**writer 不添细节。** 细节的责任在 director——细纲是"无文风约束的文章"（D34），实体细节本就该在里面；细纲没写的，否定项中"不允许发明"已覆盖（D35）。

这强化了细纲的粒度下限 = **映射无歧义** 且 **包含全部实体细节**，两个要求指向同一个下限。

## 4. 一个 run 的时序

```
1. 编排：取队列头一条输入（FIFO，不打包，D26）
2. 编排：按能力开关组装工具面（关闭的能力其工具不注册）
3. 编排：装配 director 上下文
     细纲历史 + 世界设定 + state 默认包 + 用户指令
     + 元指令 + 控制维度 + 否定项
4. director tool loop
     → 细纲（唯一终止点是 submit_outline）
5. 编排：装配 writer 上下文
     细纲 + 正文上文 + 文风 + 角色语言习惯 + 否定项
6. writer → 正文 + 偏离报告
7. 代码：契约完整性校验（E0：state 增量已提交）
8. 代码：eval 采样标记 → 只提示，不拦截
9. 代码：commit 暂存增量、落节点、落 trace（仅开发者模式）
10. 编排：有 goal 则 run 末判定 → 未达标开下一 run
```

每 run 两次主调用（director 的 tool 往返另计），落在 P15 所说 3–10x 区间的下沿。

## 5. state 写入：director 单点，run 内暂存，run 末原子提交

**由 director 通过工具写入，不是 writer**（D55）：

- director 有完整的 state 上下文（默认包 + 点查），知道该记什么、往哪个键写、是否重复；writer 只做渲染，没有新事实可提交。
- **写入单线程（P5）因此更干净：只有 director 写。**

`state_write` 可在 loop 中多次调用，写入进 run 内暂存区，**run 完整结束时一并 commit**（D56）——否则 director 先写、writer 后跑，中途失败会造成"增量已落盘但正文不存在"。

`submit_outline` 只做终止与交付，不兼管状态提交。契约（E0）是：调用它之前必须至少调用过一次 `state_write`，**空增量合法**——强制这一次是为了区分「确实没变化」与「模型忘了提交」。

**state 能力关闭时该契约随之失效**（D80）：没有 `state_write` 可调，就不能要求它。

## 6. 偏离报告

writer 若为通顺而增删了实质内容，输出**偏离报告**（通常为空，D57）。编排层将其附在节点上，下一 run 的 director 读细纲历史时可见。

「细纲更新为实际发生的」由此落地：责任是 **writer 报告、编排层记录**，而非 writer 改写细纲。writer 保持纯粹。

## 7. 打断的分阶段处理

| 阶段 | 处理 |
|---|---|
| director 阶段 | 丢弃，暂存区一并作废。细纲未成型，损失小 |
| writer 阶段 | **保留已生成的正文片段**，state 增量照常提交，节点标记为 `partial` |

writer 阶段保留而非丢弃，因为那片段是有效内容——"话说了一半被打断"在 RP 里是真实感的来源，不是需要清理的垃圾（D60）。

## 8. 归因五类

| 归因 | 症状 | 修法 |
|---|---|---|
| director 检索不足 | 细纲与 state 矛盾 | 改默认包覆盖 / 键名 |
| director 推演错 | 细纲与用户指令不符（漏转述、覆盖不全） | 改 director 契约 |
| writer 偏离细纲 | 正文与细纲不符 | 改 writer 契约 / 细纲粒度 |
| writer 文风失败 | 符合细纲但读起来不对 | 改文风约束 |
| 写入遗漏 | 增量与正文不符 | 改写入契约 |

五类**都能从 trace 直接判定**，因为每一步的输入输出都物化了，且细纲是散文、可直接与正文比对。

**归因的可行性正是 director/writer 拆分的副产品**——合并方案下无法区分"规划错了"与"执行错了"。

## 9. 职责覆盖表

一份"这件事必须有人做"的清单，用于检查没有工作掉在地上。每项标注归属。

| 工作 | 归属 |
|---|---|
| 确定本轮的控制维度取值 | 用户显式设置，编排层读取 |
| 分离元操作与内容输入 | 编排层 / 协议 |
| 停下来给选项、等待用户选择 | director（`ask_question`） |
| 把输入补全成细纲 | director |
| 无用户输入时自产细纲 | director（goal 驱动） |
| 长任务终止判定 | 独立窄调用（goal 判定） |
| state 写入 | director，唯一写者 |
| state 检索 · 默认包 | 编排层无条件注入 |
| state 检索 · 点查 | director（`state_query`） |
| 语义判断（伏笔是否兑现等） | director |
| 按文风改写为正文 | writer |
| 报告实质偏离 | writer |
| 内容的提交与呈现 | 编排层 |
| 契约完整性校验 | 代码 |
| eval 采样标记 | 代码 |
| trace 采集 | 编排层（开发者模式） |
| trace → UI 投影 | UI 层，从 trace 事件派生 |
| 回滚与分支 | 编排层 + 存储 |
| 排队与打断 | SessionRunner |
| 成本可见性 | 实时推送，用户手动打断 |

**代码不做的**：任何需要理解内容含义的判断。结构性交叉比对经落地确认在本项目里不成立，已取消——详见 [State.md](State.md)。
