# 术语

> 术语混用是设计漂移最常见的入口。这里的每一条都对应一次实际的澄清，不是词典条目。

## 时间轴上的单位

**run = node = 一份细纲 = 一份正文**，四者严格一一对应（D51）。

| 词 | 含义 |
|---|---|
| **run** | 一次完整生成：从取用户输入到提交正文 |
| **node** | 分支树上的一个节点。内容包括正文、细纲、state 增量、偏离报告 |

**不使用 "beat"。** 它曾同时指"一轮生成"和"剧情节拍"，是歧义来源。

注意与 TauriTavern 的 `run` 区分：那里一个 run 是 request-scoped 的一次生成，与分支无关；这里 run 就是节点。

## 三种数据，按「谁改变它」区分（D61）

| 词 | 内容 | 由谁改变 |
|---|---|---|
| **state** | 结构化的世界当前状态 | **剧情推进**（state_manager 每 run 末提交增量，D143） |
| **worldinfo** | 静态设定：角色卡、世界观、背景 | **用户**（元操作「改设定」） |
| **history** | 过往 run 的细纲 | 每 run 追加，只增不改 |

**state 与 history 不是并列的两份记录。** 信息本体在 history；**state 是它的一条捷径**（D99）——把每轮都要用、又不该每次回头翻的那几条拎到眼前。因此 state 里删掉一个键不等于丢了那件事，它仍在 history 里。

**`ledger`、`账本`、`后台数据` 三词已废弃。** 前者来自另一个项目且暗示会计语义；后两者含混——worldinfo 也在"后台"。

灰区：同一实体可以两边都有——「他们是兄妹」属 worldinfo，「他们现在决裂了」属 state。

## worldbook：session 的起点（D90）

**用一份 worldbook 开启一个 session。** worldbook 是用户编写和维护的那份东西，
上表里的 worldinfo 和 state 都是它的投影：

| | 来自 worldbook 的 | 之后由谁改 |
|---|---|---|
| **worldinfo** | 条目正文（`content`） | 用户 |
| **初始 state** | 条目的种子（`seeds`），session 开始时迁入 | 剧情推进 |

一个条目通常两边都出：角色卡的性格、背景留在 content，「他现在在哪」「他知道什么」
「他和谁什么关系」作为 seeds 进 state。

**为什么要有 seeds：** 不迁移的话，「陈屿在场」这类事实只存在于 worldinfo 文本里，
而 director 需要它是可写的——于是它会把设定抄进 state，抄出一份会分叉的副本。
seeds 把这个动机拿掉了。附带的好处是 seeds 成为**命名锚点**：模型看见已有的
`时间`、`林昭.知情`，就会去改这些键，而不是自己发明一套写法。

初始 state 是 **session 级**的，不属于任何路径——改 seeds 会影响所有分支，
和改角色卡的效果一致。

## 四个 agent

| 词 | 职责 | 关键约束 |
|---|---|---|
| **director** | 主 agent，tool loop。推演，产出**无文风约束的文章**（细纲） | **从不读正文** |
| **writer** | 纯渲染，单次调用。把细纲按文风改写成正文 | 不增删实质内容 |
| **state_manager** | tool loop，run 末。读本轮细纲 + 正文，写状态增量 | **state 的唯一写者**（D143） |
| **goal_manager** | tool loop，跨 run 的长对话。替用户写输入、核对进度、判目标去向 | 只在有 goal 时存在；终态只有 `done` / `failed`（D148） |

**前两个是必然存在的，后两个各自可关**：`state` 关掉则 state_manager 不跑，没有 goal 则 goal_manager 不出场。

**细纲不是大纲。** 它是一篇完整文章，写清事件、对白、实体细节——只是不受文风约束。writer 不会补充任何东西，凡细纲里没有的就不会出现在成品里。

**「goal 判定」这个叫法已废弃。** 它曾是 run 末一次输出 yes/no 的窄调用；现在是 `goal_manager`，一份长对话 + 四个工具（D148）。叫「管理者」而不是「判定者」，因为判定只是它几件事里的一件。

## 四类配置（D38 / D78）

| 词 | 改变什么 | 何时设 |
|---|---|---|
| **元指令** | **目标**——这个 session 要什么体验 | 创建时 |
| **控制维度** | **处理方式**——每轮怎么处理 | 会话内可调 |
| **模式** | **触发源**——谁触发生成 | 开关 |
| **能力开关** | **系统能做什么**——哪些工具存在 | session 级 |

`goal` 属**元指令**，不是模式——有无 goal 系统跑法一样，只是 run 末多一个判定。

## 其他

| 词 | 含义 |
|---|---|
| **state 增量（delta）** | 一个 run 的状态变化。**权威数据**——当前状态是沿路径重放增量的结果 |
| **默认包** | 无条件注入 director 上下文的那部分 state（全量键名 + 体量小的值） |
| **偏离报告** | writer 若增删了实质内容时的报告，通常为空 |
| **trace** | 完整可回放的执行记录。**开发者模式**，默认关闭 |
| **采样标记** | eval 用的可疑样本提示。**从不影响运行时行为** |
