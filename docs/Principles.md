# 方法与判据

> **从 [req](req/) 推出 [spec](spec/) 时用的工具箱。** 每条编号 `P<n>`，编号永不复用。
>
> 判据与具体设计分开：**设计会变，这些不太会**。一条判据的检验标准是——
> **删掉任何一个模块它仍然成立**。
>
> 来源：Anthropic 关于多 agent 系统的三篇、Cognition 的两篇、Microsoft Magentic-One、
> Chroma Context Rot，以及本项目落地过程中的修正。文末有清单。

## 1. 拆分

**P1. 上下文隔离是拆分的唯一不可替代收益。** 并行、专精都是次要收益，或可用工程手段替代。

**P2. 按跨边界信息带宽决定分解，不按工种。**

| 入参需要的上下文 | 返回的内容量 | 结论 |
|---|---|---|
| 少 | 少 | 纯工具化，无所谓 |
| 少 | 多 | 拆分的甜点区（检索类） |
| 多 | 少 | 不要拆，压缩本身就是主要失败源 |
| 多 | 多 | 切口错了，重新分解 |

一条修正：「多入少出 → 不要拆」劝退的是**无验证器的有损压缩**；可核查的压缩
（如事实提取）不适用。

**P3. 操作方法：先枚举全部 context，再看某种切法下两侧是否有实质差异。**
不问"该不该有某个 agent"。

**同一组工作在不同切法下结论可以相反**——见 [spec/Generation.md](spec/Generation.md)：
共享同一份权威正文不等于共享全部 context；director 另读世界、状态与工具，writer 另读
文风与角色语言习惯，细纲只作为当前 turn 的交接边界。
**没找到可分的切法，不等于不可分；换一刀可能就分开了。**

**P4. 区分一次性上下文与跨轮存活的上下文。** 同一份检索噪音，
在一次性组件上是租用，在长期存活的组件上是买断。

**P5. 写入保持单线程。** 这是一条约束，不是拓扑决策——变的可以是"谁是那个单点"。

**P6. 反模式：按角色切分**（planner / implementer / tester / reviewer）。
实验中子 agent 花在协调上的 token 多于实际工作；"同一项工作的顺序阶段"是有问题的边界。

**P7. 无验证器的交接是预算重点。** 事实类交接可核查、漂移风险低；
品味类交接错了不报警，只产出"看起来合理但不是要的东西"。

判据：一个人类主编递出这份 brief 后就走人，写手不需要追问 → 无损；
写手必然回头问"你到底想要什么感觉" → 正在有损压缩品味。

**P8. 控制流与负载分布是两根轴。** tool call（控制权不转移）vs handoff（单向移交）
是一根；主 agent 干活 vs 子 agent 干重活是另一根。
**让子 agent 承担重任务不需要放弃 tool 语义。**

若要引入 orchestrator，其决策输入必须是**控制平面状态**而非正文，否则必然在
"信息不足→决策差"和"信息充足→退化为单 agent"之间二选一。但优先级不高：
若"灵活性"仅指顺序偶尔变化，带跳转的状态机更便宜、可调试、可复现。
orchestrator 只在需要**基于运行时结果推翻计划**时才值得。

## 2. 交给谁：模型还是代码

**P9. 能在生成前问清楚的，就不必在生成后审查。**

**P10. 凡是模型的开放判断，都降级成受约束的选择。** 目的是降低对模型能力与提示词的
敏感度——开放集上的判断质量与模型能力强相关，闭集上的选择则不然。

已多次应用：不推断用户意图而用显式设置、不自由定义 schema 而是选模板或写键值、
不自由判断该不该停下来问而由控制权等级给定频率、输入处理收敛为三档互斥选择。

**P11. 审查类工作的增益 = 上下文差 × 验证器，两项相乘，缺一归零。**

- 上下文差为零 → 无增益。
- 无验证器 → 上下文差再大也无增益；此时审查意见只是第二种品味，改完趋向均值。
- 上游的上下文隔离未必消除上下文差：按"约束类型"切分与按"是否可核查"切分是
  **不同的轴**。
- **把语义判断存成结构化字段再用代码读取，不构成验证器**——字段的值本就是模型写的。
  语义判断发生在**写入时**，代码检查发生在**读取时**，后者只是一次查表。

**P12. 修复成本决定能否自动强制。** 补交状态增量成本≈0，可自动强制；
重生成正文成本高，只能提示、由用户决定。

代码检查的主要价值在**开发期调试与 eval 采样**，不在运行时拦截：
**正则不是判断器，是采样器**——把可疑样本挑出来定向送审，让覆盖率不必靠盲抽。

**P13. 规则可以做无损降维，不能做有损筛选。** 分界线是**模型是否知道自己缺了什么**。

| | 合格 | 不合格 |
|---|---|---|
| 规则做什么 | 覆盖**全集**，只调节精度 | 筛选**子集**，猜相关性 |
| 失败模式 | 信息不够细 | 信息完全缺失 |
| 模型知情 | ✓ 摘要在眼前 | ✗ 不知道存在 |
| 可自愈 | ✓ 点查补救 | ✗ |

**P14. 不预设维度，也不预设能力。** 时间、地点、角色属性的粒度与形态都取决于故事，
加字段只是把猜测挪深一层。同理，不同故事需要的**能力**也不一样——
关闭的能力其工具不注册。

## 3. 成本与边界

**P15. 多 agent 通常比等价单 agent 多耗 3–10 倍 token**（重编排的 research 类可达 15 倍）。

**P16. 每个子调用设 token 预算上限**，保证可幂等重启。

**P17. 禁止子 agent 自行再生成子 agent**——在编排层强制，不要靠提示词恳求。

## 4. 验证方法

**P18. 先做诊断，再改结构。** 把违规按归因分类统计，各类修法完全不同，
而最贵的那一类最容易被误判成下游的问题。**归因六类**见
[spec/Architecture.md](spec/Architecture.md) S12。

**P19. 消融验证。** 同一批素材跑多个配置，最少三档：单 agent 全揽 /
writer + 工具（细纲用人写的）/ 完整拓扑。

指标分两类：**事实与逻辑错误率**（工具层的存在理由）与**"是否写出了要的东西"**
（拆分的存在理由）。后者在交互式产品里有免费的行为代理——重 roll 率、打断率、
戏外引导频率。

三种 grader 按**有没有参照物**分工，恰好对应归因分类：五类有参照物 → AI 可判；
**"writer 文风失败"无参照物 → 只能人看**，而这一类恰好最主观、也最影响体验。

**AI grader 的信号是复现率，不是单次判定**：同一批素材连判多次，跨次稳定复现的才计入。
**误报不需要被消灭，只需要被过滤**——而随机性恰恰是这个过滤器赖以工作的东西，
不该被消除。AI grader 还需要人**定期校准**：不校准会悄悄漂移，
而它的错误直接误导后续所有决策。

**program grader 的准入**：只有当「违反 = 流程坏了」而非「违反 = 写得不好」时才能用。
可做的只有契约形状、可数的量、字符串存在性。

**不加内容层面的硬约束。** 除假警报外还有更隐蔽的伤害：
**模型会为了满足检查器而牺牲质量**（灌水凑字数、硬塞模板）——
那不是误报，是主动的质量损失，**且检查器永远不会告警**。

**回归集只保流程，不保质量**——创作输出不确定，
拿某一次生成当标准答案等于把噪声钉死。

**行为代理从第一版就采集**：重 roll 率、打断率、戏外引导频率、会话时长。
零标注成本，且是"文风失败"那一类唯一可规模化的信号。

**P20. 干净上下文的验证调用。** 需要判定时开新上下文，只给 [标准 + 待判对象]，
不给创作过程——**生成模型知道自己想怎么写，会往"已经达标"的方向读**。

**但这一半在 goal 上没能守住。** 判定与重拆计划是同一次判断的两面，而重拆随时可能
发生，于是它从窄调用长成了一份跨生命周期的长对话（见 [spec/Goal.md](spec/Goal.md)）。
保住的是"不读创作过程"。**代价是实测可见的**：模型读的是自己写的计划、自己判的进度，
**比干净上下文更容易往"已经达标"的方向读**——实测里它两次把一个逻辑上不可达的目标
判成达成。**防过早宣告胜利在长对话形态下更难，不是更容易。**

## 5. 什么该做，什么不该做

**P21. 不为保住某个交付特性而扭曲 agent 结构。**

流式是这条的来源：不为保住逐 token 流式而改结构。
**但把它当输出通道加回来不动任何结构**——顺序、工具循环、契约、重放全都不变。
两件事要分清：**为它改结构**不行，**在它旁边开一条旁路**可以。

**P22. 必做与 optional 的判别式：这项工作解决的是物理限制还是模型能力不足。**

长程一致性解决的是**上下文窗口的物理限制**——再强的模型也无法在几百轮之后记住早期
细节，**收益不随模型变强而消失**。多 agent 角色化、规则化解决的是**模型推理能力不足**，
**收益随模型变强而递减**。

前者进默认路径，后者归 [Ideas.md](Ideas.md)。

**P23. 代码不做任何需要理解内容含义的判断。**

结构性交叉比对落地时确认全都做不了：时间是自然语言、说话者需语义抽取、
地点无拓扑图；连"知情者 ⊆ 在场"也不成立（信息可经转述获得）。

**硬做只会得到假警报，而假警报比不检查更糟**——它会让人不再信任系统。

**P24. 检索价值与交叉比对价值必须分开评估。**

结构化对所有维度都有**检索**收益；代码**校验**只对有结构性约束的维度成立。
**混为一谈会误判**——会因为"结构化有用"而以为校验也跟着有用。

**P25. 同一段判据抄两份，就只会修好一份。**

实测过一次：循环里的催促词无条件地说"先做 A 再做 B"，模型已经做过 A 了还被催，
于是空转 12 个来回、烧掉整场 84% 的输入 token。而另一处同样的判断一直是对的
——**同一段逻辑抄了两份，只修好了一份**。

修法不是补第二份，是**合成一个**。**重复本身就是成因。**

工具描述与提示词之间同理：两份必然对不上，**而对不上的时候没人知道该信哪份**。

## 6. 怎么知道一次改动有没有效

**P26. 统计只能证伪，不能证明"没差别"。**

把一段占全文一半的提示词换成两句话，**17 项文风指标、10 项八股密度全部没有差别**
——按统计该删。**但读出来完全不同**：收束版 5/10 以同一个定式收尾，完整版 0/30。
**没有任何一项指标看得出 0/30 vs 5/10。**

推论：指标覆盖不到的维度上，**「没差别」的真实含义是「没测到」**；
精简提示词前必须**读**；**已经治好的毛病要留针对性回归探针**，
否则下一次精简会把它放回来，**而所有仪表盘都是绿的**。

还有一层：**凡是「同一个形式，好坏取决于它落在哪」的东西，字符层面的指标永远判不了。**
短句用在重点上和满篇切碎，在字符层面完全一样。

**P27. 第一步永远是量方差，不是改东西。**

同一份输入什么都不改连跑五次，指标自己就在大幅跳动（实测破折号跑遍 2.08–9.03‰，
极差是均值的 79–107%）。**跨轮报过的"效果"全部落在这条带子里。**

三步，顺序不能换：量方差 → 只看零方差的偏离或效应明显大于方差的 →
一次只动一处，**比分布而不是比单值**。

第一步排在第三步前面，因为**动一处之后你仍然读不出效果，如果不知道噪声有多大。**

由此得到一条判据：**会跳动的低值，和从不出现的零，是两件事。**
前者是这次少了；**后者是模型根本不产出这个东西，那才是系统性的。**

**P28. 单变量才叫对照。**

两条实测教训：调 writer 时**必须固定细纲**——重跑整条链会把细纲一起重新生成，
于是比较的是"不同提示词 + 不同细纲"，两侧的变化混在一起。**上文也必须固定**，
否则第 n 轮的输入会随第 n−1 轮的重写而变，**固定了细纲却没固定上文等于没固定**。

另一条更隐蔽：替换标点时"顺手"把另一句话改得更准确了，于是那一片的变化归不了因。
**改提示词时"顺手把话说得更好"就是在偷偷加变量。**

**P29. 没生效的参数不会报错，只会让你把它写进结论。**

思考模式默认开启时采样参数被**静默忽略**——不报错，就是不生效。
两处设了温度为 0，**一直没生效**，而基于它写下的结论跟着错了一条。

**这个坑踩过两次。** 第二次是在专门为此设计的实验里：用了一个文档里根本不存在的
字段名，服务端静默忽略，于是"这个参数不影响缓存"的结论进了回复。

推论：**验证一个参数有没有作用，必须先确认它的名字对得上文档，而不是只看行为有没有变。**
行为没变有两种原因——**参数无效，和参数没被认——它们看起来一模一样。**

## 7. 提示词怎么写

**P30. 列举里排第一的那个会变成默认选项。**

例子本身就是一条定式。实测：两串例子都把同一类东西排在第一个，
**9/10 轮的产出收在那个形状上**，模型自己在产出里写"第二次""第三次"
——**它知道在重复，仍然照做。**

删掉之后**不要另找一串例子替换**，换一串只会换一个定式。

判据：**先分清定式来自提示词还是模型原生，来自提示词就删，原生就别管。**

**P31. 各条的「分量」决定行为，不是措辞。**

一节开头写着"大胆写内心"，后面接了六段讲别的——产出里内心戏**完全消失**。
**模型按比重执行。** 只调顺序与篇幅、一个字不改措辞，行为就变了。

连带：从别处抄条款时要注意**它们各属于不同的单一风格，是「选一」的关系**——
叠在一起用会互相压。

**P32. 提示词自检三条。**

1. **约束对象错位是最严重的一类。** 判据：**如果一条规则禁止的是"模型不会犯的错"，
   它就是在白占体量。** 要问的是"这个维度上什么算过、什么算不足"。
2. **虚词与程度副词一律删。** 它们不增加信息，只把句子变软——
   **而提示词的每一个字都在竞争注意力。**
3. **指代必须明确。** 这类歧义人读时靠上下文自动消解，**模型没有那个默认。**

**P33. 提示词里没有的东西，清洗提示词补不出来。**

叹号与省略号在提示词里本来就是 0，改动后产出里仍然是 0.00，而参考文本是 3.84 / 6.22。
**"缺席的缺席"要靠别的手段**，动提示词的 register 够不着它。

反向的镜像效应（提示词里多、产出里也多，清洗后降下来）**曾被写下，已撤回**
——放回抖动带里看多半只是噪声。**零方差的零才是信号。**

## 8. 两条关于"看起来没问题"

**P34. 静默的降级比缺失更糟——读的人不知道拿到的是次品。**

三处同源：截断只加一个省略号（说不清丢了多少）、预算耗尽时几条结果**无声消失**、
正文没写成时**回退到一份更粗的记录**（读的人会照着它判某件事已经成立）。

**真截断必须出声，隐藏不算截断**——分界是「展开的路还在不在」。

**P35. 一个决定的理由是对的，但它要解决的问题可能不存在。**

曾把工具清单做成一条消息，理由是"让『有哪些工具』在顺序里看得见、位置可编排"。
**那条理由建立在一个错误前提上**：工具根本不在消息列表里，它走请求的另一个字段，
模型本来就看得见。于是那一节是同一份清单发了两遍。

**这类错误的形状值得单独记**：理由本身经得起推敲，所以复查时很难发现——
要问的是**"它要解决的那个问题，真的存在吗"**。

**P36. 索引是源的缓存，不是归档。源没了，缓存就该跟着没。**

一份派生数据的寿命**不该超过它派生自的东西**。资料的源文件被删掉之后，
那份索引不能继续被检索到——它此刻代表的是一份用户已经决定不要的东西。

**判据是"谁是真相"**：能从源重建的就是缓存（块表、两路索引、摘要、
解析出来的文本），删了只是要重算；不能重建的才是数据（用户写的字、
已经发生过的剧情）。**缓存可以随时丢，数据不能。**

这条容易和"快照"搞混，而两者的目的完全不同：**快照是一致性装置，不是归档**。
检索报的位置要指得准，所以要冻一份文本；但那不给它活得比源更久的资格。

**反面的诱惑很具体**：留着它"万一用户后悔了呢"。那是在替用户保存一份他
已经删掉的东西，而他下一次检索到它时不会想起自己删过——**只会以为这个系统
在拿旧资料骗他**。
