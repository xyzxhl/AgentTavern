## 全貌

**session 上只剩内容，没有配置。**

| 装什么 | |
|---|---|
| `worldbook_id` | 指向一份设定，**不内嵌拷贝** |
| 标题 | |
| 目标 | 没有就是普通会话 |
| 节点树 | 一个 run 一个节点 |
| 冻结的初始状态 | 第一轮时快照 |
| 触发源 | 「这局故事没人说话时要不要自己往前跑」 |

控制维度与能力开关**都不在这里**——它们住在提示词层。

### S119 · 两个上下文窗口分开，交给用户调

**服务** [R14](../req/推进剧情.md)

**规格** 两个默认值都是 3：

| | 谁用 | 少一轮会怎样 |
|---|---|---|
| **正文上文轮数** | writer | 语气接得生硬 |
| **状态示范轮数** | state_manager | **键名一致性直接受影响** |

**不做** 合成一个参数。

**为什么** 两者要的东西不同：writer 要的是**语气的连续**，
state_manager 要的是**记法的示范**。**合成一个会让其中一侧被另一侧的理由绑架。**

实测 state_manager 取 3 时占掉全场 42% 的输入 token——**这个数值得每个故事自己定**。

**验收** `test_state_pack_inlines_small_values_and_defers_large_ones`

### S120 · 「用户扮演谁」是故事的设定，视角是读者的偏好

**服务** [R3](../req/开局与设定.md) [R14](../req/推进剧情.md)

**规格** 判据是**「换个人来读还成不成立」**：

| | 归哪 |
|---|---|
| 视角（第一 / 第二 / 第三人称） | 读者偏好 → 控制维度 |
| 用户扮演谁 | 这个故事的设定 → 设定库的角色条目 |

**不做** 把视角写成自由文本。

**为什么** 自由文本时它散在每个 session 里，改一次只影响一个故事，
**而且从提示词那侧完全看不见**。

**验收** `test_voices_have_exactly_one_source` · `test_it_is_told_who_the_user_plays`

### S121 · 触发源留在 session

**服务** —（这是配置上调时唯一的例外）

**规格** 「这局故事没人说话时要不要自己往前跑」留在 session 上。

**为什么** 它问的是**这局故事**的事，和目标的自动续跑是同一类东西——
两者回答的都是"这局故事怎么自己往前走"。

这一条**推翻了配置上调初稿里把它归服务的判断**：它不是"这台服务怎么配"，
是"这个故事怎么跑"。

### S158 · 服务端在 run 之外改了 session，就得推回去

**服务** —（可用性底线，同 [S135](UI.md#s135)）

**规格** 凡是在一轮生成之外改动 session 的入口——切分支、设目标、改预算、
暂停 / 恢复 / 放弃——**改完就广播整份 session**（`session_updated`）。

**推整份，不推差异**：session 不大，而"哪几个字段变了"是个每加一个字段就要
重想一次的问题，漏掉一个的症状是界面显示旧的东西。

**不做** 让客户端在发完消息之后自己拉一次。

**为什么** 没有它的时候，凡是**不触发一轮生成**的改动客户端一律不知道：
按「暂停」目标真的暂停了，而按钮还写着「暂停」；按「放弃」目标真的没了，
而面板照旧挂着；「加预算」改完要等下一条进度才看得见。
**服务端每一次都做对了事，界面一动不动**——用户读到的是"这几个按钮坏了"。

它一直没被发现，是因为**设目标那一条顺带 `nudge()` 起了一轮**：正文开始动，
看起来像是有反应。**一个 bug 被另一条路径的副作用盖住了。**

客户端不自己去拉，是因为 WebSocket 发出去和 HTTP GET 之间没有先后保证——
那一拉可能落在服务端写盘之前，拿回旧的那份，而症状和现在一模一样。

这是 [S135](UI.md#s135) 的第三次：**一个不出声的成功和失败没有区别。**

**验收** `test_changing_the_session_outside_a_run_is_pushed_back`
