# 界面

> **回答**：界面上有哪些东西、摆在哪、为什么是那个形态。
>
> **不回答**：后端行为（各篇 spec）、还没做的界面（见 [TODO.md](../TODO.md)）。

## 全貌

界面是 **trace 与节点树的投影**。

一条判据管着整份布局：**一件事一个入口。** 第二个入口迟早会显示旧的东西。

```
左栏  上：独立页面（agent 提示词、单次调用、设定库、资料库、全局设置）
      下：会话记录
主区  会话：一个 turn = 过程 → 正文 → 写完之后
      或某个独立页面
```

### S123 · 左栏不做 tab 切换

**服务** [R2](../req/开局与设定.md)

**规格** 上面是独立页面的入口，下面是会话记录，**同时可见**。

**不做** 用 tab 在「会话」与「设定」之间切。

**为什么** tab 会让会话列表在看设定时消失，**而设定不是故事的互斥模式，

### S125 · 一轮渲染两块过程，中间夹着正文

**服务** [R39](../req/开发者视角.md)

**规格** 显示顺序必须和运行顺序一致：推演 → 成文 → 状态维护 → 目标判定。
所以**跑在正文之后的东西，显示在正文下方**。

切点是**位置**不是来源：writer 最后一条之后就是下半。
下面那块叫**「写完之后」**而不是「过程（续）」。

进度指示跟着当前阶段走：下面那块一有动静，上面那块就不再显示为「跑着」。

**不做** 按 agent 名字认上下半。

**为什么** 把状态维护和目标判定塞进正文上方，**等于让时间线在正文这里倒着走一段**
——读到「状态已更新」时正文还没出现，而它读的正是那份正文。

名字要**说清它是什么时候发生的**，那正是分成两块要传达的东西。

按来源认会在**目标开场**时翻车：那时 goal_manager 跑在 director **之前**，
照来源认会被扔到正文下面去，**时间线正好反了**。

**验收** —（前端行为，缺，见 [TODO.md](../TODO.md)）

### S126 · 过程按 agent 分段，思考与内容各有各的开关

**服务** [R38](../req/开发者视角.md) [R39](../req/开发者视角.md)

**规格** 一轮里最多四个 agent 说过话，**按 agent 分段**。
每段自己折叠；正常故事界面只在当前 turn 运行时展示这些段落（那时它们也是进度条）。
turn 结束后不把 thinking 或工具过程挂在历史节点上；需要跨 turn 排查时走开发者 trace。

思考段和内容**各有各的开关**。

**每一段思考都长一个样**：折叠按钮 +「谁的思考 · N 字 · Ns」。
用时是**这一段自己的**（第一个分片到最后一个分片），**跑着的时候每秒往前走**。

**不做** 把一轮的过程拼成一坨；不做思考与内容共用一个开关；
**不做**按长短给两种形态。

**为什么** 拼成一坨就分不出哪句是谁的，**而「是谁在想这件事」是查问题时的第一个问题**。

思考段动辄上万字（实测 director 一轮两万多个分片），**合用一个开关时它会把内容整个
挤出视野**。而这两样本来就是两次不同的排查——查「它写了什么」和查「它为什么这么写」，
一次只想看一个。

**不按长短分两种形态**：那一行以前只在超过 300 字时才出现（它是折叠按钮），
于是短思考连标题都没有，字数和用时无处可放——**而"它想了多久"恰恰是短思考也想
知道的**。同一种东西不该有时候有标题有时候没有。

**用时每秒跳**是因为它在跑的时候是进度指示的一部分：一个跑完才出现的总数，
恰恰错过了最想看它的那段时间。它量的是**到达浏览器的时间**（分片不带时间戳，
trace 那份要等落盘），只用来显示、不参与任何判断，那点网络误差不值得为它
再铺一路时间戳。

**验收** `test_the_agents_after_the_writer_stream_too`

### S127 · turn 结束时清掉正常界面的全部执行过程

**服务** [R39](../req/开发者视角.md)

**规格** 节点里的正文是完成后的权威版本；流式正文、thinking、工具过程和普通 trace 投影
都只属于当前 turn。服务端在 goal_manager 完成、暂停或失败处理结束后才发 `run_finished`，
客户端收到后整体清除该 run 的执行态。开发者模式按 run 落盘的 trace 独立保留并可读回。

**为什么** thinking 与工具过程不是故事历史，也不应在正常 UI 跨 turn 堆积。此前
`run_finished` 发在 goal_manager 之前，迫使客户端保留过程；正确修复是把生命周期终点
移到 goal 判定之后，而不是把执行流量长期挂在节点旁。

**验收** `test_the_agents_after_the_writer_stream_too` · `test_the_final_node_is_still_the_authority`

### S128 · 跑着的目标进输入框上方

**服务** [R26](../req/长任务.md)

**规格** 条上只回答三件事：**在推什么、推到哪儿、怎么叫停**。细节归侧栏那一页。

**不做** 只放在侧栏标签后面。

**为什么** 目标**会自己开下一轮**，这件事必须一直看得见——
只放侧栏的话，用户切到状态页就再也不知道那边还在动，
**而「下一轮什么时候开、还剩几轮预算」恰恰是他决定「要不要现在插一句」时唯一需要的
信息**。

**验收** —（前端行为，缺，见 [TODO.md](../TODO.md)）

### S129 · 目标进度每轮推，不是只在结束时说一声

**服务** [R27](../req/长任务.md)

**规格** 推送内容：中间状态（带成立与否）、花掉的轮数与 token、两条预算上限。

**不推整份 goal 产品记录或当前 turn 的执行流量**——界面只需要计划、进度和预算，
其余一个字都用不上。

面板摆在**侧栏而不是弹窗**。

**为什么** 此前只有「结束」和「暂停」两条消息，**于是目标跑着的那几轮界面上什么都不会
变，直到它突然结束**——而中间状态被一条条划掉恰恰是用户最想看的东西。

弹窗要么挡着正文、要么关掉之后就再也不知道进度了。**目标跑的时候用户是在看不是在操作。**

**验收** `test_goal_messages_without_a_goal_say_so`

### S130 · 状态编辑是同一个编辑器的两个标签页

**服务** [R20](../req/回头与改写.md) [R21](../req/回头与改写.md)

**规格** 界面上**不是两个概念**。侧栏「改状态」只作用于当前活跃路径最后一个已完成
turn；更早的 turn 不提供状态编辑入口。只有在该 turn 完成后、下一条顶层 user input
提交前且没有执行中或挂起的 run 时，细纲、正文、状态的编辑入口才可用。

下一条顶层 input 成功提交时立即关闭入口，不等它出队。run 挂起时提示用户先恢复完成
或明确放弃，不自动替他删除草稿；放弃后是否可编辑仍由窗口是否已关闭决定。

**不做** 自动重算下游或替用户协调细纲、正文、状态之间的冲突。

**为什么** 直接编辑是一项局部覆盖。系统保证保存用户给的值，不承诺据此重新理解或
生成其它内容；冲突由用户负责。

**验收** `test_editing_state_reaches_append_and_remove` · `test_editing_the_result_is_diffed_back_into_a_delta`；编辑窗口的前端断言待补，见 [TODO](../TODO.md)。

### S131 · 在非当前轮上重生成要先问过

**服务** [R19](../req/回头与改写.md)

**规格** 界面自己走「先切、再重生成」两步，**但要先告诉用户后面几轮会移出当前路径**。

**为什么** 用户按的是「重写这一轮」，看到的却是后面几轮消失了。
**它们还在，切回来就是了——而那句话得说出来。**

**验收** `test_switching_back_to_a_regenerated_sibling_restores_its_state`

### S132 · 改完上一 turn 回传整份节点

**服务** [R20](../req/回头与改写.md) [R21](../req/回头与改写.md)

**规格** 编辑窗口内的上一 turn 修改落地后，服务端**回传整份节点**。

**不做** 让客户端把发出去的东西塞回本地。

**为什么** 改「结果」时落盘的增量是**服务端算的**——客户端塞回去的话那份增量就是旧的。
**回传整份是唯一不需要客户端猜的做法。**

**验收** `test_editing_the_result_is_diffed_back_into_a_delta`

### S133 · 界面外观归浏览器本地

**服务** —（这台机器上这个人的偏好）

**规格** 色彩模式、正文字体与字号落在浏览器本地存储，**和后端一个字节都不来往**。

**为什么** 它回答的是「**这台机器上的这个人**怎么看得舒服」——换个人来读答案就变了。
而 session 里存的是「这局故事是什么」。

落地上有一处值得记：**颜色改走 CSS 变量时，通道值要分开写**（`13 15 18` 而不是
`#0d0f12`）。整串变量会让透明度修饰符**静默失效**——失效的症状是
**颜色照样出得来，只是不透明了**，属于最难发现的那种坏法。

**验收** —（前端行为，缺，见 [TODO.md](../TODO.md)）

### S134 · 选取值只有一种交互形态

**服务** [R34](../req/调教提示词.md)

**规格** 一排按钮，选中的高亮。**二值也不例外**——「开关」就是在「是」和「否」之间
选一个。全界面所有选择走同一个控件。

**一个例外**：折叠标记是**披露控件**（点的是「给我看」，不是「设成这个值」），
保持自翻。

**不做** 多值用按钮组、二值用「点一下自己翻面」的 toggle。

**为什么** 那个区分是假的。代价有两层：**手上的**（同一个页面里有的地方点一下换值、
有的地方点哪个是哪个，用户得先分辨这是哪一种才敢点）和**眼睛上的**
（toggle 只显示当前值，**看不见「另一个选项是什么」**）。

「用户扮演的就是他」那处还多一层误导：**单按钮的形状暗示「可以多标几个」**，
而它其实至多一个。

散在各处各写一遍正是这次飘掉的原因——**现在只有一处定义**。

**验收** —（前端行为，缺，见 [TODO.md](../TODO.md)）

### S135 · 前端的失败必须显示出来，光会抛不算

**服务** —（可用性底线）

**规格** 每个动作都包进统一的错误处理，**出错就显示在页头**。
接口响应要校验类型，**让失败抛得更早更响**。

**不做** 只有 `try/finally` 而没有人接。

**为什么** 这是同一条教训的第二遍。第一遍给响应解析加了类型校验让它抛得更早，
**但调用处仍然没有人接**——于是「新建成功 → 紧接着的列表刷新 500 → 异常静默消失 →
界面看起来什么都没发生」，而用户报的是「新建无效」，**离真正的原因隔着三层**。

> **一个只会抛不会显示的错误，和不报错没有区别。**

**验收** `test_a_stale_entry_does_not_take_the_whole_list_down`

### S167 · 整轮失败留在时间线上并可重试

**服务** [R52](../req/推进剧情.md)

**规格** `run_failed` 到达后清掉本轮流式片段与执行过程，但在正文流末尾保留原 user
input、失败原因与「重新生成」按钮。按钮从当前活跃叶重新提交同一输入；新 run 开始、
正常完成、切换分支或切换 session 时清掉这份临时记录。

自动 goal 开出的无 user input 失败不伪造重试文本，仍走目标暂停与页头通知。

**不做** 为失败 turn 创建节点，或把失败 run 的 thinking / 工具对话带进重试。

**为什么** 整轮失败按设计判定本次输入无效，但无效不等于界面上从未发生。原输入消失后，
用户既无法确认失败的是哪一轮，也没有自然的恢复入口。

**验收** —（前端行为，缺自动化，见 [TODO.md](../TODO.md)）

### S170 · 提示词编辑器先选完整套装，再选接收方

**服务** [R54](../req/调教提示词.md)

**规格** agent 与单次调用仍是两个并列入口，但两页顶部共用同一个当前套装选择。
套装名称在原位修改；「复制当前套装」直接生成并选中一个完整副本；自建套装可以删除，
默认套装不可删除。切换套装后，下面接收方列表与编辑器整体刷新到新套装。

**不做** 在每个 agent 旁各放一份套装选择；不把五个 YAML 平铺成「套装名 × 接收方」
的一长列；不使用浏览器命名弹窗。

**为什么** 套装是五份配置共同的上层地址，不是某一 agent 的字段。只在页面上加标签而
不改变文件结构，会让复制、删除、导出都仍需用户手工凑齐五份文件。

**验收** —（前端行为由 build/lint 覆盖，交互自动化待补，见 [TODO.md](../TODO.md)）

### S155 · 改名就地改，不用弹窗

**服务** —（统一交互规则）

**规格** 凡是「给这个东西起个名字」的地方，**点名字，名字当场变成输入框**。
回车或失焦提交，Esc 取消，**空白或没改动一律当取消**。全界面走同一个控件。

**没有例外。** 每样东西的名字都在它自己那一页的标题处改：设定在设定页顶栏、
会话在故事页顶栏、设定库的卡片在卡片标题上。

会话列表那一行**只负责打开**。它曾经在旁边挂一个 ✎（那一行的文字是打开动作，
点它改名会把主要动作顶掉），于是「怎么改名」在界面上有两种答案——而那正是这条
判据要消掉的东西。**列表里改不了名，得先打开它**，这是有意付的代价。

**不做** `prompt()` 弹窗；不做「一个改名按钮 + 一个弹窗」；不做列表里的行内改名。

**为什么** 同 [S134](#s134) 的判据，换一件事：**一件事只有一种交互形态。**
弹窗那一版还多两处坏：`prompt()` 是浏览器的东西，长得和整个界面不是一路；
而且它把「叫什么」从它所在的位置搬走了——改完要回到列表里才看得见结果。

**这条判据自己被违反过一次，值得记**：第一版把设定的三处都改了，会话却只改了
侧栏那个 ✎——因为当时搜「会话标题在哪儿显示」只搜到侧栏一处，**而它就在故事页
左上角，是整个界面最显眼的位置**。搜不到不等于没有（同 TODO 里那条自我提醒）。

**验收** —（前端行为，缺，见 [TODO.md](../TODO.md)）

### S156 · 接口声明的形状必须和它实际接受的一致

**服务** —（可用性底线，同 [S135](#s135)）

**规格** 每条路由的请求体都要在 OpenAPI 文档里**作为请求体**出得来。
`/openapi.json` 本身也是验收的一部分。

**为什么** 它住在这一篇是因为**症状全在界面上**。世界书改名坏了很久：请求体模型
定义在 `create_app` 函数体内，而那个文件有 `from __future__ import annotations`
——FastAPI 只能拿模块 globals 解析注解，局部名字不在里面，于是**不报错，
退而求其次把它当成查询参数**。用户看到的是「改名无效」，服务端说的是
「缺少查询参数 patch」，两句话对不上。

这是 S135 的同族：**一个不出声的降级和没坏没有区别**，直到有人去点它。
`app.openapi()` 是这一类的通用探测器——同一个解析失败会让**整份文档**抛错，
所以那一条测试同时钉住了 `/docs` 与 `/openapi.json`（它们坏了好几个提交都
没人发现，因为没有一条测试碰过）。

**验收** `test_every_route_declares_its_body`

## 一条立在这里的判据

界面第一版只覆盖了一条线——**输入 → 看正文 → 再输入**，
而系统本身是一棵可回头、可改写、可调参的树。重生成、切分支、改细纲正文状态、
手动断段**后端全部完成且有测试，界面上一个入口都没有**。

其中切分支缺失最重：设计是「创建受限、切换不受限」，
**它是回到历史分叉点的唯一路径**，没有它，重生成出来的兄弟节点永远回不去。

这是同一个失败模式的**第五次**。所以判据立在这里：

> **一条决策落地与否，看的是它从用户那一侧够不够得着，
> 不是模型和测试跑不跑得通。**
