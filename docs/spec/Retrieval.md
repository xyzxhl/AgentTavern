# 检索与历史

> **回答**：模型怎么找回不在眼前的东西——早前的剧情、按需展开的设定。
> 以及跨轮的上下文怎么攒、怎么压。
>
> **不回答**：状态自己的形状与判据（见 [State.md](State.md)）、
> 工具签名（见 [Tools.md](Tools.md)）。

## 全貌

三样东西必须区分，判别式是**谁改变它**：

| | 内容 | 由谁改变 |
|---|---|---|
| **state** | 世界的当前样子 | **剧情推进**（state_manager 每轮提交增量） |
| **worldinfo** | 静态设定：世界、角色 | **用户** |
| **history** | 过往每一轮的细纲 | 每轮追加，只增不改 |

灰区：同一个实体两边都能有——"他们是兄妹"属 worldinfo，"他们现在决裂了"属 state。

### 核心难点：信息需求在推演过程中才产生

**某个角色出场 → 需要他的信息；但"他出场"是 director 在推演中才决定的。**

代码无法预判，因为决定尚未做出。这使得预取在**实体级信息**上本质受限——
它只对体量小、恒定相关、可无条件注入的那几样成立。

**这个问题没有被解决，只是从代码手里交给了模型。**

### S52 · 规则可以做无损降维，不能做有损筛选

**服务** —（这是这一层的准入标准）

**规格** 智能检索与规则检索可以共存，**但规则的范围受限于"在所有情况下都不出错"**。

判据：**分界线是模型知不知道自己缺了什么。**

| | 合格 | 不合格 |
|---|---|---|
| 规则做什么 | 覆盖**全集**，只调节精度 | 筛选**子集**，猜相关性 |
| 失败模式 | 信息不够细 | 信息完全缺失 |
| 模型知情 | ✓ 摘要在眼前，知道可以展开 | ✗ 根本没意识到它存在 |
| 可自愈 | ✓ 点查补救 | ✗ |

**不做** 两样按这条判据出局的——

- **时间局部性预取**（"上一轮涉及的实体这一轮大概率仍相关"）：它在猜相关性，
  场景切换即带错人，而模型不知道有角色信息没被带进来。
- **关键词触发**：漏命中 → 条目完全缺失 → 模型不知道有这个设定存在。

**验收** `test_history_search_marks_hits_without_filtering` · `test_worldinfo_index_covers_everything`

### S53 · 全量索引 + 按需展开，索引必须带体量

**服务** [R5](../req/开局与设定.md)

**规格** worldinfo 与 history 用**同一个模式**，不是两套：

```
注入：全部条目的索引（标识 + 摘要 + 体量）+ 近期条目的全文
工具：按标识拉取正文，支持分页
```

索引**必须带体量**，让模型知道拉全文的代价。**索引必须带 ref**——
拿得到的标识，不是"第 N 轮"这种人话。

**不做** 只索引"已被激活的"条目。那底层仍是筛选子集。

**为什么** 索引不带 ref 曾经让整个历史检索层从未被调用：索引写的是「第 N 轮」，
而读取工具要的是 run id——**模型看得见索引，却拿它没办法**，必须先花一轮换 id。
对比之下 worldinfo 的索引一直带 ref，它的读取就一直被正常调用。**差别就在这一处。**

**验收** `test_worldinfo_index_covers_everything` · `test_always_worldinfo_is_injected_on_demand_is_indexed` · `test_history_read_expands_the_whole_segment`

### S54 · 搜索只标注不筛选，查不中也要说清

**服务** —（S52 的直接推论）

**规格** 历史索引**永远覆盖全部轮次**，命中的只多一个标记，
并在结果里明写"**没命中不等于没发生过**"。

**不做** 把 query 当子串过滤器返回命中的子集。

**为什么** 查不中就返回空列表，而模型会把"空"读成"没这回事"——
**这正是判关键词触发不合格的那条理由，我们自己却犯了同一个错。**
而且伏笔常常换了个说法，逐字查不中是常态不是例外。

值得单独记：**同一个错误换了个位置就没认出来。** 这条准入标准是我们自己定的，
批评别人的实现时用得很顺手，写自己的检索工具时却漏掉了。

**验收** `test_history_search_marks_hits_without_filtering`

### S55 · 关掉按需展开时，三者各自退回全量或永久隐去

**服务** [R5](../req/开局与设定.md)

**规格** 共用一条原则：截断 + 按需展开是**无损降维**，
**一旦没了展开的路，截断就变成有损筛选**。

| 关掉 | 行为 |
|---|---|
| `state_query` | 状态**每轮全量注入**，长值不截断 |
| `worldinfo_read` | 按需条目**全文进静态前缀**（设定跨轮不变，代价只付一次） |
| `history_search` | 被压缩的原文**永久隐去**，但**摘要仍留在上下文里** |

三处都**不再广告没注册的工具**。

**不做** 关掉工具之后仍然截断。也不做"整段抹掉"——模型必须知道那几轮存在过。

**验收** `test_state_is_injected_in_full_when_query_is_off` · `test_on_demand_worldinfo_is_inlined_when_read_is_off` · `test_worldinfo_tools_disappear_when_read_is_off` · `test_compacted_history_is_gone_for_good_when_search_is_off` · `test_state_query_disappears_from_both_sides_but_write_stays`

### S56 · 检索工具的描述给触发条件，不给机制说明

**服务** [R31](../req/调教提示词.md)

**规格** 六条触发条件：

| 情形 | 为什么 state 和摘要都不行 |
|---|---|
| 要**引用早前的原话** | state 里根本没有原话；摘要会改写措辞 |
| 要**兑现或推翻一个伏笔** | 埋下时它两边都进不去 |
| 要说清**先后与因果** | state 只有此刻的值；摘要把顺序压平了 |
| **摘要与 state 对不上** | 摘要可能有损；冲突时以原文为准 |
| 用户**直接指某一轮** | "回到他们在酒店那次" |
| 怀疑**与早前矛盾但说不清哪里** | 这是"不知道自己漏了什么"，只能扫 |

**反面同样要写**：想知道现在什么样看 state；想接住上一轮语气——近几轮细纲已经在
上下文里；只想知道大概发生过什么——摘要够用。

**为什么** state 与摘要的盲区是**同一个**：state 只记会约束后续的，
摘要只保留写它那一刻的重点。**两者的交集盲区就是「当时不要紧、现在才要紧」的细节**
——而伏笔的价值天生延迟显现，埋下时两边都进不去。**这不是摘要写得不好，
是原理上做不到。**

不写反面会滥用：每轮翻史，token 爆炸。正反对照着说，边界才钉得住。

### S57 · 摘要按段压缩，分界由模型判断

**服务** [R16](../req/推进剧情.md)

**规格** 摘要与细纲是 **n : 1**。编排层攒够最小轮数就问模型"该在第几轮之后断开"，
回 0 表示这一段还没完、再等一轮，到最大轮数强制断开止损。

段落按**「末节点 + 跨度」寻址**，不记起止 id。

**不做** 按轮一一对应。

**为什么** 一轮**不是语义单位**（一场对峙横跨四轮，一次转场只占半轮），
而且**条数不收敛**（50 轮就是 50 条索引）。

末节点寻址是为了分支安全：父指针唯一，从末节点上溯 span−1 步的链是确定的，
**任何经过末节点的路径都得到同一段**。

**验收** `test_segment_closes_when_the_director_says_it_closed` · `test_open_segment_waits_another_run` · `test_every_segment_goes_through_summarize` · `test_a_summary_says_how_many_runs_it_replaced_and_how_to_get_them_back`

### S58 · 判定在生成时，压缩在需要时

**服务** [R16](../req/推进剧情.md)

**规格** 归段拆成两步：**每轮生成后当场问**"这一轮是不是一段的结尾"，
答案记在节点上；压缩晚些按标记分组。

追问要问**「断在第几条」而不是「这轮是不是结尾」**，且允许**回溯**标记到前面几条。

**不做** 等一批轮次滑出窗口再问"这几轮算不算一段"。

**为什么** 两件事的**最佳时机不同**。合在一起时实测查全只有 0.67——
漏判是结构性的：待归段缓冲区里只有已滑出窗口的轮次，
**所以"第 9 轮是个分界"要等三轮之后才被问到，而那时问的人已经看不见揭示这个分界的
第 10 轮转场了**。分界恰恰是靠后一轮才认得出来的。

问法同样是结构性的：**决定性的差别是问题的形式，不是它看得见什么**。
二值答案只能对当前轮独立表态，**说不出"不是这里，是两轮前"**。
改成问位置且允许回溯，查全 0.33 → **1.00**。

仍会多切（查准 0.60），但**方向是良性的**：漏切把两段无关的戏并进同一条摘要，
是不可逆的信息损失；多切只是多一条索引，每段本身仍然完整。

**验收** `test_segment_closes_when_the_director_says_it_closed` · `test_open_segment_waits_another_run`

### S59 · 摘要由编排层触发，不做成模型可调的工具

**服务** [R16](../req/推进剧情.md)

**规格** 段一收，编排层就压。默认**开**，与其它能力"默认关"相反。
索引里据实标注是「总结」还是「开头」。

**不做** 让模型自己决定什么时候压缩。

**为什么** 压缩的收益全在**未来的轮次**——这一轮花 token，好处归下一轮。
**让优化当前轮的模型去做一件只利后续的事，是把激励放反了。**
实测 12 轮下来它一次都没被调用过。

默认开是因为**它的回退项不中性**：没有摘要时索引退化为"细纲前 120 字"，
那不是精度低一点，而是**位置偏置**——开头原样保留、结尾完全消失，
而它还顶着「总结」的名字。**会误导模型的回退不能当作安全默认值。**

**验收** `test_every_segment_goes_through_summarize` · `test_an_index_entry_says_how_much_it_left_out`
（后者钉的是回退那一半：没归过段的轮次在索引里是"细纲前 N 字 + 全文字数"）

### S60 · director 的对话跨轮持续，压缩越界一次、全部替换

**服务** [R7](../req/推进剧情.md)

**规格** 上一轮的用户消息、推理、**工具调用与结果**原样接在后面——
director 看得见自己查过什么、为什么那么写。

**状态与控制维度放在每轮的用户消息里，不放 system**。

压缩**不是段落一收就做**，而是攒到预算上限再做，**并且一次把所有能被摘要顶替的
段落全换掉**。

**不做** 每轮重建全新对话；不做每收一段换一段。

**为什么** system 是缓存前缀，**放会变的东西进去，前缀每轮失效**，
而且旧值会以"写在最前面"的权威姿态误导模型。

每收一段换一段等于每隔几轮动一次前缀，缓存反复失效——**那还不如不持续。**

节点只存**本轮新增的消息**，重放时沿路径拼接，分支因此天然安全。

**验收** `test_everything_is_kept_until_the_budget_is_crossed` · `test_crossing_the_budget_replaces_every_summarised_segment_at_once` · `test_nothing_is_dropped_when_no_segment_has_been_summarised_yet`

### S61 · 轮内保结构，跨轮扁平化

**服务** [R7](../req/推进剧情.md)

**规格** 同一条信息在两种场合要的形态不同：**本轮内**，工具调用与结果是模型正在
往下走的那条链；**跨轮**，它只是事实来源。所以重放时把一轮压成
「用户输入 → 一条 assistant 记录（调了什么、返回了什么、细纲是什么）」。

**扁平化发生在重放时，不在落盘时**——节点里存的仍是原样记录。

三样必须留住，它们各自不可再生：**用户输入**（用节点上的原文，
不是当时那条裹着旧状态快照的轮次提示）、**插话**（它改变了那一轮的走向，
位置也有意义）、**细纲**。

**验收** `test_a_past_turn_carries_no_tool_calls_at_all` · `test_flattening_keeps_the_facts_and_drops_the_stale_state` · `test_an_interjection_survives_flattening_in_place`

### S62 · 推理段在 run 内原样回传，落盘时抹掉

**服务** —（内部契约）

**规格** 分界划在 **run 边界**上。run 内推理是那条工具链的一部分（草稿续跑的是
同一个 run，所以草稿里要留）；run 之间值钱的是查到了什么、写下了什么细纲。

预算计数**必须把推理段算进去**。

**为什么** 实测一轮 director（3 个来回）的推理有 **15284 字**，而它产出的细纲只有
**207 字**——推理比产出长七十倍。原样存下来，持续对话跑两轮就撞预算，
压缩变成每轮都发生、前缀反复失效，**持续对话的全部意义就没了**。抹掉后两轮实测 2298 字。

预算只数正文而不数推理会**系统性低估**，且低估幅度随对话变长而增大。

**验收** `test_reasoning_is_stripped_before_a_node_is_stored` · `test_reasoning_counts_toward_the_context_budget`

## 这一层的验收标准：调得动就行

**检索不是早期必须做到完美的东西。** 验收标准只有一条：
**工具注册了、模型在需要时调得动、语义不误导、关掉时行为明确。不做查准查全要求。**

理由是它在系统里的位置——**检索是 state 与摘要的兜底，不是常规路径**：
state 记着会约束后续的和还欠着的账，摘要按"可不可再生"取舍，
剩下真正漏掉的才轮到它。

**前两条越准，兜底被用到的次数越少。** 实测里检索多次"正确地闲置"——
摘要保住了要找的信息，模型不必去翻。**那是系统健康的表现，不是覆盖不足。**

因此该继续投的是摘要，**它决定兜底要被用到多少次**。

## 两条方法论警告

**① 一个覆盖不到的组件，最容易的失败方式不是"测出问题"，而是"测出一切正常"。**

为检索造探针改了三版：第一版**问句里含着答案**；第二版埋点落在细纲开头，
而索引回退是"前 120 字"，**原样泄漏**；第三版埋了直接答案，
**摘要把它完整保住了，检索正确地闲置**。

第三版尤其要说清：**那不是失败**。失败的是探针——它测的东西不存在。
真正的条件就是上面那条判据本身：**埋下去的东西，当时必须不要紧。**

**② 被测的东西没有启用，而结果看起来像一个发现。**

"12 轮一次都没调用过检索"这个观察什么也说明不了——检索默认关闭，
而回归集的场景没打开它，**那 12 轮里两个工具根本没有被注册**。

这类错误比测出问题更危险：它给的是虚假的安全感，**还会引出一整串建立在假前提上的分析。**
