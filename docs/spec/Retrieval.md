# 检索与历史

> **回答**：模型怎么找回不在眼前的东西——早前的剧情、按需展开的设定。
> 以及跨轮的上下文怎么攒、怎么压。
>
> **不回答**：状态自己的形状与判据（见 [State.md](State.md)）、
> 工具签名（见 [Tools.md](Tools.md)）。

## 全貌

三样东西必须区分，判别式是**谁改变它**：

| | 内容 | 由谁改变 |
|---|---|---|
| **state** | 世界的当前样子 | **剧情推进**（state_manager 每轮提交增量） |
| **worldinfo** | 静态设定：世界、角色 | **用户** |
| **history** | 过往每一轮的输入、插话与正文；正文是唯一叙事权威 | 每轮随路径追加；仅最后一轮在编辑窗口内可改 |

灰区：同一个实体两边都能有——"他们是兄妹"属 worldinfo，"他们现在决裂了"属 state。

### 核心难点：信息需求在推演过程中才产生

**某个角色出场 → 需要他的信息；但"他出场"是 director 在推演中才决定的。**

代码无法预判，因为决定尚未做出。这使得预取在**实体级信息**上本质受限——
它只对体量小、恒定相关、可无条件注入的那几样成立。

**这个问题没有被解决，只是从代码手里交给了模型。**

### S52 · 规则可以做无损降维，不能做有损筛选

**服务** —（这是这一层的准入标准）

**规格** 智能检索与规则检索可以共存，**但规则的范围受限于"在所有情况下都不出错"**。

判据：**分界线是模型知不知道自己缺了什么。**

| | 合格 | 不合格 |
|---|---|---|
| 规则做什么 | 覆盖**全集**，只调节精度 | 筛选**子集**，猜相关性 |
| 失败模式 | 信息不够细 | 信息完全缺失 |
| 模型知情 | ✓ 摘要在眼前，知道可以展开 | ✗ 根本没意识到它存在 |
| 可自愈 | ✓ 点查补救 | ✗ |

**不做** 两样按这条判据出局的——

- **时间局部性预取**（"上一轮涉及的实体这一轮大概率仍相关"）：它在猜相关性，
  场景切换即带错人，而模型不知道有角色信息没被带进来。
- **关键词触发**：漏命中 → 条目完全缺失 → 模型不知道有这个设定存在。

**验收** `test_the_worldinfo_index_is_name_and_size` · `test_all_three_expand_the_same_way`

### S53 · 全量索引 + 按需展开，索引必须带体量

**服务** [R5](../req/开局与设定.md)

**规格** 三个域——设定、前情、状态——用**同一个模式**，不是三套：

```
注入：整棵树折起来（key + 体量）+ 常驻的那部分全文
工具：按 key 取回内容，**全给**
```

折起来的地方**必须带体量**，让模型知道取全文的代价。**地址必须是 key**——
拿得到的东西，不是"第 N 轮"这种人话。

**key 是人读得懂的名字**：状态的键名是模型自己起的，设定的条目名是用户起的，
两者都既是提要也是地址。**只有段落例外**——它没有名字，只有一段摘要，
而摘要当不了地址（太长、会重、传回来会被改写一两个字），所以它用 id，
**而 id 旁边永远跟着那段摘要**。

> 有名字的用名字，没名字的用 id，而 id 旁边跟着提要。

**不做** 只索引"已被激活的"条目（那底层仍是筛选子集）；**不做**分页与按体量
截断（见 [S157](#s157)）；**不做**在索引里塞正文开头——那是位置偏置最重的
一种预览，开头原样保留、结尾完全消失，而它还顶着「摘要」的名字。

**为什么** 地址不可用曾经让整个历史检索层从未被调用：索引写的是「第 N 轮」，
而读取工具要的是 run id——**模型看得见索引，却拿它没办法**，必须先花一轮换 id。
对比之下设定那侧的索引一直带得回去，它的读取就一直被正常调用。**差别就在这一处。**

同一条毛病的第二种形态是**地址和占位符不是同一套**：设定曾经显示 id、
状态显示键名、前情显示 run id，三处各写一遍，对不上时没有任何地方会报错——
模型照着占位符里的名字去调工具，工具说"没有这个"。所以现在只有一份实现（S157）。

**验收** `test_all_three_expand_the_same_way` · `test_worldinfo_is_addressed_by_name` ·
`test_the_worldinfo_index_is_name_and_size` · `test_always_worldinfo_is_injected_on_demand_is_indexed` ·
`test_history_read_expands_the_whole_segment` · `test_what_is_folded_is_addressable`

### S54 · **已撤销**：搜索那条路整个删了

**服务** —（S52 的直接推论，判据仍然成立）

这一条曾经规定：历史索引永远覆盖全部轮次，`history_search` 的 query
**只标注命中、不筛掉任何一轮**，并在结果里明写"没命中不等于没发生过"。
它修的是我们自己犯的那个错——查不中就返回空列表，而模型会把"空"读成
"没这回事"，正是判关键词触发不合格的同一条理由。

**`history_search` 现在整个删掉了**，所以这条规格没有对象了。判据没有被推翻，
是被**更彻底地满足**了：连"命中"这个概念都不存在，折起来的树永远覆盖全部段落。

删它的理由是它买到的东西太少：命中标记能加的信息只有"这几个字逐字出现过"，
而**伏笔常常换了个说法，逐字查不中是常态不是例外**——那正是上面那段话自己说的。
一个每次都要附带一句"没命中不等于没发生过"的功能，不值一个工具位。

> 仍然值得记：**同一个错误换了个位置就没认出来。** 这条准入标准是我们自己定的，
> 批评别人的实现时用得很顺手，写自己的检索工具时却漏掉了。

**验收** 无——没有对象了。覆盖全集那一半由 [S53](#s53) 的验收守着。

### S55 · 关掉按需展开时，三者各自退回全量或永久隐去

**服务** [R5](../req/开局与设定.md)

**规格** 共用一条原则：截断 + 按需展开是**无损降维**，
**一旦没了展开的路，截断就变成有损筛选**。

| 关掉 | 行为 |
|---|---|
| `state_query` | 状态**每轮全量注入**，深处不折、长值不折 |
| `worldinfo_read` | 按需条目**全文进静态前缀**（设定跨轮不变，代价只付一次） |
| `history_read` | 被压缩的原文**永久隐去**，但**摘要仍留在上下文里** |

三处都**不再广告没注册的工具**——那句话和工具名是同一件事的两处，
所以它也在 YAML 的 `rendering` 里（`history_folded_gone` 就是关掉时的那一句）。

**不做** 关掉工具之后仍然截断。也不做"整段抹掉"——模型必须知道那几轮存在过。

**验收** `test_state_is_injected_in_full_when_query_is_off` · `test_on_demand_worldinfo_is_inlined_when_read_is_off` · `test_worldinfo_tools_disappear_when_read_is_off` · `test_compacted_history_is_gone_for_good_when_read_is_off` · `test_state_query_disappears_from_both_sides_but_write_stays`

### S56 · 检索工具的描述给触发条件，不给机制说明

**服务** [R31](../req/调教提示词.md)

**规格** 六条触发条件：

| 情形 | 为什么 state 和摘要都不行 |
|---|---|
| 要**引用早前的原话** | state 里根本没有原话；摘要会改写措辞 |
| 要**兑现或推翻一个伏笔** | 埋下时它两边都进不去 |
| 要说清**先后与因果** | state 只有此刻的值；摘要把顺序压平了 |
| **摘要与 state 对不上** | 摘要可能有损；冲突时以原文为准 |
| 用户**直接指某一轮** | "回到他们在酒店那次" |
| 怀疑**与早前矛盾但说不清哪里** | 这是"不知道自己漏了什么"，只能扫 |

**反面同样要写**：想知道现在什么样看 state；想接住上一轮语气——近几轮正文已经在
上下文里；只想知道大概发生过什么——摘要够用。

**为什么** state 与摘要的盲区是**同一个**：state 只记会约束后续的，
摘要只保留写它那一刻的重点。**两者的交集盲区就是「当时不要紧、现在才要紧」的细节**
——而伏笔的价值天生延迟显现，埋下时两边都进不去。**这不是摘要写得不好，
是原理上做不到。**

不写反面会滥用：每轮翻史，token 爆炸。正反对照着说，边界才钉得住。

**验收** `test_history_read_description_has_both_sides_of_the_boundary`

### S57 · 摘要按段压缩，分界由模型判断

**服务** [R16](../req/推进剧情.md)

**规格** 摘要与正文是 **n : 1**。编排层攒够最小轮数就问模型"该在第几轮之后断开"，
回 0 表示这一段还没完、再等一轮，到最大轮数强制断开止损。
归段判断与摘要调用的叙事输入都只包含正文，不附带细纲、状态增量或旧工具记录。

段落按**「末节点 + 跨度」寻址**，不记起止 id。**那个末节点 id 就是它的 key**
（[S53](#s53)）：段落是三个域里唯一没有名字的东西，所以它是唯一用 id 当地址的，
而 id 旁边永远跟着那段摘要——摘要是提要，id 是地址。

**展开必须按段给回全文**：摘要在上下文里顶替的是**整段**，只还回末节点那一轮
比不展开更糟——模型会以为自己已经看全了。

**不做** 按轮一一对应；**不做**让摘要本身当地址（太长、会重、传回来会被改写
一两个字）。

**为什么** 一轮**不是语义单位**（一场对峙横跨四轮，一次转场只占半轮），
而且**条数不收敛**（50 轮就是 50 条索引）。

末节点寻址是为了分支安全：父指针唯一，从末节点上溯 span−1 步的链是确定的，
**任何经过末节点的路径都得到同一段**。

**验收** `test_segment_closes_when_the_director_says_it_closed` · `test_open_segment_waits_another_run` · `test_every_segment_goes_through_summarize` · `test_a_summary_says_how_many_runs_it_replaced_and_how_to_get_them_back` · `test_history_read_expands_the_whole_segment` · `test_only_folded_history_is_on_the_tree`

### S58 · 判定与摘要在生成后完成，重放直接兑现

**服务** [R16](../req/推进剧情.md)

**规格** 归段拆成两步：**每轮生成后当场问**"这一轮是不是一段的结尾"，
答案记在节点上；一段一旦收束，编排层立即为该段生成摘要，后续重放直接用摘要替换原文。

追问要问**「断在第几条」而不是「这轮是不是结尾」**，且允许**回溯**标记到前面几条。

**不做** 等一批轮次越过字符窗口再问或再决定是否折叠。

**为什么** 两件事的**最佳时机不同**。合在一起时实测查全只有 0.67——
漏判是结构性的：待归段缓冲区里只有已滑出窗口的轮次，
**所以"第 9 轮是个分界"要等三轮之后才被问到，而那时问的人已经看不见揭示这个分界的
第 10 轮转场了**。分界恰恰是靠后一轮才认得出来的。

问法同样是结构性的：**决定性的差别是问题的形式，不是它看得见什么**。
二值答案只能对当前轮独立表态，**说不出"不是这里，是两轮前"**。
改成问位置且允许回溯，查全 0.33 → **1.00**。

仍会多切（查准 0.60），但**方向是良性的**：漏切把两段无关的戏并进同一条摘要，
是不可逆的信息损失；多切只是多一条索引，每段本身仍然完整。

**验收** `test_segment_closes_when_the_director_says_it_closed` · `test_open_segment_waits_another_run`

### S59 · 摘要由编排层触发，不做成模型可调的工具

**服务** [R16](../req/推进剧情.md)

**规格** 段一收，编排层就压。默认**开**，与其它能力"默认关"相反。摘要生成失败时
该段继续以原文进入 history，不回退到按字符数截取正文开头。

**不做** 让模型自己决定什么时候压缩。

**为什么** 压缩的收益全在**未来的轮次**——这一轮花 token，好处归下一轮。
**让优化当前轮的模型去做一件只利后续的事，是把激励放反了。**
实测 12 轮下来它一次都没被调用过。

**验收** `test_every_segment_goes_through_summarize`

### S60 · director 跨 turn 只继承产品记录，完成段立即折叠

**服务** [R7](../req/推进剧情.md) [R31](../req/调教提示词.md)

**规格** 已完成 turn 跨边界只留下三类产品记录：顶层 user input、按原位置保留的纠正/
引导与最终正文。thinking、tool call/result、运行时错误与细纲一律不进入后续 turn
的 context。

**状态与控制维度放在每轮的用户消息里，不放 system**。

完成段从下一 turn 起直接换成段落摘要；未完成段继续保留逐轮正文。折叠不看字符数。

**不做** 每轮重建全新对话；不做上下文越过某个字符阈值才折叠。

**为什么** system 是缓存前缀，**放会变的东西进去，前缀每轮失效**，
而且旧值会以"写在最前面"的权威姿态误导模型。

每收一段会改变一次前缀，这是按语义边界折叠的明确缓存代价；不能为减少失效而让字数
阈值决定何时隐藏剧情。

节点保存重放所需的产品记录，重放时沿路径拼接，分支因此天然安全。系统不从旧工具
回执里补捞、概括或复制内容。

**验收** `test_unclosed_runs_are_kept_in_full` · `test_completed_segments_fold_without_a_character_threshold` · `test_nothing_is_dropped_when_no_segment_has_been_summarised_yet` · `test_a_past_turn_carries_no_tool_calls_at_all`

### S61 · 执行流量只活在当前 turn，挂起时才进草稿

**服务** [R7](../req/推进剧情.md) [R11](../req/推进剧情.md) [R31](../req/调教提示词.md)

**规格** 当前 run 内的 thinking、tool call/result 与运行时错误按协议原样保留，供后续
操作继续使用。run 被打断并挂起时，为了恢复同一个 run，把协议配对完整的执行记录持久化
进草稿。

turn 完成、明确放弃或整轮失败时，草稿中的执行记录随草稿一起删除；完成节点从一开始就
不存这些内容。重生成虽然仍在同一逻辑 turn，但它是新 run / 新版本，也不继承旧版本的
执行流量。

开发者 trace 是例外：它可以 append-only 留下完整交换用于审计，但永远不作为后续模型
context 的来源。

**验收** `test_a_past_turn_carries_no_tool_calls_at_all` · `test_flattening_keeps_only_the_input_and_prose` · `test_an_interjection_survives_flattening_in_place` · `test_reasoning_and_tools_only_persist_in_a_draft`

### S62 · 推理段只在 run / 草稿内存在

**服务** —（内部契约）

**规格** run 内推理是当前工具链的一部分，原样回传。草稿续跑的是
同一个 run，所以挂起时推理段也要随草稿持久化；完成节点与后续 turn context 一律不留
原始推理，也不另行生成跨轮推演摘要。

这条生命周期与 S61 的 tool call/result 完全相同。

**为什么** 实测一轮 director（3 个来回）的推理有 **15284 字**，而它产出的细纲只有
**207 字**——推理比产出长七十倍。原样存下来，持续对话跑两轮就撞预算，
压缩变成每轮都发生、前缀反复失效，**持续对话的全部意义就没了**。抹掉后两轮实测 2298 字。

**验收** `test_reasoning_and_tools_only_persist_in_a_draft`

### S157 · 折叠与展开是同一件事的两半，只有一份实现

**服务** [R5](../req/开局与设定.md)

**规格** 三个域各提供一棵 `key → content` 的树，**共用一个折叠器、一个展开器、
一套回执话术**（`agenttavern/disclosure.py`）。

| 域 | key | 提要 | 折叠单位 | 展开 |
|---|---|---|---|---|
| 状态 | 键名 | **就是 key 本身** | 每条分支从叶端起最后两层的对象；不按字符数折叠 | `state_query` |
| 设定 | 条目名 | 同上 | 按需条目的正文，**不看长度** | `worldinfo_read` |
| 前情 | 段落 id | **那段摘要** | 已归段的那几轮 | `history_read` |

前情的同一套折叠与地址同时供 director 和 goal_manager 使用：两者共享语义段落边界、
段落摘要与展开实现；goal_manager 另外保留用户在目标期间亲自给出的方向，不让它随正文
折叠消失。

**折叠留下的 key 必须就是展开接受的地址。** 折起来的地方一律是「key + 体量」，
只有前情多一句摘要——因为只有它的 key 不是人话。

**工具面上仍是三个**（[S21](Tools.md#s21)）：共用实现在下面一层，不在工具那一层。

**不做** 一个 `expand(域, 路径)`；**不做**分页、按体量截断、"没给全"那套话术
（[S26](Tools.md#s26)）；**不做**三处各写一遍占位符。

**为什么** 这三样以前是三套寻址（键路径 / 条目 id / run id）、三套截断话术、
三份"没找到"的写法。**对不上的时候没有任何地方会报错**——模型照着占位符里的
名字去调工具，工具说"没有这个"，而那一段就此取不回来了。这不是假设：地址不可用
曾经让整个历史检索层从未被调用过（[S53](#s53)）。

一份实现还顺带把两个原本各自为政的决定统一了：**取不到时把可用的 key 整个回给
模型**（让它下一轮改对，并压住键名漂移），以及**部分命中照样给**（为了几条不存在
的地址把整次调用判成失败，等于让模型多花一轮重来）。

未命中回执必须明确区分「可用地址列表」与「已经展开的正文」：地址列表不等于内容，

### S180 · 按需 worldbook 的名字同时承担提要与地址

**服务** [R56](../req/推进剧情.md) [R5](../req/开局与设定.md)

**规格** 折叠后的按需 worldbook 只展示条目名与体量，条目名同时是
`worldinfo_read` 的地址。用户负责让名字足以说明主题、适用场景与关键区分，使模型能在
不试读正文时判断它是否可能有用；系统不从正文生成、改写或校验名称质量。

**不做** 保存跨轮工具摘要来弥补含糊名称；不让代码按关键词猜条目是否相关；不把
按需条目正文提前泄漏进索引。

**为什么** 原始工具对话跨轮保留会膨胀上下文，另生成摘要又有成本、失真与线性增长。
名称本来就同时是人类可见提要和稳定地址；让作者提供有辨识度的名称，是更简单且可控的
乐观路径。代价是名称含糊时模型可能试探性读取，系统不承诺消除这种行为。

**验收** `test_worldinfo_is_addressed_by_name`；真实模型用含主题、场景与关键区分的长条目名
回归，检查是否能从索引选择最小相关集合。名称质量本身由人工评估，不设代码门禁。

### S182 · 三类折叠都使用语义边界，不使用字符阈值

**服务** [R58](../req/推进剧情.md)

**规格** state 对每个分支独立从叶端计算，把最后一个对象键及其叶子键值作为折叠单元；
分支外层路径全部显示。worldbook 只按条目的 `mode=on_demand` 折叠，history 只按已经
完成并取得摘要的剧情段折叠。任何一类都不因字符串或累计 context 超过某个字符数才折叠。

**不做** 长字符串叶子的特殊隐藏；不做正文开头截断回退；不把 corpus 的建索引分块
误当成上下文折叠——分块是检索单位，不会用占位符替换模型本来应看到的内容。

**为什么** 字符数与内容是否适合隐藏没有语义关系，会让同一结构仅因措辞长短得到不同
可见性。叶端对象、显式按需标记和剧情段落分别是三个域已有的自然边界。

**验收** `test_state_folds_each_branch_from_its_leaf_end` ·
`test_a_long_string_is_not_folded_because_of_its_size` ·
`test_explicit_leaf_folding_does_not_depend_on_string_size` ·
`test_completed_segments_fold_without_a_character_threshold`。

## 这一层的验收标准：调得动就行

**检索不是早期必须做到完美的东西。** 验收标准只有一条：
**工具注册了、模型在需要时调得动、语义不误导、关掉时行为明确。不做查准查全要求。**

理由是它在系统里的位置——**检索是 state 与摘要的兜底，不是常规路径**：
state 记着会约束后续的和还欠着的账，摘要按"可不可再生"取舍，
剩下真正漏掉的才轮到它。

**前两条越准，兜底被用到的次数越少。** 实测里检索多次"正确地闲置"——
摘要保住了要找的信息，模型不必去翻。**那是系统健康的表现，不是覆盖不足。**

因此该继续投的是摘要，**它决定兜底要被用到多少次**。

## 两条方法论警告

**① 一个覆盖不到的组件，最容易的失败方式不是"测出问题"，而是"测出一切正常"。**

为检索造探针改了三版：第一版**问句里含着答案**；第二版埋点落在细纲开头，
而索引回退是"前 120 字"，**原样泄漏**；第三版埋了直接答案，
**摘要把它完整保住了，检索正确地闲置**。

第三版尤其要说清：**那不是失败**。失败的是探针——它测的东西不存在。
真正的条件就是上面那条判据本身：**埋下去的东西，当时必须不要紧。**

**② 被测的东西没有启用，而结果看起来像一个发现。**

"12 轮一次都没调用过检索"这个观察什么也说明不了——检索默认关闭，
而回归集的场景没打开它，**那 12 轮里两个工具根本没有被注册**。

这类错误比测出问题更危险：它给的是虚假的安全感，**还会引出一整串建立在假前提上的分析。**
