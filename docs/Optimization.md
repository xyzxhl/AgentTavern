# 优化流程

> 项目里有多个提示词、工具描述、装配规则、参数。这份文档规定**怎么改它们**——
> 尤其是怎么知道改对了。
>
> 判据在 [Principles.md](Principles.md)，这里把它们串成流程。

## 1. 优化对象

按"改一处影响多大"排序。前两类的杠杆远大于后两类。

| 类别 | 具体 |
|---|---|
| **上下文装配** | 注入什么、多少、什么顺序；两个滑动窗口（`upstream_runs` / `state_recent_runs`）、`state_inline_limit`、默认包范围 |
| **提示词** | 四个 agent（director / writer / state_manager / goal_manager）+ 一次单次调用（summarize）的提示词，全在 `prompting/*.yaml` |
| **工具面** | 各工具的名称、描述、参数描述；能力开关的默认值。**描述只说「作用 + 参数格式」**，判据归 YAML（S27） |
| **措辞映射** | 控制维度枚举值 → 提示词片段（输入处理三档、展开密度、控制权） |
| **参数** | 全在 `config.yaml`（S86）：各 agent 的轮数上限、`budget_chars`、归段跨度、采样标记阈值、goal 预算 |

**工具描述是被低估的优化对象**——它也是提示词，而且模型对它的敏感度不低于系统提示词。

**一次只改一个。** 归因统计是唯一的信号，同时改两处就分不清是哪个起的作用。

## 2. 从参考实现取材

`docs/sillytavern_preset_example/` 下有三套实战 SillyTavern 预设（其中两套另有适配 TauriTavern 的 Agent 版），以及一个 36 种文风的技能包。它们是最好的初始提示词素材来源——都是被真实使用打磨过的表述。

### 它们的结构

不是"一份提示词"，是**大型可勾选提示词库 + 正则后处理 + 前端脚本**：

| | 狐神 | 双人成行 | 夏瑾 |
|---|---|---|---|
| prompts 条目 | 217（启用 66） | 250（启用 78） | 140（启用 10） |
| regex 脚本 | 39 | 41 | — |
| 前端脚本 | 2.9 MB | 220 KB | — |

它们用 `{{setvar::名::…}}` 定义变量，最后由一个「注入强调」块统一拼装——**那就是它们手写的上下文装配层**，和 `prompting/` 这个组装器同构。

### 一个强验证

它们的分类几乎逐条对应我们从原理推出的控制维度：

| 预设里的开关 | 我们的 |
|---|---|
| 分段转述（**选一**） | 输入处理三档（S81） |
| 禁止抢话（**选一**） | 是否允许抢话（S81） |
| 智能长短文（**选一**） | 展开密度 |
| 文风要求（**选一**） | 文风（元指令，只给 writer） |
| 行动选项 | `ask_question` |
| 防全知 / 防剧透 | 信息不对称（G1，optional） |
| 杀八股 / 禁词表 | 否定项 |

**「（选一）」这个命名约定本身就是 P10**——把开放判断降级成闭集选择。这条原则不是推导出来的，是实践者早已收敛到的。

### 取材时必须先分类：写作经验 vs 架构补丁

**这是这份材料唯一危险的地方。** 预设里很大一部分内容不是写作经验，而是**在补 SillyTavern 的架构缺陷**。照抄会把我们不需要的复杂度请回来。

| 内容 | 性质 | 处置 |
|---|---|---|
| 转述手法、抢话边界、篇幅分级、推进基准、落笔手法 | **写作经验** | 抄 |
| 状态栏 / 行动选项的 HTML 标签格式 | **补丁**：只能靠标签从一坨文本里刮结构 | 不抄——我们有 `state` 与 `ask_question` |
| 39 条隐藏正则（剥离思维链、草稿、选项） | **补丁**：产出物没有字段之分 | 不抄——我们有 `outline` / `prose` 分字段与 trace 分层（S111） |
| 大段「工具参数必须是 JSON 对象而非字符串」的教学 | **补丁**：解析失败会截断整轮 | 不抄——`ToolCall.from_raw` 已把它变成可恢复的 tool result |
| 结构化时间标签 `<ft_clock day minute>` | 介于两者之间 | 思路对，但属 S30 的**模板库**层（尚未做），不是固定核心 |

判据很简单：**如果一条规则存在的理由是"否则没法从文本里分辨出某部分"，那它是补丁，不是经验。**

### 归属：写什么 vs 怎么写

预设是一整坨，拆进我们的拓扑时要逐条判断给谁（[spec/Architecture.md](spec/Architecture.md) §3）：

| 内容 | 归 |
|---|---|
| 转述手法、转述与抢话的对照、抢话的停止条件 | director |
| 篇幅分级、反填充清单、叙事推进基准 | director |
| 落笔手法（情感落在外在、节奏跟感知走） | **writer** |
| 台词的措辞、语气、绕不绕（S89） | **writer**——语言描写也是描写 |

分错边就是在破坏隔离，所以**这个划分要有测试守着**——现有测试断言 writer 的 prompt 里有「情感落在外在」而没有「剧情锚点」。

### 三条最值钱的表述

1. **转述与抢话必须对照着说。** 单独讲各自的规则时模型会在边界上摇摆；对照着说边界就钉死了——转述处理**已经写出的**，抢话是替用户写**尚未发生的**。
2. **禁止抢话要给「停止条件」**，不是"别写太多"：推进到向用户提出问题/选项、做出等待回应的动作、或形成只能由用户推动的局面，就收。没有这个，"别抢话"会让模型畏手畏脚。
3. **反填充清单**（不许用天气、家具、路程、换装、无意义等待凑字数）比"不要注水"具体得多，而且正好防住 P19 那个失败模式——给了字数目标，模型就会灌水。

### Agent 版的 critic 子 agent

两套 Agent 版都用了「主 writer + 只读检查子 agent（禁词、人设）」。

**按 P11 它们的增益是成立的**：禁词表是用户给的明确真值（有验证器），子 agent 只读正文 + 禁词表（有上下文差），两个条件都满足，与 goal 判定同构。

我们仍不做，理由不变（P12：检出后要重写正文，成本高，决定权应在用户）。但记下这个观察——**如果将来发现否定项违规频发，这是唯一一处 P11 明确成立、值得重新考虑的地方。**

## 3. 三种 grader 的分工

### 判据：有没有参照物

这是分工的唯一依据，而且它**恰好对应归因五类**（S12）：

| 归因 | 参照物 | 谁来判 |
|---|---|---|
| director 检索不足 | 细纲 vs **state** | AI |
| director 推演错 | 细纲 vs **用户指令** | AI |
| writer 偏离细纲 | 正文 vs **细纲** | AI |
| 写入遗漏 | 增量 vs **正文 + 本轮之前的 state** | AI |
| 写入冗余 | 增量 vs **判据本身**（S34/S36） | AI |
| **writer 文风失败** | **无**（符合细纲但读起来不对） | **只能 human** |

五类有参照物，一类没有。**没有参照物的那一类恰好最主观、也最影响体验**——这是 human eval 不可省略的原因，也是 P11 说的"无验证器时审查意见只是第二种品味"在这里的具体形态。

**这张表有两处是被首批实测改出来的**，两处都值得记：

- **写入遗漏原先只给「增量 vs 正文」，不够。** 不给本轮之前的 state，它分不清"漏记"和"早就记过"——种子里写着"与一个已死之人站在一起"，它仍报了"未记录此人已死"。**参照物不完整比没有参照物更危险**：它照样给得出自信的判断。
- **原先没有「写入冗余」这一类**（S12）。写入侧只有遗漏没有多余，于是 `照片.状态: "柜台，正面朝上"` 被全部归因一致判为没问题。**分类有洞时，洞里的问题是查不出来的，而不是被查出来判错**——后者还能从证据里看出来，前者只会呈现为一片"没问题"。

### program grader —— 保守使用

**准入标准：只有当「违反 = 流程坏了」而非「违反 = 写得不好」时才能用。**

前者二值、无争议；后者是品味。可以做的只有三件：

- **契约形状**：有没有调 `state_write`、有没有 `submit_outline`、JSON 是否合法、run 是否完成
- **可数的量**：字数、工具调用次数、loop 轮数、token 消耗
- **字符串存在性**：用户角色名是否出现在正文里（抢话的粗筛）

它们的用途只有两个：**回归护栏**与**采样器**。

> **正则是采样器，不是判断器**（P12）。它不回答"这段写得对不对"，只把可疑样本挑出来送审。

现有的 `sampling_flags` 就是正确形态——返回"可疑"，不返回"错误"。

#### 采样器不能反过来当决策项：正文/细纲比值的教训

**"可疑"只对单个样本成立；把它汇总成一个均值，它并没有因此变成一个指标。**

比值（`prose / outline`）是判隔离有没有生效最廉价的信号（S14），拿它挑样本是对的。但把 `ratio_avg` 当成回归信号，两次实测都栽了：

| | 比值 | 我当时的读法 | 实际 |
|---|---|---|---|
| noir，S60 前后 | 1.9 → **1.22** | "S60 引入了回归" | 同一批改动下 data 是 1.75 → **1.82** |
| chapters，同一配置连跑五次 | 1.43 ~ 1.69 | —— | **纯噪声，跨度比上面那个"回归"还大** |

两条毛病叠在一起：**它的方差本来就大于要检测的效应**，而且**它在不同题材上不可比**——对白密集的场景比值天然低，因为细纲写对白语义、正文写实际台词，接近 1:1，而对白不产生可展开的描写（Q30）。

> **判回归要用在题材间可比、且方差小于效应的量**：归因分布（"writer 偏离细纲""写入冗余"）、契约违例数、分界查全查准。比值只留在逐轮报告里当线索，不进结论。

### 为什么要保守：假警报之外还有更坏的

假警报会让人不再信任系统，这条已经说过。但硬约束还有一个**更隐蔽的伤害**：

> **模型会为了满足检查器而牺牲质量。**

要求字数必须落在某个区间，它就会灌水或砍细节；要求正文必须包含某个模式，它就会硬塞。这不是误报，是**主动的质量损失**，而且从检查器的角度看一切正常——它永远不会告警。

因此：**不加"字数必须在 X–Y 之间"这类硬约束，不加"必须包含某某"这类模板检查。** 这些量只作为采样信号。

自动强制的边界由 P12 划定：**修复成本决定能否自动强制**。补交状态增量成本≈0，可以强制；重生成正文成本高，只能提示、由用户决定。

### AI grader

规模化的语义判断，**只用在有参照物的四类归因上**。

- 用**干净上下文**（P20）：只给 [参照物 + 待判对象]，不给创作过程——否则它会往"没问题"的方向读。
- 输出**结构化的归因标签**，不是评分。评分无法指导行动，归因可以——五类的修法完全不同。
- 用便宜模型即可，它做的是比对不是创作。

**AI grader 本身需要校准**：定期由 human 抽查一批它的判断，看归因是否可信。不校准的 AI grader 会悄悄漂移，而它的错误会直接误导后续所有决策。

### human grader

唯一能回答"是不是要的东西"。昂贵，因此必须**定向**——只看 program 采样 + AI 归因挑出来的样本，加一小批随机对照（防止采样器本身有系统性盲区）。

**交互式产品有免费的行为代理**（P19）：重 roll 率、打断率、戏外引导频率、会话时长。这些不需要任何标注成本，而且比问卷更诚实。**从第一版就采集**——它们是"文风失败"那一类唯一可规模化的信号。

## 4. 流程

```
1. 采集     开发者模式跑一批 session，落 trace
2. 筛       program 采样器标记可疑样本（不判对错）
3. 归因     AI grader 对「采样命中 + 随机对照」做五类归因
4. 统计     看哪一类占多数  ← 这一步决定改什么
5. 改       按该类对应的修法改，一次一处
6. 回归     program grader 确认流程没坏
7. 验收     human 在小样本上确认质量真的变好
```

**第 4 步是核心。** P18 说"先做诊断，再改结构"——五类的修法完全不同，而且**最贵的那一类最容易被误判成下游的问题**：director 检索不足导致的细纲错误，看起来像 writer 写砸了。

| 归因占多数 | 该改什么 |
|---|---|
| director 检索不足 | 默认包范围、键名一致性、`history_read` 是否该开 |
| director 推演错 | director 提示词、控制维度的措辞映射 |
| writer 偏离细纲 | writer 提示词、**细纲粒度**（Q21） |
| writer 文风失败 | 文风约束的表述、**是否需要前移结构层**（Q20） |
| 写入遗漏 | `state_write` 的工具描述、流程步骤的措辞 |

**归因的可行性是 director / writer 拆分的副产品**——中间量物化了才分得清"规划错了"和"执行错了"。合并方案下这张表整个不成立。

### 新 grader 的第一件事是校准，不是用它的数字

首批归因跑出「写入遗漏 40%、检索不足 20%、推演错 20%」。**按这个分布去改就全错了**——人工核过之后，四条里至少三条站不住：

| 报告 | 核查 |
|---|---|
| 未记录"何平已死" | 种子里她**本来就知道**死者已死，本轮新增的只有名字。参照物不完整导致的误报 |
| 陈屿知道照片来源却反问出处 | 他的人设正是"说话绕、用反问代替回答"，而且他在用这个问题换筹码。**grader 拿不到人设**（P20 干净上下文的代价） |
| 把"钟表铺"写成"旧货店" | 那家店在设定里就叫旧货店，里面堆着旧钟表。改的是称呼不是含义 |
| 未记录"陈屿拒收照片" | 一个转瞬即逝的局面，按 S34 判据本来就不该记 |

第三条尤其要记住：**干净上下文（P20）是有代价的**。不给人设，grader 就把"故意装不知道"读成"忘了自己知道"；给了人设，它又会开始为一切辩护。这条张力没有免费的解法，**只能靠校准把它量出来，而不是靠调 prompt 消掉它**。

因此纪律是：**grader 改动后，先用 `--regrade` 在同一批素材上重判，人工核一遍误报率，再决定它的数字能不能用。** 换素材重跑会把 grader 的差异和模型本身的随机性混在一起，那样谁也说不清是什么变了。

### 误报不需要被消灭，只需要被过滤（P19）

打了两轮补丁之后发现：**补一个误报，下一次会冒出另一个不同的误报。** 三次重判的对照：

| | 第 1 次 | 第 2 次 | 第 3 次 |
|---|---|---|---|
| `照片.状态` 记朝向 | —（当时还没有这一类） | ✔ | ✔ |
| `关系` 键混进动作摘要 | — | ✔ | ✔ |
| 场景跳夜里但 `时间` 没更新 | — | ✔ | ✔ |
| 反问出处 = 矛盾 | ✔ | ✔ | ✘ |
| 「钟表铺」→「旧货店」 | ✔ | ✔ | ✘ |
| `set null` = 记录未明 | — | ✔ | ✘ |
| 「林昭在场却写她推门进店」 | ✘ | ✘ | ✔ |

**上三行是真问题，跨次稳定；下四行是误报，每次换一个。** 而温度已经是 0——这不是采样温度的问题。

于是解法从"把 grader 调准"改成"**把噪声过滤掉**"：`--repeat N` 每类判多次，**过半才计入**。这比继续打补丁划算得多，而且它不依赖我猜中下一个误报长什么样。

补丁仍然要打——但只打那些**稳定复现的误报**（人设导致的回避、同一实体的别名、`null` 的语义），它们是判据本身写漏了，不是噪声。**判据的洞和 grader 的抖动，靠复现率就能分开。**

`--repeat 3` 跑下来的结果干净得出乎意料：

| 归因 | repeat=1 | repeat=3 |
|---|---|---|
| 检索不足 / 推演错 / 偏离细纲 | 20% / 20% / 20% | **全部 0%** |
| 写入冗余 | 40% | 40%（两条都是 3/3） |
| 写入遗漏 | 40% | 20%（3/3） |

**活下来的三条全是 3/3，而且每一条都经人工核实为真；1–2/3 的那些全是噪声。** 没有中间地带——这比预期更利落，也说明阈值取"过半"是够用的。

## 5. 组件调试顺序

**归因五类本身就是调试顺序**，这不是巧合——它们按数据流排列，而**上游的错会伪装成下游的错**：

```
worldbook 种子 → 初始 state
                    ↓
用户输入 → director（读 state / worldinfo / history，调工具）→ 细纲 → writer → 正文
                    ↓
                 state 增量
```

state 脏 → director 读到错的 → 细纲错 → 正文错。**症状出现在最下游，病因在最上游。**

因此顺序是固定的，**不能反过来**：

| # | 组件 | 为什么排在这 |
|---|---|---|
| 1 | **state 写入**（`state_write` 描述、注入格式） | 它污染之后的一切。而且它自己没有上游 |
| 2 | **检索**（worldinfo / history 渐进式披露） | 缺信息与推演错在细纲上长得一模一样 |
| 3 | **director 提示词**（转述、抢话、推进） | 到这一步才能确定"信息是全的，是想错了" |
| 4 | **writer 提示词**（文风、台词） | 唯一只影响正文的一层 |
| 5 | **可选能力**（goal / ask_question / summarize） | 关掉时系统仍完整（P14），最后调 |

> **先调 writer 是最容易犯的错。** 上游脏数据会被当成 writer 的锅，于是写出一堆补偿性的提示词补丁——补丁在上游修好之后仍然留着，且没人记得它们为什么在。
>
> 这不是假想：阶段 1 我在跑过任何归因之前，凭肉眼样本连改了四轮 writer。事后回看，其中"收尾定式"那条**根本不在 writer 侧**（S90）。

## 6. 集成调试

组件各自正确不等于合起来正确。集成面按**耦合强度**排：

| 集成面 | 查什么 | 只能在这里暴露的问题 |
|---|---|---|
| **线性多轮** | 状态沿路径累积、前情衔接、键名漂移 | 增量合并、种子被覆盖、同一概念多个写法 |
| **长会话（20+ 轮）** | 渐进式披露真的走起来 | 索引撑爆、state 膨胀、摘要质量、早期信息丢失（Q23） |
| **分支** | 重生成 / 切换 / 编辑节点 | **状态跟着路径走**（S42）——切分支不切状态是"文本对、状态悄悄错"，几百轮后才以角色行为不合理的形式暴露 |
| **打断** | 打断的单位是阶段，掐到哪段哪段作废（S49） | 暂存区泄漏到下一轮、恢复点选错（空输入只重跑该段，有输入回 director） |
| **实时链路** | WebSocket 消息序、autocontinue | 消息乱序、冷启动误触发 |

**前两个是每次改动都要跑的；后三个是改到相关代码时才跑。**

### 分支：纯代码层面的正确性，不必用真实模型跑

一度做了一个真实模型的污染探针（在 A 支埋专属名物、跑完 B 支去搜）。**那是把确定的事变成了概率的事，还贵。**

分支要验的是"B 支的上下文里有没有 A 支的东西"，而上下文是三个**确定的数据通道**：

| 通道 | 坏了说明 |
|---|---|
| `user_input` | 每轮的 user 消息取错了路径 |
| `state` | `state_at` 按 session 而不是按路径折叠（S42 失守） |
| 重放出来的 `history` | `replay_messages` 串了路径（S60 失守），**包括工具调用与结果** |

三条各写一个断言就够了，脚本化回复即可，跑一秒钟。真实模型只能给出"这一次没串"，而且**串了但这一轮恰好没用上时它还是绿的**——那是运气不是正确性。

最后一条是 S60 引入的新通道：工具往返现在也留在上下文里，而查细纲查不到它（工具结果不出现在细纲里），必须单独断言。

**反向也要查**：主干上确立的事实两支都必须还记得。只查污染会漏掉相反的错误——隔离过头，路径重建把主干也切掉了。

### 打断：挂起，不是作废

见 S48 与 S50。这里错了两次，两次都是同一种错：**把一个动作归进了它不属于的那一类**。

| | 要不要已完成的部分 | 插入点 |
|---|---|---|
| 重生成 | 不要 | —— |
| **引导** | 要 | **下一个操作边界** |
| **打断** | 要 | **就在被掐掉的那次操作处** |

- 第一次错：把打断归成了重生成（"被否决的推演不该留"）。**"用户否决了这条路线"是我替用户加的假设**——按下停止只说明"别再往下跑了"。
- 第二次错：把引导归成了推进（排队，等这一轮写完再开新的一轮）。**那样的话用户看着 director 往错方向查了六次资料，也只能等整段正文写完才说得上话。**

两次修正之后，三者的判别式就只剩上表那两列了。「操作」= 一次模型调用或一次工具调用。

`tests/test_branch.py` 钉住：引导落在两次操作之间且不开新的一轮、打断只掐掉在飞的那次操作（仍然产出**同一个**节点）、打断而不说话则挂起成草稿、被掐掉的工具调用仍有结果、续跑后是一个节点、切了分支的草稿被丢弃、writer 阶段打断不需要草稿。

四个坑值得单独记：

- **尾部悬空的工具调用**必须处理掉。掐在工具调用上时要**补一条"被打断"的工具结果**（继续跑的路径）；存草稿时要**整条丢掉**（挂起的路径）。留着它，下一次请求会被端点拒绝**整份**，而错误发生在之后，看上去和打断毫无关系。危险的那一刻在集成测试里很难复现，所以截断函数要手工构造消息列表直接测——否则这段逻辑等于没被测过。
- **消息序限制了边界能设在哪**：`tool_calls` 和它的 tool 结果之间塞不进 user 消息，所以边界只有三处——一轮开始前、纯文本回复之后、一次响应的全部工具结果补齐之后。
- **信号和操作在赛跑**。操作先跑完时没东西可掐，"掐到没掐到"就是假的判据，而用户明明按了停止。边界处要再看一次信号本身——这个 bug 是测试抓出来的，两条用例同时红。
- 续跑时注入的 state 要用 `current_state`，否则模型刚看完自己那条 `state_write` 的回执，紧接着收到一份没有它的状态。

## 7. 消融

改单点靠上面的循环。**判断一个组件该不该存在**，靠消融（P19）——同一批素材跑多个配置：

1. 单 agent 全揽
2. writer + 工具（去掉 director，细纲用人写的）
3. 完整拓扑

指标分两类：**事实/逻辑错误率**（工具层的存在理由）与**"是否写出了要的东西"**（拆分的存在理由）。

若某一层无增益，正确动作**不是删掉其功能**，而是把它从"流水线上游"改为"需要时被咨询"。

optional 机制的强度旋钮（见 [Ideas.md](Ideas.md)）天然是消融维度——档位本身就是配置。

## 8. 回归集

一组固定的场景 + 录制的输入序列，改动后重跑。

创作输出不确定，所以回归集能保的**只有流程，不是质量**：

- program：契约都满足了吗、run 都跑通了吗、token 有没有异常膨胀
- AI：归因分布有没有恶化
- human：只看一小撮

**不要试图用回归集锁定输出内容。** 那等于把某一次生成当成标准答案，而它不是。

### 必须包含一个「反向的世界」

调 state 判据时，所有实测都跑在同一个悬疑场景上。在那个场景里得出的两条经验，拿数据化的世界（修真 + 数值系统：灵石、冷却、消耗品）一压，**一条错了，一条漏了**：

| | 悬疑场景下看着对 | 数据化世界揭穿的 |
|---|---|---|
| "只在这一两轮内有意义的就不记" | 照片朝向、离收摊几分钟确实不该记 | **错的**——冷却只剩两回合活不过几轮，漏了立刻出逻辑错误。判据是"能不能被算错"，不是"存续多久"（S34） |
| `set` + `append` 两种写入语义够用 | 那里的清单（知情、经历）天然只增不减 | **漏了 `remove`**——消耗品会用完。模型绕开缺口的方式是把清单拍成字符串，结构不可逆地塌掉（S32） |

第二条尤其值得记：**缺口不是以报错的形式出现的**，是以"模型找到了一条绕过去的路"的形式出现的，而那条路悄悄破坏了数据结构。只看有没有出错，永远发现不了。

因此回归集里**必须有一个与主场景性质相反的世界**。判别式不是题材，是**约束的性质**：文学场景的约束多是长效、定性、只增不减的；数据化世界的约束是短效、定量、有增有减的。两边都过的规则才是规则，只在一边过的是那个场景的经验。

### 现有的四个场景

| 名字 | 轮数 | 性质 | 专门用来查 |
|---|---|---|---|
| `noir` | 5 | 现代悬疑，克制文学向 | 转述、抢话、知情累积（约束长效、定性、只增不减） |
| `data` | 5 | 修真 + 数值系统 | 资源结算、冷却、消耗品增删（约束短效、定量、有增有减） |
| `noir_long` | 12 | 同 `noir`，但够长 | **渐进式披露**——第 2 轮埋「三年前七月」，第 11 轮逼问 |
| `pulp` | 5 | 都市异能，网文腔 | writer 是否真的跟着 `prose_style` 走；也是"表达自然"的量尺 |

`noir_long` 与 `pulp` 各自补一个盲区：前者补的是**短场景走不到的代码路径**（`RECENT_OUTLINES = 3`，5 轮的场景里 `history_read` 一次都不会被调用，归段也不会真的压缩）；后者补的是**同向的文风**——`noir` 与 `data` 的 `prose_style` 都是克制文学向，两个场景分不开"writer 在跟文风走"和"writer 一直用同一副默认腔调"。

### C1 / C3 / C4 上已经发生的修正

三个阶段的具体发现见下面三节。它们共同的形状值得先说：**每一次真正有效的修复，都不是"再加一条禁令"，而是改掉了让模型走错路的那个诱因或那个信息缺口。**

| 症状 | 无效的做法 | 有效的做法 |
|---|---|---|
| 把设定抄进 state | 在工具描述里禁止抄 | worldbook 种子（S68）——**移除诱因** |
| 清单被拍成字符串 | 要求保持形状 | 补 `remove` + 渲染标出「清单」（S32）——**补上缺的语义与信息** |
| 每轮同一个画面收尾 | 三次不同措辞的禁令 | 告诉 writer**跳过它不算偏离**（S90）——**把它划到"事实"之外** |
| 细纲过度描写 | — | 事实 vs 呈现的对照 + **给出越界的代价**（S14） |

### C4 的前置：粒度先被一个提示词错误锁死了

在测粒度之前，粒度根本没有活动空间——细纲与正文长度几乎相等（524/526、739/753、559/544、644/648），writer 只做了断句和引号替换。

根因不是模型不听话，是 prompt 让 director 越界：它被告知"产出是一篇不受文风约束的**完整文章**"，同时拿到了**篇幅**要求——而篇幅只能靠描写凑。于是 director 写出成品散文，writer 除了照抄无事可做。**两个症状（细纲过度描写、正文文风糟糕）是同一个根因。**

修法是把分工改成**事实 vs 呈现的对照**，并在两侧都说：

- director：「事实是『桌上摊着一只拆开的座钟』；描写是『齿轮和发条散在垫布上，黄铜在灯下发暗』。」+ **「你写了它只会照抄」**——给出越界的**代价**，而不只是禁令。
- writer：同一组对照，加上「**这不是润色，是展开**」。
- 篇幅分级整段移到 writer；director 那侧换成**事件密度**（`ExpansionDensity` 的反向投影：铺陈少 → 同样篇幅装下更多事件）。

结果：214/710、217/463、240/558。**这条测出来的方法比结论更重要——先看两侧的输出长度比，它是隔离是否真的生效的最廉价指标**（program grader 可算，且没有假警报风险：它不判断好坏，只报告分布）。

副作用即 S91：writer 一旦真的在展开，就够得着抢话这条线了。**每次给一侧松绑，都要重查它有没有获得新的越界能力。**

### C4：writer 侧

细纲详细度经人工检查后确认没有大问题，优化转到 writer。

**最有效的一改是把台词划给 writer（S89）。** 判据是"语言描写也是描写"：细纲写**说了什么意思**，正文写**这句话怎么出口**。此前细纲直接写定台词，`character_voices` 完全是死的——语言习惯根本没有落点。数据化世界的交易场景 1.1 → 2.4 倍，价钱一个没错，台词开始有口音。

这同时改掉了 Q30 的诊断：对白密集的场景比值低，**不是"对白无法展开"，是对白当时被写死在了细纲里**。

**三次失败的收尾定式修复，值得完整记下来。** 四份样本 4/4 以同一画面收尾（「等她开口」「等着她给一个回答」「只等回音」）：

| 尝试 | 结果 |
|---|---|
| 只在 writer 侧说"收尾不要总是同一个画面"，并点名禁「顿了一下」 | **无效**。根不在这——细纲里写着"等她回答"，writer 照写才是对的。且它写出了「停了一下」「顿了顿」 |
| 改 director：删掉停止条件里的"做出了等待回应的动作"，加"不要再补一句「他没再说话，等她回答」" | **无效**。产出「说完站在原地，等她回答」 |
| 删掉上面那句样句，改成纯正向表述 | **仍无效**。产出「说完站在柜台里等林昭开口」 |
| **禁止 + 替代**：两侧都说"停在最后一件真发生的事上（一个刚问出口的问题、一件被推过来的东西）"，且告诉 writer**跳过这句不算偏离** | **生效**。正文收在「她看着他手上那副手套。」 |

三条教训：

1. **一度以为是负面示例在充当模板**（给了样句，模型就照着产出）。**删掉样句后行为不变，这个假设被证伪。** 真实原因更简单：「把球交给用户」是 airp 的类型惯例，模型认为那就是最后发生的事。
2. **只禁不给替代，等于没说。** 模型需要一个落点，否则它会退回最熟的那个。
3. **最终生效的是"漏掉它不算偏离"这半句**——director 至今仍然会写那句，是 writer 学会了跳过。**把某样东西划到"事实"之外，比反复要求不要写它更有效。**

**代价已经出现，记为 Q29**：不让写"某人在等"，writer 就改成停在 POV 角色的知觉上（「她看着他手上那副手套」「指腹贴着石面的凉意」），三份样本一致。而 POV 角色正是用户角色——这撞上了抢话。**破掉一个定式会把出口挤向另一条被禁的路。**

再次印证 S91 那条：**每次给一侧松绑，都要重查它有没有获得新的越界能力。**

### C1：state 写入

改动最多的一层，因为它在数据流最上游，脏了之后所有下游症状都变形（§5）。

| 发现 | 修法 |
|---|---|
| 模型把设定抄进 state，副本会与设定分叉 | worldbook 种子（S68） |
| 判据是**时态**的（状态 vs 事件），拦不住记得过细 | 换成**用处**判据：不记会不会写出"不可能发生"的事（S34） |
| 「只在这一两轮有意义的不记」会误杀冷却与余额 | 明写**存续时长不是判据**（S34，由 `data` 揭穿） |
| 清单只能整体重写，模型改用字符串把它拍平 | 补 `remove`；渲染标出「清单」（S32） |
| state 与 history 的关系没说清 | 定位为**捷径而非第二份记录**，判据随之变成双条件（S36） |
| 场景跳到夜里，旧的 `时间` 留在原地变成假信息 | **过期的值比没有值更糟**；新建键前先看有没有已在说同一件事的键 |
| 把**这一秒的画面**当状态记（占比最高，两场景各 40%） | 自检「下一轮开始时这条还成立吗」——**已验证有效** |
| 已有 `沈砚.冷却`，又另起一个裸键 `冷却` | 提示词拦不住；改用采样标记查"只差一个前缀的同名键" |

第一行的修复在数据化世界复跑中确认：`青鬃狼.状态: "侧扑已至近前，即将落身"` 这类**整类消失**，采样标记从 5 条降到 3 条，同时资源结算全对（3 石 − 2 = 1、符 ×2 → ×4、定身符经 `remove` 消耗）。

第二行是那次复跑**新暴露**的：那一轮 state 里两个冷却键并存且值不同，模型下一轮自己发现并删掉了——**但中间那一轮是脏的，而当时没有任何检查报得出来**（值的形状没变、没超长、也不算漏记）。提示词里"新建键前先看有没有已在说同一件事的键"没能拦住。

它现在由 program 采样器兜住，判别式很窄：**只报"一个裸键 vs 一个带前缀的同名键"**。`林昭.知情` 与 `陈屿.知情` 共享词尾却都是对的——两边都带前缀就不是歧义，那正是 `.` 分组要表达的东西。这也是 §3 那条"只看形状不看内容"的又一个实例。

**复跑的归因（repeat=3）：写入冗余 40% → 0%。** 剩下的三条全是 2/3，而且**三条同源**——都从那个裸键 `冷却` 长出来：

```
第 3 轮  沈砚.冷却 = 三回合
第 4 轮  冷却 = 两回合        ← 写进了裸键，沈砚.冷却 没动
第 5 轮  沈砚.冷却 = 一回合   ← 对账时直接跳了两格；顺手删掉裸键
```

于是 grader 报出"细纲说还剩一回合，状态说三回合"（检索不足）、"正文没动御剑斩，增量却改了冷却"（写入遗漏）。**症状散在三类里，病灶只有一个。** 这正是 §5 那条"上游的错会伪装成下游的错"在类别之间的版本。

除了检测器，还补了一条通用提示：**带倒计时的值每一轮都要重算一遍，它不会自己往下走**。「还剩三回合」「三天后到期」「一个时辰后关门」都是这一类，**漏一轮不会报错，只会在几轮后变成一个对不上的数**。

### C3：director

`noir` 上五类归因（repeat=3）里 director 那两类都是 0%。`data` 上命中两条，各有各的意思：

- **一条是回归集自己错了**：种子写「申时，离坊市关门约一个时辰」，设定写「戌时关门」——申时加一个时辰是酉时。模型忠实用了设定里的戌时，反被判成检索不足。**这反过来说明 grader 抓得住真矛盾，包括素材里的。**
- **一条催生了 S106**：用户写「我再来一记御剑斩」，而它还在冷却，否定项又明写"不要让冷却中的法术生效"。**转述规则与世界规则正面冲突，而设计里从没规定过谁让谁。** 模型选对了，但那是蒙对的。现在规则是：动作是锚点，结果归世界，落空要写得可见、有据。

第二条是这一阶段最值钱的产出——**"两条规则都对但打架"的地方，不写下来就等于交给运气。**

### 语义分界：三版都试过，最好的仍是第一版

`chapters` 场景（四段剧情，段间是转场，预期分界 {3,6,9}）上的三次实测：

| 版本 | 问法 | 时机 | 查全 | 查准 |
|---|---|---|---|---|
| v1 | **位置**：编号批次里"断在第几条之后" | 滑出窗口后 | 0.67 | **1.00** |
| v2 | 二值："这一轮是不是结尾" | 生成后 | 0.33 | 0.25 |
| v3 | 二值 + 告知本段已开几轮 + 默认 `open` | 生成后 | 0.33 | 0.50 |
| v4 | 二值，且改成持续对话（细纲并排在上下文里） | 生成后 | 0.33 | 0.33 |
| **v5** | **位置，且允许回溯到前面几条** | **生成后** | **1.00** | 0.60 |

**决定性的差别是问题的形式，不是它看得见什么。**

v2 → v3 → v4 三版都在补"让它看得更全"：加对照框、给默认值、换成持续对话把整段细纲并排摆在上下文里。**查全纹丝不动，一直是 0.33。** 因为分界是**相对判断**，而二值答案只能对当前轮独立表态——它**说不出"不是这里，是两轮前"**。模型再看得清楚，正确答案也装不进那个形状。

v5 换成位置问法并允许回溯，查全直接到 1.00。它保留了生成后的时机（揭示分界的那一轮在手里），又拿回了 v1 的相对判断能力。

**残留的多切（查准 0.60）是良性方向**：漏切把两段无关的戏并进同一条摘要，是不可逆的信息损失；多切只是多一条索引，每段本身仍然完整、仍然被正确压缩。因此 v5（1.00/0.60）优于 v1（0.67/1.00）——**这两个数不该等权看**。

**方法上的两点**：

- 五版的差别只在追问的问法与时机，素材完全相同。这类对照便宜、可复现，比在真实会话里凭感觉调有效得多。
- **我连着三版都在调"给它多少信息"，因为那是最直觉的假设。** 真正的瓶颈在答案的形状上——一个只能回 yes/no 的问题，再多的上下文也救不回来。下次遇到"加了信息却不见好转"，先检查问题的形式。

### A1：待做的消融（Q20 / Q21）

这两项只能靠跑起来回答，且**是同一张力的两端，须一起测**：

- **Q20**：文风约束的结构性部分能否 100% 留在 writer 侧。风险是默认腔调写出的东西结构上已是 AI 味的（三段式、总结性收尾），第二遍换词易换骨难。
- **Q21**：细纲的粒度下限。太粗则映射有歧义（writer 偏离↑），太细则 director 成本逼近正文全长、且其默认腔调的结构更难被改掉（文风失败↑）。

指标就是归因里的两类：**writer 偏离细纲**（AI 可判）与 **writer 文风失败**（只能人判）。粒度往两端调，看这两个数怎么走。

**它此前跑不了，因为粒度根本没有活动空间**（细纲与正文长度几乎相等，见上面 C4 的前置）。那个错误修掉之后比值稳定在 1.5–2.4，粒度这才成为一个可调的量。

做它还缺一样东西：**一个能真正改变细纲粒度的旋钮**。目前粒度是 `submit_outline` 描述与 director 提示词的隐含结果，没有可调参数。

> **S80 之后 `Variant` 本身要重做。** 它原先往 session 上写 `capabilities` / `control`，
> 而这两个类都搬进提示词了（[spec/UI.md](spec/UI.md) §7），它失去了全部着力点。
> **补法是让 bench 换一份 YAML，而不是换一个取值**：把 `prompting/` 复制到临时目录、
> 改掉要消融的那几档、让装配器读那一份。这与"取值只有一处"不冲突——取值仍然只住在
> YAML 里，bench 只是用了另一份 YAML。**这条路顺带解决了上面那个缺口**：细纲粒度
> 本来就没有"配置"可调，只有提示词可改，而换 YAML 恰好就是改提示词。
