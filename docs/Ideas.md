## 非轮次式的形态

创新点 (b) 的方向：agent 化之后，角色扮演的交互还该不该是「用户说一句、系统回一段」。

**这是探索方向，不是确定设计。** 判据是**用户体验是否真的改变**，而不是表面上还有没有
run 这个概念——把 run 改名叫别的，什么也没发生。

已经落地的那部分不在这里：让它自己往下跑（[长任务](req/长任务.md)）、停下来给选项
（[R12](req/推进剧情.md)）都已经是 req 了。剩下的还没想清楚。

### 时间驱动

让一局故事在没有用户输入时按时间或外部信号自行触发，仍只是非轮次方向下的候选形态。
它目前没有清楚回答“用户能做什么、怎么算做到了”，因此不进入 session schema，
也不占现行 spec。原 S121 已撤销并保留编号。

## 可选机制：真实性与戏剧性

三样东西一直被记着但没进默认路径：**多 agent 角色化**、**规则化**、**自主演化**。

三条共同的判断：

- **只适合部分场景**，不该进默认路径。
- 做的话应该是**强度旋钮而不是布尔开关**——"真实性削弱戏剧性"不是绝对的，
  而且对逻辑能力弱的模型，这些机制反而降低它的推理负担。
- **自主演化不按错误率评估**：它改变的是世界的呈现方式，不是降低出错率。
  拿错误率去衡量它，量的是错的东西。

## 为什么这一层要单独存在

之前这些东西混在决策台账里，和“状态是路径的函数”这种**已经落地、有测试**的条目
并排躺着，同一个编号、同一种引用形式。

于是读的人分不出哪条是"系统就这么做的"、哪条是"我们想过但没做"。
**一条还没想清楚的想法，一旦被引用得像规格，就会有人照着它写代码。**
